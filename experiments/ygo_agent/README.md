# ygo-agent 本机逐步指导试验

这是独立、手动运行的概念验证（PoC），用于验证现成打牌模型能否从工具箱真实决策窗口中连续选择动作。正式应用没有新增助手按钮，没有改变现有方案、模块搜索、训练随机起手或外部客户端读取流程。本目录不参与桌面打包。

## 已验证的结果（2026-09-19）

Windows x64、Python 3.14.5、LiteRT 2.2.0，CPU 两线程。没有训练或微调，未使用 GPU、云端推理或个人牌组。三组指定起手各运行一局，使用上游公开相剑构筑；抽牌和额外随机结果由实际引擎处理，具体牌序及全部原生日志留在本地。

| 案例 | 引擎确认的实际选择 | 实际场面 | 规则事件 |
| --- | ---: | --- | --- |
| 莫邪、龙渊、大同蟠龙、灰流丽、无限泡影 | 38 | 赤霄、承影，盖放无限泡影 | 无对手追加响应 |
| 莫邪、大同蟠龙、灰流丽、效果遮蒙者、无限泡影 | 20 | 赤霄，盖放墓穴的指名者、无限泡影 | 无对手追加响应 |
| 第一组起手，对手持有并启用灰流丽 | 31 | 赤霄、鲜花，盖放无限泡影 | 原生事件确认莫邪的抽牌效果被无效，随后继续展开 |

合计 89 次实际选择，另有三次未执行的结束回合建议，共 92 次推荐。单次特征适配及推理的中位耗时为 **3.156 ms**，范围 **0.727–4.088 ms**；不含首次加载、动画及引擎结算。普通起手这一局的连续操作循环耗时约 23.8 秒。

仅有一个合法选项的窗口直接采用该选项，不调用神经网络；上述耗时统计包含这些窗口。

这些动作没有调用正式方案库。相同手牌可以因后续随机抽牌而产生不同路线；这是三例工程验证，不是统计评测，不证明全局最优、胜率或优于当前模块系统。无龙渊起手这次只做到赤霄，仍需与人工及既有方案对比策略质量。

开发期还遇到并处理了：最新版双列卡号表与旧模型映射不匹配；Windows 原生加载器不接受部分中文绝对路径；空连锁窗口已被原生界面自动确认，不能再当成模型动作写入历史。开发试跑的原生记录保留在隔离目录，未混入上表的三场正式试验统计。

## 固定资产与运行边界

- 上游：[sbl1996/ygo-agent](https://github.com/sbl1996/ygo-agent)，源码与单列卡号映射固定至 `7888000e081519ea8258ed027e6d97ae8f3f0d0a`，匹配 864 张卡的词表。
- 权重：公开发布的 `0546_26550M.tflite`，17,679,932 字节。文件清单及 SHA-256 见 [assets.lock.json](assets.lock.json)。每次加载先验证所有下载资产，再导入上游特征代码。不要仅替换卡号表或重排编号。
- 上游代码和许可证只下载至忽略目录；其许可说明见下载的 `upstream/LICENSE`（ygo-agent MIT，包含 envpool Apache-2.0 声明）。本实验不重新分发模型、上游代码或卡牌资源。
- 原生决策、区域、卡牌实例和响应来自工具箱；模型输入隐藏对手未知身份，并对我方剩余牌组排序及重映射，避免泄露真实牌序。对手预设手牌可显示在练习界面截图中，但不作为已知身份送入模型。
- 当前仅适配部分我方先攻第一个回合窗口。未识别卡号、未覆盖窗口、叠放素材、多区域选择、模型容量溢出、无法表示的撤选等情况停止，不默默截断或用默认动作替代。
- **动态属性尚不完整**：原生快照未提供当前攻防、类型、等级等全部动态值，本实验使用卡库基础属性。比如承影的效果能改变攻防，这些变化尚未进入模型。当前模型建议不能当作完整实战判断。
- 卡牌数量上限 160、策略动作上限 24、和数选择组合搜索上限 16 个候选。单局最多 80 个决策窗口，运行器最多等待模型进程 180 秒。
- 建议绑定窗口版本与原始提示。只有对应响应被原生接口接受并得到后继窗口，才提交该建议的循环网络历史；用户改选、状态变化或不确定回执会停止，需要重新构建历史。尚未实现任意偏离后的模型历史恢复。
- 正常对手使用公开青眼构筑且关闭追加响应；灰流丽案例使用项目既有基础干扰构筑，只验证这一干扰场景。未验证完整对局、后攻、最新卡池、动态禁限表、外部平台或自由问答解释。

## 运行

前提：已准备本项目的 Node/Electron 依赖、`.local/desktop-bundle` 原生运行资源和 `uv`。以下命令均从仓库根目录执行，模型运行库只安装到独立虚拟环境。

```powershell
uv venv --python 3.14 .local/ygo-agent-pilot/.venv
uv pip sync --python .local/ygo-agent-pilot/.venv/Scripts/python.exe experiments/ygo_agent/requirements.txt
python experiments/ygo_agent/bootstrap.py
python experiments/ygo_agent/bootstrap.py --verify

# 不加载模型依赖的适配边界测试
python -X utf8 -m unittest discover -s experiments/ygo_agent -p 'test_*.py' -v

# 每个命令创建自己的后台验收应用，不移动系统鼠标，不发送全局按键
node experiments/ygo_agent/desktop.cjs --case=baseline
node experiments/ygo_agent/desktop.cjs --case=single-starter
node experiments/ygo_agent/desktop.cjs --case=ash

# 由上述本地证据生成 Markdown 与 HTML 报告
python -X utf8 experiments/ygo_agent/report.py
```

`single-starter` 对应表中的“无龙渊起手”，不表示排除了其他卡牌的起动能力。

全部下载文件、虚拟环境、公开测试构筑、测试数据、JSON/JSONL、原生场地截图及 HTML/Markdown 报告位于 `.local/ygo-agent-pilot/`，沿用现有忽略规则，不写入用户正式数据目录，不进入 Git。代码中的自动输入只允许固定隔离路径和明确标记 `test_control=true` 的会话；正式启动仍不启用这些测试接口。

`report.py` 为每个案例展示最后一次尝试，包括失败，详细原始结果链接保留在报告中。此前尝试及开发阶段日志继续保留，正式提交只包含可复现脚本、依赖与资产清单和说明。

## 检查与后续方向

本实验已通过 13 项边界测试：写入前核对隔离服务归属、隐藏信息不进入输入、牌序及实例插入顺序不泄露、动作身份映射、未知选择拒绝、缺失卡牌拒绝、窗口与回合范围、容量限制、历史提交一致性、下载资产完整性及失败案例报告。三场原生试验获得连续后继状态；HTML 在 1280 px 与 390 px 宽度下通过无横向溢出、图片加载和三组记录检查。

项目回归：`npm test` 通过 458 项 Python 与 219 项 JavaScript 测试；`npm run test:desktop -- --native-only` 和 `npm run test:packaged -- --native-only` 各通过 24 项验收。首次开发版验收暴露了旧随机翻牌测试仍期待四个预览的问题，已依据现有数量合并行为修正为一个“随机牌 ×2”及两个独立去向，并通过两种桌面验收；没有修改正式渲染逻辑。未重新打包应用，未执行其他全部桌面专用套件。

后续优先补齐动态局面、精确效果身份和动作覆盖，再做固定局面集上与现有方案的对比。确认策略有改进空间后，才考虑把已验证记录整理为示范样本及训练数据；本次没有实施训练管线，也没有证明原项目 CUDA 训练流程可以在本机 AMD GPU 上直接运行。

后续实验按[AI 推演生成数据与本地模型学习验证计划](../../docs/ai-learning-feasibility-plan.md)分阶段验证，采用本机优先、零付费调用的预算。该文档定义了数据可靠性、教师对照、学生训练、独立评测和更新回退的通过条件，目前仅为计划，尚未执行。
