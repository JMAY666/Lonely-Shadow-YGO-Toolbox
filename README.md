# 寂寞暗影的游戏王工具箱

**Lonely Shadow's Yu-Gi-Oh! Toolbox**。目前聚焦游戏王卡组展开的前置设计、练习记录、逐步回看与方案管理。

基于精简后的 YGOPro 工作副本，提供“卡组编辑 → 展开前置设计 → 展开场地 → 当前展开方案调整 → 保存前二次确认 → 展开管理”。Electron 桌面版复用现有 HTML/CSS/JavaScript 界面、Python 服务、YDK/JSONL 数据格式与原生引擎，不写入原始 YGO 安装目录。

本仓库公开源码、适配补丁、依赖锁定文件、测试与文档。Windows 成品包、卡牌数据库、卡图、效果脚本和个人数据保留在本地，不随 Git 发布；从源码运行时需按下方说明准备运行资源。

## Windows 桌面版

1.9.1 将创建妥协分支集成到时间轴节点的右键弹窗中，取消列表底部的独立创建区域。右键目标步骤，即可在附近选择分支时点并创建；支持 Shift+F10、Esc、点击外部关闭和窗口边缘避让。右键其他步骤会同步回看对应场面；无可恢复时点、正在展开或位于妥协分支内部时，弹窗说明禁用原因。分支的规则恢复、条件、记录和保存方式不变。

1.9.0 新增“妥协场构建”：完成主线后，在“展开方案调整与保存”的左侧时间轴右键目标步骤，在弹窗选择明确的恢复时点，创建同一方案内的妥协分支，再进入“妥协场构建前置”配置对手场景手牌。主线上可以创建多个独立分支，本次不支持分支内嵌套子分支。没有有效分支时，前置入口保持可见且禁用。

新记录保留完整引擎重放所需的调用、输入与随机起点。进入分支时先独立重建并校验原始对局，再构造场景手牌和合法选择窗口；代价、效果次数限制、双方区域、LP、阶段与连锁由规则引擎继续处理。旧方案缺少重放记录、引擎／卡牌／效果脚本版本改变，或场景会改变分支点之前的实际结果时，明确拒绝恢复，原方案仍可回看。不会用截图或近似场面代替可运行的对局状态。

妥协场的对手窗口与主窗口连接同一场对局。进入时先接管对手，暂停 AI；可多次“接管对手”和“交还 AI 托管”。关闭对手窗口会先交还托管，不结束对局。没有可发动卡牌的空响应窗口自动通过；存在合法选择时由当前控制方决定。对手使用原有基础 AI 决策，复杂到超出其策略范围的选择会保留并交回手动处理。

预设手牌与实际干扰分别显示。只有实际连锁记录支持时才展示“灰流丽 → 贪欲之壶：效果被无效”等结论；未知影响保留事件，允许用户补充关联和说明。分支终场、动作、前提和说明随主线一起经过二次确认保存，不另建独立方案。打开管理与回看默认主线；“查看妥协场”切换路线，“包含妥协场资源”独立控制统计，按主线与当前一个分支的资源份数取较大值，对手手牌单独展示。一图流默认只有主线，可选择加入哪些妥协分支，以虚线区域和连接具体步骤／响应点的箭头区分；分享文件也保留分支的冻结展示内容，但不携带本机引擎重放文件。

恢复边界、数据文件与验收说明见 [妥协场实施说明](docs/compromise-design.md)。

1.8.0 在“展开管理”后新增独立“TAG 管理”页面，可新增标签、改名、编辑别名、搜索并增删包含的卡牌。默认按系列编号收录，人工增删覆盖默认归属；自动分类使用最新范围，人工分类保留。标签编辑可跨页面保留，保存前也有退出提醒。

卡牌详情支持停留 400 毫秒后悬停预览，短暂划过不打开；移入浮层可继续阅读，点击可固定，Esc 或关闭按钮可收起。超量素材在同一资料浮层内保留上一级上下文，点击或悬停素材查看其详情，可返回原超量怪兽的素材列表。适用于方案回看、日志、终场展示和 TAG 管理里的卡图；不改变场地状态。

1.8.0 为一图流的操作卡牌和终场展示补上与简略日志一致的 30×24 位置图示，预览、PNG 和 SVG 导出均包含。图示按每次记录的场上位置高亮，蓝色表示我方、红色表示对方；缺少位置记录时不猜测。图示使用内嵌矢量绘制，离线导出仍完整可见，卡名与备注自动留出空间。

展开管理支持方案分享文件和系列标签分类。卡片本身的发动与卡片效果的发动分别显示，例如“发动场地魔法卡－转生炎兽的圣域”。卡片发动已完成但没有额外动作时，简略日志和一图流不再显示“处理结果未记录”；未确认结算、被无效或无法确定发动类型的记录仍保留状态提示。已有正式方案通过只读展示兼容，不改写其冻结动作。

1.8.0 的“展开管理 → 生成一图流”使用卡图与操作关键词展示发动、Cost、对象和处理结果，召唤素材与召唤出的卡牌也用卡图连接；多张素材或较长效果流程自动换行。顶部展示起手条件与已标记终场卡牌，下方用箭头连接蛇形排列的真实步骤，可预览、放大、导出嵌入全部相关卡图的 PNG／SVG，也可点击步骤回看。图中不列展开使用资源，保留费用数值、必要区域信息、无效／未记录结果和随机依赖提示。长路线自动增加列数；过长备注使用摘要，完整内容仍在原步骤中。

展开管理中的终场摘要显示已勾选效果的完整原文、场上位置示意与区域名称，并完整保留逐卡说明、逐效果备注和终场整体说明。终场步骤、简略日志、保存前确认和一图流仍显示效果序号与红色备注；卡牌详情和详细日志保留效果原文。简略日志在卡图下方保留 30×24 像素的场上位置示意图，悬停可查看完整区域名称；墓地、除外、素材等位置继续保留文字标注。步骤栏使用贴边箭头收起和展开，保留键盘操作与文字提示。终场卡牌和效果勾选、逐效果备注、初始真实手牌、区域浮窗、可收起的 Step 侧栏与左右键切步继续沿用；空备注不显示，明确规则导致的叠放素材附带送墓在简略日志中省略，原始证据保留。

展开回看：日志支持简略／详细切换，简略版横向展示发动、Cost 和处理结果；卡牌详情在点击位置附近打开，右侧固定按钮可随时开关日志；途中抽牌在回看和终场使用随机卡背。保留只读步骤时间轴、决斗盘、卡牌来源与素材详情、逐步及终场逐卡说明，以及使用资源／起手条件／随机依赖的二次确认。原历史列表移到“展开管理 → 历史记录与未保存草稿”，已有牌组、日志及报告保留。场地中的操作回退、双方起手与对手设置、AI、计时和删除恢复继续沿用。

沿用此前的展开摘要过滤、GPU 加速和原生子窗口合成修复。普通战斗事件保留在原始记录中，效果与费用仍显示在展开步骤中；准备提示在首帧、场地命中和合成兼容检查通过后消失。

对手 AI 默认关闭，沿用无干扰的空场占位。开启后显示双方场地与对手状态，基础对手实际参与规则内互动；结束操作统一使用工具箱顶部“展开结束”。

展开场地左侧使用可回退时间轴，替换原生卡图与介绍栏；卡组编辑页的卡片详情不变。开场发牌和阶段提示不等待过场动画。删除和重新展开使用页内确认。旧版本目录保留：请结束当前展开并退出旧版，再从下方 1.9.1 目录启动。

完整解压 `release/1.9.1/YGOTrainer-1.9.1-windows-x64.zip`，双击其中的 `YGOTrainer.exe`。本机展开目录为 `release/1.9.1/win-unpacked/YGOTrainer.exe`。**必须保留同目录的 DLL、resources 等全部内容，不能只复制 EXE。**

- 面向 Windows 10/11 x64，包内包含 Electron 44.3.0、Python 3.14.5 嵌入式运行时、YGOPro Lite、卡牌数据库、卡图和 Lua 脚本。启动不需要 Node、Python、开发服务器、外部浏览器或管理员安装步骤。
- 主窗口自动启动并连接自己的本地服务，使用系统分配的 `127.0.0.1` 端口，避免与旧网页服务或其他软件争用固定端口。同一数据目录重复启动只激活已有桌面窗口。
- 在“方案前置设计”填写名称与条件，点击“开始展开”进入主窗口内的 **展开场地**。YGOPro 以 Windows 子窗口方式渲染到预留区域，保留 Irrlicht/OpenGL 操作控件与独立受管进程。切换其他区域隐藏场地但继续记录，点击“展开场地”返回；调整主窗口大小会同步调整场地。
- 关闭主窗口时提示未保存的构筑、前置设计、草稿文字和未结束的尝试；可取消退出。展开中关闭应用记为“中断 / client_closed”，保留已落盘草稿；点击“展开结束”记为手动完成。确认退出后等待原生记录落盘，再关闭附属窗口和服务、释放端口。
- 首次启动会把约 1.28 GB 的资源准备到用户数据目录，并显示等待界面。后续启动复用资源；更新包中的程序资源时保留配置、卡组、训练记录和备份。

### 开发与打包

开发需要 Node.js 22.12+、npm、Python 3.12+ 和已构建的 `.local/YGOPro-Lite` 工作副本。首次准备需联网下载固定版本的嵌入式 Python/Electron；正常运行不联网下载资源。

```powershell
npm ci
npm run desktop:prepare
npm start

npm test
npm run test:desktop
npm run build:dir
npm run test:packaged
npm run build
```

`desktop:prepare` 校验 Python 归档哈希，按白名单生成 `runtime.zip`，只携带所需资源与干净的默认配置；个人卡组、展开方案、训练记录、旧配置、账号、Bot/WindBot、录像和日志不进入应用包。`build:dir` 生成 `release/1.9.1/win-unpacked/`；`build` 另生成上述 Windows ZIP 包。整个 `release/` 与 `.local/` 均留在本地，不进入 Git。

`test:desktop` / `test:packaged` 使用后台 Electron、内置 Python 和真实原生引擎，以隔离数据目录验证 YDK 导入、编辑删除、场地嵌入与缩放、效果发动、通常召唤、报告、重启和关闭，并覆盖 1／2／3／5 张起手、双方配置、返回修改、计时和草稿／方案删除。验收同时检查场地没有被重叠的分层窗口覆盖，不能仅以原生截图或鼠标命中成功判断场地可显示。测试通过引擎自己的命中检测和 Irrlicht 事件接口点击，通过渲染驱动捕获场地图像，不使用系统鼠标、全局按键或其他应用窗口。

测试脚本显式启用 `YGO_DESKTOP_TEST=1` 与 `YGO_DESKTOP_BACKGROUND=1`：仅测试实例提供内部输入／截图接口并固定随机种子，日志开始行标记 `test_control: true`。正常启动不启用这些接口，继续使用随机起手。一图流验收还覆盖真实保存方案的 PNG／SVG 下载、各环节卡图嵌入、多张素材换行、节点与卡图环节的文字边界、导出失败恢复、键盘跳转原步骤及冻结方案保持不变；终场摘要回归检查完整效果原文、位置与备注，并核对简略模式保持原有显示。

验收资料保存在 `.local/evidence/electron-development/` 和 `electron-packaged/`，不覆盖生产数据。

### 用户数据与旧数据迁移

打包版默认数据目录为 `%LOCALAPPDATA%\YGOTrainer`，与程序解压目录相互独立。开发版默认使用 `.local/desktop-dev/`；测试使用 `.local/desktop-check-development/` 与 `.local/desktop-check-packaged/`。完整数据目录结构：

```text
YGOTrainer/
  runtime/                         引擎可写运行副本；包资源自动准备
    system.conf                    原生配置，后续资源更新不覆盖
    deck/                          迁入的旧副本构筑
    _trainer/decks/                 工具保存的 YDK
    _trainer/backups/               构筑覆盖前备份
    _trainer/sessions/              训练记录，内部格式见下文
    _trainer/plans/                 正式方案快照及删除恢复副本
    _profile/                      原生隔离配置与日志
  migration-backups/<UUID>/         迁移前快照和 SHA-256 清单
  migration.json                   迁移结果、来源、备份位置及校验和
  electron/                        Electron 本地配置与缓存
  window.json                      桌面窗口尺寸
  logs/desktop.log                 启动和服务错误日志
```

`npm start` 在首次运行时自动从 `.local/YGOPro-Lite` 备份并迁移到开发数据目录。打包版本不会携带或自动扫描其他机器上的私人数据；首次迁移当前工作副本时使用：

```powershell
.\release\1.8.0\win-unpacked\YGOTrainer.exe --import-from "$PWD\.local\YGOPro-Lite"
```

先正常结束旧版训练并停止旧网页服务；源服务仍占用目录或原生训练存活时拒绝迁移。迁移顺序为：完整清点 → 独立备份 → 核对备份和源文件哈希 → 复制到空目标 → 逐文件核对 → 写入完成标记。旧数据保留原处；中途退出可从验证过的备份继续，不覆盖已经产生新修改的目标文件。已使用的桌面数据目录不会被再次导入覆盖；如需另行迁移，使用 `--data-dir "另一个空目录" --import-from "旧副本目录"`。

更换应用包后直接启动新的 EXE 即可继续使用同一数据目录。需要恢复时先完全退出应用，将整个数据目录另外备份，再将 `migration-backups/<UUID>/files/` 复制到**新的空数据目录**的 `runtime/`，用 `--data-dir` 启动并核对；迁移备份只覆盖迁移当时的数据，之后新增记录需要从当前数据目录的备份恢复。

## 旧网页入口（兼容保留）

需要 Windows、Python 3.12 或更新版本，以及已准备好的 `.local/YGOPro-Lite` 工作副本。服务使用 Python 标准库，无需安装第三方依赖。

```powershell
.\Start-Trainer.ps1
```

打开 [本地展开练习室](http://127.0.0.1:18765)。重复启动会打开已有服务。需要查看启动错误时可直接运行 `python src/trainer/app.py --no-browser`；已有服务时先关闭该服务。关闭网页不会结束模拟器中的训练。

1. 点击“导入卡组”选择已有 `.ydk` 文件，或直接把文件拖到卡组编辑页；核对预览后点击“导入为新构筑”。也可以在顶部打开已有构筑或新建构筑。左侧显示卡片详情，中间显示完整构筑；顶部“卡片列表”打开默认收起的右侧搜索抽屉。
2. 保存构筑，点击“方案前置设计”，填写方案名称、起手条件和备注；点击“开始展开”。已有副本构筑的编辑保存到练习室目录，不覆盖原有 YDK。
3. 在自动打开的原生场地中手动召唤、发动效果并选择区域或对象，现有引擎及效果脚本负责规则判断与结算。
4. 点击工具箱的“展开结束”，在调整区按节点检查场面、编辑说明，点击“保存方案”进入资源和起手条件核对；点击“确认存入展开管理”后正式保存。返回修改保留全部编辑，重启后正式方案及说明仍保留。

`Start-YGOPro-Lite.ps1` 保留原生卡组编辑入口；训练与报告从 `Start-Trainer.ps1` 进入。原生编辑器管理副本的 `deck/`；练习室管理独立的 `_trainer/decks/`。

## 卡组编辑

- 推荐先导入现成的 YDK 卡组，再用卡牌搜索进行微调。顶部和空主卡组中央均有导入入口，支持文件选择、单文件拖放，以及粘贴完整 YDK 原文；每次最多 32 KB、1000 行。
- 在构筑下拉框选择一项，点击旁边的“删除构筑”并确认，即可删除该工作副本中的构筑。删除前校验版本并在 `_trainer/backups/deleted/<UUID>/` 留下 YDK 与元数据；已有训练报告及冻结快照不删除。正在训练的构筑禁止删除；删除当前编辑构筑会清空编辑区，删除其他构筑保留当前未保存编辑。需要恢复时，退出应用后将备份的 `deck.ydk` 按元数据中的原名称复制回 `decks/` 或 `deck/`，不要覆盖同名新文件。
- 导入预览显示主卡组／额外／副卡组的张数、卡名、卡号和同号张数。实际载入完整保留三个分区、重复卡和原始顺序。未知卡号、无效格式、分区错误、衍生物和数量超限会阻止导入；主卡组不足 40 张可以先作为草稿导入编辑。
- 导入只创建编辑中的新构筑，点击“保存构筑”后才写入练习室。与已有练习室构筑同名时自动添加后缀，保留原文件和已有构筑；当前有未保存修改时，在载入前提示是否放弃。关闭预览不会改变当前构筑。
- 主卡组、额外卡组和副卡组同时显示，每张卡以独立卡图排列，重复卡不会折叠。分区标题显示张数及卡牌类型统计，桌面窗口按可用高度调整主卡组每行张数。
- 单击任意卡片，在左侧查看卡图、等级／阶级／LINK、攻守和效果全文；效果区独立滚动，加减按钮保留在下方。
- 点击“卡片列表”打开右侧抽屉，在其中搜索卡名、编号或效果文本，按怪兽／魔法／陷阱／额外卡组筛选。双击结果自动加入主卡组或额外卡组；使用详情里的“副卡组 ＋1”加入副卡组。抽屉可通过“收起”或 `Esc` 关闭，关闭不改变搜索内容或构筑；每次启动默认收起。
- 右键卡组内的卡片移除所点的一张，或用详情中的“−1”按分区移除。点击“撤销”或在非输入框中按 `Ctrl+Z` 撤销最近的加卡、移除或排序，保留最多 50 次卡牌编辑；打开／新建构筑会重置撤销记录。
- “排序”分别按卡牌类型、等级和卡号排列三个分区。排序和加减操作都需要保存；有未保存修改时不能开始训练，打开另一构筑或关闭页面会提示。
- 窄窗口和手机宽度仍通过顶部按钮打开搜索抽屉，抽屉宽度受视口限制；构筑、详情与顶部打开、新建、保存功能保留。

界面保留现有自由练习规则与 YDK 保存方式。编辑已有副本构筑时，保存会创建练习室副本；覆盖练习室构筑前仍自动备份。未接入 MDPro3 的禁限表、收藏或关联卡牌功能。

## 展开报告

### 前置设计、重试与保存

- 先填写非空方案名称，再设置实际起手数量。默认 5 张，提供 1／2／3 张快捷选项和其他正整数输入；最多为当前主卡组实际张数与自由练习上限 60 张的较小值。额外和副卡组不参与抽取。卡牌选择只列出选定主卡组，显示总数、指定数和剩余可指定数。
- “添加卡牌”要求起手至少包含指定副本。指定 1 张不会排除随机抽到剩余同名副本；指定总数不能超过牌组中该卡数量。
- “添加禁止卡牌”始终可用，包括单张起手或全部指定时。禁止条件对整副初始手牌生效，不占用槽位。同一卡不能既指定又禁止；冲突、超量或满足条件的卡牌不足时明确提示并阻止开始。空槽位从扣除指定副本、排除禁止卡后的牌组中不放回抽取；禁止卡仍保留在剩余牌组中，后续规则正常。
- 缩减数量或编辑卡组后，原有指定与禁止条件继续保留。超出数量的指定槽位会标记，已移出主卡组的卡牌会提示；必须手动移除、替换或增大数量，不会静默丢弃选择或放宽条件。
- “启用对手 AI”默认关闭。开启后可以选择已有对手卡组、编辑本次训练卡组和设置部分或全部起手；默认仍为 3 张灰流丽、37 张魔物狩人，指定起手 1 张灰流丽与 4 张魔物狩人。双方“编辑卡组”复用同一编辑器，点击“应用卡组并返回条件”只改变本次设计，不覆盖来源卡组。导入和选卡能力继续可用。
- “允许对手 AI 响应玩家操作”默认开启。关闭时，内核 AI 放弃对玩家操作的可选发动，强制效果、目标选择、费用与规则结算仍执行；AI 自身回合沿用基础通常召唤、随后结束的逻辑。仍为内核简单 AI，没有新增复杂策略或战斗策略；不保证任意复杂卡组的策略质量。AI 的效果、费用与结果进入同一原始事件记录。
- 玩家默认先手；选择后手时，对手先走第 1 回合。双方初始 LP 独立设置，默认 8000，范围为引擎接受的 1–2,147,483,647 的整数。起手数量指规则开始前实际发出的初始手牌：后手到自己的抽卡阶段仍按规则额外抽 1 张，例如设置 1 张，正常进入第 2 回合主要阶段时会有 2 张（无其他卡效时）。
- 计时默认关闭；正计时默认起始 0 秒，也可填写起始时长；倒计时填写正整数总时长，单位为秒，显示为时:分:秒。进入可操作场地后开始，场内查看记录或临时切换其他区域仍计入整体用时；返回修改条件、结束或重试时停止，新的尝试按配置重置。倒计时归零只停止计时并提示，场地仍能继续操作。
- 场地顶部“返回修改条件”确认后停止当前尝试，保留双方卡组、起手、禁止条件、AI 开关、先后手、LP 和计时设置。修改并再次开始时，随机位置重新抽取（仍可能偶然得到相同卡牌），使用新 UUID 和独立记录；旧尝试的原始记录保留。确认框可取消，正式方案不会因此改变。
- “重新展开”经确认后恢复双方初始状态，保留方案文字、条件、实际起手、牌组顺序及本次随机状态。旧尝试标为已放弃并从常规列表隐藏，独立的原始文件保留；后续草稿只使用新尝试日志，绝不混入旧步骤。
- “展开结束”生成待确认草稿；“保存方案”只生成确认摘要，只有“确认存入”写入正式方案。可以编辑方案和步骤名称、备注、终场逐卡说明、具体效果补充及条件核对，不改写动作和规则状态。记录中断、终场连锁未结束或逐步快照缺失时不能作为完整新方案保存。保存失败保留内容，重复确认同一草稿只产生一个正式方案。调整页可“放弃草稿”；正式方案可继续调整说明或确认删除。
- 正式方案保存完整牌组、卡牌文本、起手条件、实际起手、操作及最终状态快照。修改或删除源牌组不改变方案；历史记录仍可访问。切换区域保留当前填写内容并提醒其保存状态；切换另一条草稿前确认是否放弃未保存的文字。
- “展开管理”提供列表、查看、调整、删除和“生成一图流”。教程取自当前已保存方案的冻结快照与已保存说明，不混入未保存草稿；旧方案缺失条件或终场标记时明确提示，生成和导出不改写方案。PNG 适合直接分享，SVG 包含嵌入卡图、无需本地服务即可离线打开；过长路线的 PNG 达到画布限制时提示改用 SVG。原始资源与起手条件核对仍保留在方案详情及保存确认中。“以此条件再次展开”从冻结方案恢复全部配置，旧方案缺失的新字段使用旧版默认值（5 张、先手、双方 8000 LP、响应开启、计时关闭），新尝试独立保存。删除确认显示方案名称；删除只将目标正式快照移入本地恢复目录，不影响源牌组、其他方案或原始历史。

### 方案分享与系列分类

- 在展开管理点击“导出方案”下载 `.ygoplan.json`，分享内容包括构筑、起手条件、冻结卡片文本、步骤和事件依据、回看快照、人工说明、终场标记及标签正名／别名／主标签。文件不包含本机路径、进程信息、账户、原始 JSONL、卡图或可执行脚本；卡图使用接收方本地资源，缺图显示占位图。需独立离线看图时，可另外导出一图流 PNG／SVG。
- “导入方案”先校验文件版本、大小和数据结构，并展示名称、操作数量、标签及缺失卡牌。单文件上限 20 MB；确认后生成独立方案 UUID，同名方案不覆盖，重复文件打开此前导入项。失败时保留原有方案。导入后可回看、编辑说明、生成一图流与按条件新建展开；实际训练仍须通过本地卡库和脚本校验，分享记录不会被声称为本机重新验证过的对局。
- 标签使用卡库的系列编号与系列表识别归属，支持同一卡牌属于多个系列及子系列。当前内置已核实官译“转生炎兽”（含繁体／日文／英文别名）；其他系列默认采用本地系列表名称，来源在管理界面可见，不宣称全部译名已逐项官方核对。“TAG 管理”可新增自定义标签、编辑正名及多个别名，并搜索添加或移除标签中的卡牌；改名保留旧名为搜索别名，同一名称不能混归到两个标签。导入按系列编号合并，保留本地正名，冲突别名不改变已有归属。
- 新方案保存时自动分类；旧方案可即时显示自动分类，但不会仅因查看而改写文件。默认按实际参与路线的我方不同卡号统计（重复使用、同名副本不增加浓度；未使用的抽牌、对方卡牌不计入）。某系列至少 2 种且占比达到 20% 才自动添加；浓度最高者为唯一自动主标签，同浓度优先更具体的子系列，再按名称稳定排序。没有足够证据时留空，不猜测。自动模式随标签卡牌范围更新而重新计算显示，不改写冻结步骤；手动和导入的分类保持原选择。
- “编辑标签”可添加、移除、指定或取消主标签，允许人工设置多个主标签；“自动识别标签”重新计算并供保存前检查，不会在后台覆盖人工选择。标签面板列出浓度与卡牌依据。自动识别为本地确定性辅助，无需大模型或联网。每方案最多 30 个标签，每标签最多 30 个别名；标签的人工卡牌范围也随分享文件导出。导入遇到同名或同系列已有标签时保留接收方的卡牌范围，并提示差异。
- 列表支持方案名、系列正名或别名搜索，并可按系列筛选、仅按主标签分类或查看未分类。分类单独保存，修改前备份正式方案；标签库也保留修订备份。手动清空标签会持久保存，不会在重启后重新补回。

### 展开场地中的操作回退

- 左侧包含“初始状态”、步骤序号、关键卡牌、摘要和当前节点。步骤与同一原始记录生成的展开报告共用动作投影，不单独猜测卡效。同一次连锁或连续选择中的多个步骤按原顺序展示在一组内，点击后恢复到整组完成的状态；处理中显示待完成步骤。
- 点击节点回到它完成后的状态；撤销某一步应选择前一个节点。初始状态是本次自动准备完成后的第一个玩家决策点，通常为主要阶段；后手时会包含此前的对手自动行动与规则抽卡。恢复保留双方实际起手、全部区域与位置、牌组顺序、LP、回合阶段和规则内效果限制。
- 回退后，尚未改写的后续节点暂时标为“待替换”，仍可以点选恢复；第一次实际规则响应发生后，旧后续节点退出当前有效路线。查看记录、结束并保存只使用当前路线。已保存方案独立冻结，不会因另一尝试回退而被覆盖。计时仍表示本次尝试总用时，不随规则状态回退。
- 恢复期间场地暂停输入，时间轴显示处理状态并防止重复点击。引擎在独立的第二个核心与 Lua 实例里，使用本次种子、载入顺序、完整响应和查询顺序重演，核对消息字节、查询结果与全区域状态后切换；恢复校验失败保留原可操作引擎。正常训练仍为随机种子，固定种子只用于显式验收实例。
- 支持范围：本次仍在运行的单人规则引擎。除初始决策点外，可恢复节点仅在主要／战斗阶段的操作选择且当前连锁为空时生成；选素材、选对象、支付费用、连锁处理中不建立单独的恢复节点，但可以从这些选择界面回到此前节点。纯规则流程不增加报告动作，但需要恢复的阶段／战斗状态会作为状态节点保留。
- 引擎没有可直接反序列化 Lua、处理器栈及效果次数状态的快照接口，所以不能只用 JSON 场面恢复。重演耗时随路线长度增加，超过 20 秒或结果不一致会取消恢复；该期限在核心调用之间检查。已关闭的场地、历史方案和旧版日志不提供继续操作式回退，仍可查看或按原条件新建尝试。
- 原始 `native.jsonl` 始终追加，保留退出路线的证据；新增 `checkpoint`、`rewind`、`branch` 和 `route_input` 控制记录。报告先选择有效路线再生成原有 `events` / `actions`，旧战斗过滤和事件格式保持兼容。内存中的完整调用序列仅服务本次存活的引擎，关闭后不承诺恢复。

### 记录展示

调整区左侧从“初始手牌”到“终场结果”连续编号为 Step N，自定义名称不改变序号。中间展示节点结束后的真实区域、手牌和素材。点击卡图在附近打开详情浮层，显示冻结资料和截至该节点的来源；点击日志里的卡牌也不会切换当前步骤或滚动到页首。浮层可用关闭按钮、Esc 或点击外部关闭，卡牌随页面滚动移位或切换页面时收起。右侧固定小开关随时打开或收起日志，顶部保留原入口。日志顶部可切换“简略／详细”，默认简略版横向展示发动 → Cost → 对象（如有）→ 处理结果；场上位置小图缩为 30×24 像素，墓地等区域保留文字。费用、无效与结果缺失仍保留，长流程可横向滚动。超量召唤上方已表示素材与结果，不再重复素材去向；连接等召唤的逐卡去向在详细版查看。Esc 优先关闭卡牌浮层，再关闭日志。只读回看不调用场地回退、不重新抽牌或执行规则动作。

- 优先以原生 checkpoint 分组，旧日志使用完整消息批次；跨边界的连锁合并到记录齐全后的节点，并标出记录范围。原始动作投影的噪声过滤继续保留。
- 超量怪兽显示素材数量及“本体／素材”切换；墓地、除外和额外卡组可查看列表。主怪兽区按记录标 1—5 号，共享额外区独立展示，灵摆与场地区保留。未知身份使用卡背，连接怪兽的异常守备状态显示待核对。
- 不相关的对方区域隐藏。对方响应、目标及效果文本涉及对方时保留相关区域，并提供动作前的对方状态参考；效果文本只用于提示关联，不证明条件已被独立验证。对方未公开区域的身份在回看投影中隐藏，原始证据保留。
- 我方途中效果抽卡和规则抽卡按实例在日志、节点场面、卡牌浮层、保存确认和已保存方案终场摘要中显示“随机抽牌”卡背；起手保持实际手牌，检索得到的同名副本不受影响。缺失实例的旧记录不按卡名猜测对应关系。真实抽到的卡名仍保留在原始报告与依据中；若路线后续实际使用指定随机命中，条件摘要继续列入随机依赖。显示切换不改写冻结快照或重新抽牌。
- 终场整体说明与每张卡的实例说明分别保存；步骤名称、备注和效果补充也独立保存。返回修改保留编辑，改动后重新生成确认摘要。未确认的编辑仍在当前页面内存中，退出应用前应完成保存。
- 保存前分别展示实际使用资源、起手条件和随机依赖。按实例去重，回收再使用不加份数，未参与操作的随机牌不列为指定资源。途中随机抽到且用于路线的指定牌单列随机依赖。
- 明确、无附加身份限制的单张手牌费用可自动显示“任意手牌 ×1”；其他费用可人工核对真实限制。此卡后续还有非费用用途时不能简化。人工补充需填写数量、关联步骤和用途，与记录事实区分。统计针对本次路线，不声称推导所有替代路线的最小条件。

- 起手单独展示；起手和正常回合抽卡、阶段、选择、占位方跳过及连锁流程不占用展开步骤。
- 普通攻击宣言、伤害步骤、战斗结果、紧随战斗结果的单纯伤害及普通战斗破坏送墓不占用展开步骤；战斗中发动的效果、效果伤害、回复及费用照常展示。最终 LP 与场面仍取自真实快照，原始事件可随时查看。
- 按每组连锁和对应结算区间关联实际结果，按“费用 → 处理”展示。多段连锁保留各自结算顺序，不仅凭卡名合并。
- 支付 LP 的发动费用也归入对应效果，先于检索、特殊召唤等处理显示；依据发动费用区间、付款方和连锁快照关联，不根据文本中的数值补造支付。
- 卡牌详情保留完整效果文本。简版日志使用记录中已核实的效果映射显示编号与简述，悬停或键盘聚焦显示对应详细文本；无法匹配时显示“具体效果待补充”，用户补充单独标记。发动、结算完成、无效和结果未记录分别表达。
- 同一次效果中的多张同类费用合并展示卡名。例如金满而谦虚之壶的 6 张里侧除外费用合成一项；翻开、取走一张和剩余卡排序回到卡组底部分别显示，不称为“加入卡组”。
- 按核心召唤类型、素材与区域事件区分连接、同调、超量、融合等召唤。素材移动归入召唤，效果特殊召唤不重复列出入场移动；复活融合怪兽不会仅因卡片类型被称为融合召唤。原怪兽区 6／7 显示为额外怪兽区 1／2。
- 省略已确认的普通魔法／陷阱常规结算后送墓；效果移动、费用、无效及未完成状态仍保留。
- 效果全文直接可见，另可展开“查看依据”核对事件，或切换原始事件、打开 JSONL。效果文本不会用来补造尚未发生的结果。

效果抽卡统计排除起手和规则抽卡。当前为自由练习：检查主卡组 40–60 张、额外及副卡组各不超过 15 张、卡号、分区和脚本，不执行禁限卡表及同名三张限制。副卡组保存在构筑快照中，不参加训练场地。

## 本地保存与恢复

```text
.local/YGOPro-Lite/_trainer/
  decks/                     工具保存的 YDK
  backups/                   覆盖保存前的备份
  tag-library.json           本地标签正名、别名与修订号
  backups/tags/              标签库修改前的恢复副本
  plans/<尝试 UUID>.json      正式方案的完整冻结报告（原子写入）
  plans/deleted/<UUID>.json   删除的正式方案恢复副本，防止迟到的保存请求重建方案
  sessions/<训练 UUID>/
    session.json             冻结构筑、卡牌文本、时间和结束原因
    deck.ydk                 本次交给模拟器的构筑
    opening.cfg              版本 2 原生配置（双方发牌顺序、实际数量、先后手、LP、AI 响应）
    opponent.ydk             启用 AI 时冻结的对手卡组；原生端校验副本数量
    timeline-state.json      当前节点与输入版本；回退防重复及过期校验
    rewind-operation.json    最近回退的处理状态
    ready.json               只读可操作状态标记，用于启动本次计时
    native.jsonl             原始事件与状态
    report.json              当次生成的报告
    report-v8.json           当前动作投影及只读节点快照，旧版报告保留
```

只有“展开结束”标为手动完成；关闭模拟器、引擎提前结束或缺少结束标记均按中断保留。服务重启根据进程创建时间重新关联存活训练，避免误认被复用的进程号。异常时保留最后成功落盘状态，尚未写入的数据不能保证恢复。恢复误删方案时先退出应用，备份数据目录，再将对应 `plans/deleted/<UUID>.json` 移回 `plans/`；不要覆盖同名文件。

新正式方案内冻结 `review`（节点状态、实例来源）、`annotations`（用户说明）、`requirements`（确认摘要）和 `edit_revision`。更新正式方案说明前，原版本备份到 `plans/revisions/<UUID>/<版本>.json`；恢复时退出应用、备份当前文件，再用所需旧版本替换该 UUID 的正式文件。源卡组修改不会改变方案。旧正式方案缺少逐步状态时显示未知，原文件不在读取时升级；旧会话可从保留的原生日志派生 v8 报告。详见[记录说明](docs/recording.md)和[视觉与规则参考](docs/review-references.md)。

`.gitignore` 排除 `.local/`、依赖、缓存、日志、构建产物和凭据，排除不会删除文件。源码、补丁、依赖锁、合成测试和说明纳入 Git，个人构筑及训练数据留在本地。

## 构建与检查

当前副本已经准备好。重新构建需要 Visual Studio C++ x64 工具链（当前验证 VS 2026），先结束运行中的副本模拟器：

```powershell
python scripts/apply_lite.py
.\scripts\build.ps1
python -m unittest discover -s tests -q
node --check src/trainer/web/app.js
node --check src/trainer/web/report-view.js
node --test tests/deck_editor.test.cjs
```

Node 用于 Electron 开发、打包和编辑器测试；打包后的桌面应用已经包含所需运行时。原生构建使用经校验的 ASCII 目录联接，实际源文件仍在本副本。

从空目录准备时，依次运行 `python scripts/prepare_copy.py <原始YGO目录>`、`python scripts/fetch_sources.py`、`scripts/prepare_runtime.ps1`，再应用补丁和构建。复制工具逐文件校验，已有副本时拒绝覆盖；精简只处理副本。下载版本与校验和固定于 [source-lock.json](scripts/source-lock.json)。`python scripts/fetch_sources.py --verify-only` 只校验本地归档。本次验证已准备副本的重建，没有在全新目录重复完整下载、解包和全量构建。

[验收记录](docs/verification.md) 区分实际运行与合成测试；[第三方来源](docs/third-party.md) 说明上游版本与许可证。

[引擎与卡牌资源更新机制设计](docs/update-mechanism-design.md) 记录上游更新包检查、兼容边界、安装恢复和验收方案；该更新机制尚未实施。
