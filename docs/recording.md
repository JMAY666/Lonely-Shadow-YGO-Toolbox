# 训练记录与摘要

## 原始证据

每次训练使用独立 UUID 目录，冻结 YDK、构筑、卡名和文本、数据库与客户端 SHA-256。开始快照核对主卡组／额外卡组的卡号及张数，副卡组只保存在快照中。

1.1.0 的展开沿用这一目录和日志格式，在 `session.json` 增加 `expansion`（名称、备注、起手条件、实际起手、发牌顺序、初始随机种子及对手配置）与 `plan_stage`。阶段为 `recording`、`draft`、`saved`；重新展开的旧尝试标为 `discarded`，保留原始文件并从常规列表隐藏。旧记录不需要迁移，继续展示为原训练历史。

1.2.0 的 `opening.cfg` 版本 2 传递经校验的双方主卡组顺序、实际起手数量、先行玩家、双方 LP 与 AI 响应设置；对手另有 `opponent.ydk`，原生端再次核对副本计数。初始发牌与先后手抽卡均由现有内核流程执行，记录中的玩家仍为 0、对手仍为 1。禁止条件只影响指定数量的初始手牌，不进入内核禁止规则。版本 1 配置和旧方案仍可读取；旧方案缺失设置按 5 张、先手、8000 LP、响应开启和计时关闭恢复。

“重新展开”使用新 UUID 和空日志，复用冻结牌组、顺序与种子。“返回修改条件”结束旧尝试并恢复设置，再次开始重新抽取随机位置。放弃的草稿标为 `abandoned`，原始记录仍可读取，迟到保存不能创建正式方案。计时设置保存在 `expansion.timer`，运行计时以渲染器单调时钟计算；只读 `ready.json` 标记首个玩家可操作时机，不提供测试输入能力。

正式保存以 `_trainer/plans/<尝试 UUID>.json` 的原子写入为准，保存完整报告快照；同一 UUID 重复保存返回原方案。草稿名称及备注修改不会改变执行条件。删除将该文件原子移入 `plans/deleted/`，不删除任何会话日志或源牌组；该恢复文件同时阻止迟到的重复保存重建方案。

对手开关默认关闭，开启后默认使用 `basic-ash-v1`，也可换用或编辑本次对手卡组与起手。沿用内核 `DUEL_SIMPLE_AI`，由适配层补上通常召唤、结束回合。可选响应开关接入内核发动决策，强制连锁优先处理，费用、对象与结算保留。内核自动响应产生的发动、费用和结算照常落盘；适配层响应标记 `actor: opponent_ai`。这是基础干扰练习配置，未新增复杂策略或战斗决策。

`native.jsonl` 用递增采集序号与毫秒级批次时间，在界面动画前写入并刷新完整引擎消息。字段包含 `session`、`seq`、`time_ms`、`kind`、十六进制 `raw` 和核心 `state`。消息按固定核心协议拆分，事件标识为“批次序号:字节偏移”。未知消息停止该批后续解释并保留字节，不猜测下一条消息边界。

区域状态包含双方 LP、回合、阶段、卡牌位置、叠放关系、`cardid`、移动原因和活动连锁。新客户端还记录 `summon_info`、`material_instance_ids` 和 `reason_card_instance`，用于核对具体召唤方式与素材归属；原因效果包含 `effect_handle`（Lua 注册句柄）、所属／拥有者卡牌、描述编号、效果类型与范围。句柄只在本会话活动效果的生命周期与对应连锁范围内使用。核心 `effect.id` 在发动过程中会重排，不能独立作为稳定身份；旧版记录可用同一连锁完成时的快照核对重排编号。

读取时按会话隔离、按采集序号去重。重复序号内容冲突、序号缺口、截断行及解码问题产生提示；不同序号的相同动作保留。位置无法唯一匹配时实例为未知，不用同名卡替代。

## 摘要规则

1.3.0 的回退仍在同一个尝试 UUID 内追加记录。`checkpoint` 标记本次第一个玩家决策点，以及之后无活动连锁的主要／战斗操作选择；`rewind.target` 选择已有节点，`branch.target` 在首次新输入时截断旧后续路线，`route_input.revision` 用来拒绝过期请求。读取器以节点的父记录链选择有效记录，原始序号、事件引用和退出路线的物理日志均保留。当前报告和正式保存只投影所选路线；没有这些控制记录的旧日志按原顺序读取。

原生端没有可用的完整引擎反序列化接口，JSON 快照也没有 Lua 栈和次数限制。回退通过同一进程内的独立核心／Lua 实例重演实际种子、牌序、完整响应和客户端查询。每次 `process` 的返回状态与消息字节、查询字节及节点全区域快照必须一致，再切换场地。旧核心在重演和校验期间保留，测试可以在校验后注入失败以确认旧场地仍可继续。恢复所需的完整调用序列保存在当前引擎内存中；关闭引擎后不提供继续操作式恢复。

时间轴与报告共用 `project_actions`。一个恢复边界内的多条动作保留原编号与次序；中间选择和连锁处理不生成独立可恢复节点。无摘要动作的回合／阶段／普通战斗边界可以作为状态节点展示，不改变既有的战斗噪声过滤。计时维持本次尝试的总经过时间。

原始 `events` 保持可追溯，`actions` 为单独显示投影。生成新版 `report-v7.json` 不改写旧报告（包括 v5、v6）、YDK、元数据和日志。重新打开旧训练时自动生成当前版本摘要。

1. 按实际起手事件、`REASON_RULE` 和 `REASON_EFFECT` 区分起手、规则抽卡及效果抽卡。抽卡阶段中的效果抽卡仍保留；原因不明确时单独列出并标记未知。
2. `MSG_CHAINING` 开始效果摘要，卡名、区域与文本取自本次记录。界面主标题统一显示“发动某卡的效果”，下面显示完整卡片文本，“实际结果”显示已经发生的结果。每组连锁独立编号，不把下一组连锁 1 合入上一组。
3. `MSG_CHAIN_SOLVING` 到对应 `MSG_CHAIN_SOLVED` 确定结果区间。反向结算时结果归回对应发动，摘要标注多段连锁的结算顺序。原因效果不匹配则不强行归因。
4. 费用可能位于 `MSG_CHAINING` 之后、`MSG_CHAINED` 之前，也可能在发动之前。费用标记与原因效果必须能唯一指向同一发动。显示时先列费用，再列实际处理；多张同类、同来源／目标区域、同表示形式的除外费用聚合为一项，保留全部卡名和事件引用。无法归属则单独保留。
   `MSG_PAY_LPCOST` 没有卡牌引用：只有一个尚未完成的发动费用区间、付款方匹配发动控制方、核心快照中的连锁及效果身份一致时，才记录明确的 `cost_activation_ref`。描述金额保持原始事件值。缺少快照、记录缺口、区间已关闭或多区间重叠时不使用该归属；同一效果身份出现在多段连锁时仍按发动引用区分。
5. 普通魔法／陷阱从魔法陷阱区送墓，只有同实例已结算、原因恰为 `REASON_RULE` 且无效果／费用／重定向标记时才作为常规处理省略。其他效果移动、费用、破坏、解放和异常状态仍保留。
6. 回合、阶段、选择、占位方跳过、加入连锁、结算开始／完成及连锁结束不独立显示。无效、未完成状态写入对应效果摘要。
   攻击宣言、战斗结果与伤害步骤开始／结束也不独立显示。`MSG_DAMAGE` 没有原因字段，仅省略紧随 `MSG_BATTLE` 的独立伤害（允许中间穿插 LP 更新与显示提示）；其他动作、效果或采集序号缺口会关闭这个判断区间。连锁结算中的效果伤害仍归入效果，有明确原因效果或无法确认来源的其他伤害保留。仅有 `REASON_BATTLE`／战斗破坏标记、从怪兽区正常送墓且无费用和原因效果的移动省略；效果、替代、重定向或未知移动保留。攻击无效可作为效果的实际结果。所有省略只作用于摘要，原始事件和最终 LP／区域快照不变。
7. 同一卡组内部的移动作为顺序操作处理，正确更新被挤动的实例位置；相同位置的排序刷新不算新增卡牌。“放回卡组底部”要求原始事件确实将卡组内部卡牌移到序号 0，不能只凭文本猜测。翻开的卡、加入手卡的卡与回到底部的卡能对应时，才使用“剩余 N 张”的表述。
8. `summon_info` 的实际召唤类型用于识别连接／同调／超量／融合等方式，素材必须有核心素材列表或材料原因与明确的目标实例。旧记录缺少核心召唤类型时只用可核实的素材原因与目标关联。卡片的融合／连接等类型不能证明这次使用了何种召唤方法，普通复活仍显示特殊召唤。召唤和盖放确认后，入场移动从同一效果的处理列表中移除，保留在证据里。
9. 原 `LOCATION_MZONE` 序号 0–4 显示为主怪兽区 1–5，序号 5–6 显示为额外怪兽区 1–2；超量素材的位置单独解释为叠放地址。

效果原文可以写“①：自己抽2张”，但“实际过程”的抽卡数量只来自实际事件。发动无效、中断或没有抽卡事件时，原文仍可阅读，实际结果不会被补造成抽卡成功，状态单独标明。效果②允许从手卡特殊召唤一只怪兽时，只显示用户实际选择并成功召唤的卡牌。

## 内部效果文本序号与界面全文显示

以下映射用于核对实际发动效果。1.4.0 的卡牌详情继续展示完整冻结文本，右侧简版日志在已有可靠映射时显示效果编号、简述和详细提示；映射未知时显示“具体效果待补充”，允许单独保存用户说明。兼容的完整报告仍展示全文，不覆盖原始证据。

`card_semantics.py` 从冻结文本提取独立的①：／②：段落，排除“这个卡名的②的效果……”等共通限制中的引用。单一编号效果直接取该段；引擎描述文字能唯一匹配一段时使用该段，不假设 `Stringid(code, 0)` 是效果①。例如太古的白石的描述索引 0 实际对应效果②。

对已核对脚本的贤士、连接栗子球、太古的白石、青眼亚白龙、黄金卿、红化血染之黄金国永生药和米迦埃莉丝，使用冻结文本校验和、描述编号／发动区域和脚本依据对应效果序号。米迦埃莉丝的描述索引 0 对应①，索引 1 对应检索的③；被动的②不会因此被写成发动。文本变化会让映射失效；未覆盖的多效果卡、复制效果或模糊信息保留编号未知及完整文本，不能承诺任意卡片都自动识别编号。

## 范围与限制

### 1.4.0 只读回看、条件摘要和确认保存

`review.py` 在有效路线的原生状态上生成 `review.version = 1`。初始节点使用实际发牌批次的状态，普通节点优先使用 checkpoint；没有 checkpoint 的旧记录使用完整批次。跨过边界的动作推迟至完整结束，将同一边界内的动作一起展示。每个节点保存稳定标识、连续显示编号、动作引用、记录范围、状态引用及完整区域状态。终场单列，不把终场状态填到缺失的中间步骤。此投影不使用引擎重演接口。

`annotations.version = 1` 的 nodes 按稳定节点标识保存名称与备注；cards 按终场 cardid 保存逐卡说明；effects 按动作标识保存用户补充；costs 保存人工核对的费用替换范围。补充条件必须有数量、当前节点和用途，后端校验所有引用。未知实例不按卡名强行合并。原始事件、冻结卡组和状态不接受这些编辑字段覆盖。

使用资源以实际实例去重；初始持有且参与路线的实例进入起手条件，已知从主卡组或额外卡组使用的实例进入相应资源组，途中抽到后才使用的指定卡进入随机依赖。抽到但没有继续使用的卡不计入。费用仅在明确费用事件与对应效果文本一致、没有后续身份用途时泛化；未覆盖的复杂限制需人工核对。缺少实例或来源的情况在确认摘要中提示，不能当作已证明的最小资源条件。

`/api/plans/preview` 不写正式方案，返回经过校验的摘要和绑定事实版本、名称、备注与用户说明的确认值。`/api/plans/save` 校验确认内容，原子写入完整正式快照；同 UUID 重试返回已存文件，不重复建档。说明更新检查 edit_revision，并在 `plans/revisions/<UUID>/` 保留旧版本后原子更新；说明已经改变时拒绝过期写入。

新会话报告缓存单独写 v7。已有正式方案只使用自身冻结内容：缺少 review 时，初始手牌可以展示，其他缺失节点明确未知，终场使用旧方案原有状态。不会读取后来变化的源会话来悄悄补齐旧正式方案。查看旧方案不改文件；用户明确保存说明时才写入兼容投影并保留修改前版本。回退应用版本前先备份完整 `_trainer` 目录，必要时从 revisions 或 deleted 恢复具体正式文件，原始 JSONL 始终保留。

对方区域按该节点的参与卡牌、目标、响应及效果文本筛选。文本关联只说明需要核对对方状态，不是通用条件求值器；提供已记录的动作前状态，无法匹配具体效果时保留可能相关的区域。回看投影遮蔽对方手牌、里侧额外和里侧场上／除外身份，不修改引擎原始快照。

- 这是确定性的事件摘要，不是 AI 评价或通用卡效自然语言解释器。替代、持续、复制及复杂效果无法可靠归属时独立显示或标为未知，不把所有相邻变化算给最近发动的卡。
- 实际桌面验收包括贤士检索、连接栗子球、简易融合，以及 1.4.0 的霍普超量召唤／取除素材、重力控制者连接召唤、双龙卷费用与对象。素材转移、同名素材和更多类型另由合成记录覆盖；没有声称逐一卡片实测。
- 卡图查看时读取当前副本，构筑、卡名和文本来自训练时快照；缺图显示占位图。
- 支持当前松散数据库、图片和脚本布局。检测到未支持的压缩扩展包时阻止启动，避免与引擎资料不一致。自由练习不作禁限卡合法性裁定。
- 异常时读取最后成功写入的批次。未完成连锁不标为正常完成；断电或磁盘失败可能丢失尚未落盘数据。
