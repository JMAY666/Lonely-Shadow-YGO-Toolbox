# 学生观察、动作与历史契约 v2

本契约用于本机 P0B/P1 工程实验。它与旧 `ygo-agent` TFLite 适配层、78 样本探针及学生 v1 分开；不能交换词表、张量或权重。代码入口为 `experiments/ygo_learning/contract_v2.py`，模型为 `student_v2.py`。

## 适用范围与事实来源

首轮使用公开相剑构筑、专用机制构筑和受控对手，在自由练习规则下验证先攻首回合的执行。它不代表当前赛事禁限表、通用卡池或完整比赛能力。

原生动态观察只在 `YGO_TRAIN_TEST_CONTROL=1` 且 `YGO_TRAIN_LEARNING=1` 时启用。`training_learning.inc` 在真实规则核心查询当前类型、属性、种族、等级、阶级、连接值/标记、攻防和基础攻防。查询作为新增的 `LearningSnapshot` 核心调用保存并重放，旧调用枚举编号不变。查询前后核对已有语义状态、通常召唤与效果使用计数；发生变化立即报错。该检查加上完整重放是本阶段的证据，不能推定所有卡片脚本均无副作用。

正常应用不启用这些观察。学习验收模式保留有意义的连锁选择，只有没有可发动效果的空连锁窗口继续由原客户端自动通过。控制器独立核对原始日志，任何未记录的有意义我方选择都导致验收失败。

## 玩家观察

| 内容 | 来源和处理 |
| --- | --- |
| 卡实例、控制方、区域、表示、叠放关系 | 原生状态；模型使用区域中的公开位置引用，不接收引擎实例 ID |
| 当前攻防、类型等 | 已记录的核心 getter；已知且不在牌组内的卡缺少动态值时拒绝，不以卡库基础值代替 |
| 我方牌组 | 已知构筑的多重集合按卡号规范排序；真实顺序、实例 ID 不进入模型；牌组中的卡只编码基础类别属性，动态标记为否 |
| 对手未知信息 | 手牌、牌组、里侧场上/除外/额外等身份遮蔽；公开表侧额外卡保留已知身份。移入我方牌组的对手所有卡也不凭日志公开身份 |
| 连锁 | 最多 16 环；公开的处理卡、效果说明编号、类型、类别、事件编号；未知效果显式标记 |
| 资源 | LP、双方各区数量、回合/阶段、我方通常召唤已用/上限/额外次数、连锁深度；效果对象可提供的剩余次数独立编码 |
| 全局效果计数 | 私有计数键不输入网络；提供我方使用量统计。具体是否还能发动或召唤仍以核心当前合法窗口及真实结算为准 |
| 历史 | 最近 32 个已确认我方响应的动作字段、回合和阶段；完整响应前缀保留在本地证据中，重建时重新编码 |

隐藏信息不进入学生进程。私有原始提示、实例 ID、真实种子和完整日志留在隔离控制器，供精确执行与重放使用。身份未知与卡槽填充不同；卡号超出模型包声明的编码范围时明确拒绝。编码范围不等于模型学会了范围中的每张卡。

## 张量字段

所有张量在 CPU 进程边界核对精确形状、类型和有限值。`uint8` 字段经字段嵌入处理；卡号、效果编号和枚举的多字节表示可区分，不把菜单下标当成效果编号。连续数值使用独立浮点通道。

| 张量 | 形状、类型 | 含义 |
| --- | --- | --- |
| `cards` | 160 × 41，uint8 | 控制方、区域、序号、表示、身份已知、卡号；当前/基础类别的类型、属性、种族、等级、阶级、连接值、连接标记；无效、动态值有效、叠放标记与承载卡位置 |
| `card_numeric` | 160 × 8，float32 | 当前/基础攻防除以 10000；等级/阶级除以 13，连接值除以 8；计数位在首轮为零，带类型计数器另行拒绝 |
| `global` | 23，uint8 | 回合、行动方、阶段、双方手牌/牌组/额外/墓地/除外/怪兽区/魔陷区数量，连锁与通常召唤信息、契约版本 |
| `global_numeric` | 16，float32 | LP/8000、召唤资源、连锁深度/10、主要资源区数量/60、我方效果使用总量/16、候选数量/64 |
| `history` | 32 × 29，uint8 | 最近已确认动作优先；27 个动作字段和回合/阶段，空历史补零 |
| `chains` | 16 × 22，uint8 | 连锁序号、已知标记，以及公开处理卡、说明、效果类型、类别和事件编号 |
| `actions` | 64 × 27，uint8 | 提示类型、动作类别、选择数、主要卡区域/序号、目标区域/序号、效果类型、前两张卡号、选项值或效果说明编号、取消和控制方信息 |
| `action_numeric` | 64 × 8，float32 | 选择数、成员数、成员当前攻防/等级合计、数量参数、效果对象的剩余比例与有效标记 |
| `members` | 64 × 160，float32 | 动作选择的卡实例；相同已知牌组副本共用规范位置；排序操作保留顺序权重 |
| `legal` | 64，bool | 枚举候选槽位；填充槽不得被执行。它表示适配器生成的可用响应，真实核心仍做最终合法性校验 |

最多 160 个卡槽、64 个完整候选、16 个组合成员、16 环连锁。组合搜索最多检查 8192 个组合、中间结果最多 1024 个；排序最多 4 张。数值超过声明范围、容量不足、缺少动态属性或无法唯一绑定实例时停止，不截断候选或必要状态。

首轮不支持带类型计数器的模型输入、溢出式求和或卡名宣言；其他未在真实案例中覆盖的协议模式也不作支持承诺。接口能解析某种报文不等于该机制已经验收。

## 动作与历史事务

每个模型候选对应一个完整原生响应。卡片组合、素材选择、区域、取消和撤选均由当前提示枚举；引擎要求继续选择时，再取得新的真实窗口。相同可观察牌组副本可合并候选，但控制器保留原始响应别名。候选标识绑定 `version + raw prompt + response`。

执行顺序为：

1. 核对当前未回答窗口和版本，构造玩家观察与候选。
2. 多选交给 CPU 学生；只有唯一候选可旁路模型。
3. 在可丢弃副本中校验所选响应，禁止用副本的未来信息作为本次学生输入。
4. 使用一次性租约向真实实例提交，核对相同窗口、原始响应和提交回执。
5. 等待后继真实检查点，才把动作写入已确认历史。

重复回执、旧窗口、实际改选或缺少后继状态都拒绝更新历史。模型进程退出后不执行旧建议；新进程使用从完整已确认前缀重建的历史。选择结束回合只是请求，结束阶段的可选窗口仍由学生处理；观察到回合实际变更才计为完成。

重复局面、120 次决策、180 秒单回合上限分别停止并记账。停止循环、超时、不支持和真实结束是不同结果。P1 不启用教师兜底，不使用失败的开发回合重新标注本轮学生。

## 模型包与复现

数据包记录实际来源文件、起手、资源/契约/模型/加载器/旧协议解析器哈希。模型包包含训练报告、数据清单、检查点和 CPU `.pt2`，启动时验证代码、规则资源及导出文件哈希。独立运行清单再固定控制器与实验脚本的源码哈希。

学生 v2 使用约 147 万参数，训练样本是受控开发示范，监督标签只表示实际执行过的选择。相同特征下存在多个示范选择时保存已观察标签集合，集合内命中率不代表唯一最优策略或胜率。正式教师质量和策略测试按[验证计划](ai-learning-feasibility-plan.md)另行开展。

全部原始数据、模型、环境、失败尝试和运行清单保存在 `.local/ygo-learning/`，不进入 Git 或正式应用包。该目录遵守 20 GiB 停止上限；开发运行器采样隔离进程的内存并检查 8 GiB 上限，批次最多 30 分钟。磁盘达到上限时保留证据并停止，不自动删除数据。
