# MyCard 超先行补丁

在左侧导航底部点击「全局设置」，入口紧邻「TAG 管理」上方。设置中保留起手数量和教程快捷键，并提供独立的超先行补丁管理区。

## 使用

1. 打开设置时读取本地状态；没有版本信息或上次检查超过五分钟时自动检查官方版本。也可随时点击「检查更新」。失败时显示原因和上次成功检查的时间，本地已安装版本继续保留。
2. 「安装补丁」下载并检查官方当前包。安装后显示本地版本、官方更新时间、补丁卡片数量和下载地址。官网及下载地址可在系统浏览器打开。
3. 有新版本时点击「更新补丁」。替换整份旧包，已经从官方包移除的卡牌或资源也会从本应用的补丁投影中移除，不叠加旧包残留。
4. 「卸载补丁」移除正在使用的补丁，恢复基础卡库与脚本。个人卡组、收藏、TAG 编辑、方案、历史和原始记录保留。使用补丁新卡的构筑需要重新安装该补丁才能继续校验和展开；已保存报告保留当时的卡牌快照。

这些操作立即生效，无需点击设置窗口下方「保存」。下方保存／取消只影响原有的起手数量等表单。补丁处理时显示阶段和下载进度，禁止重复操作。展开或后台推演正在运行时必须先结束；下载与应用期间不能新建引擎会话。

## 来源与适配

- 官方说明：[MyCard 超先行更新进度与介绍](https://mycard.world/ygopro/arena/#/superpre)。程序使用该页面当前调用的 `data/version.txt` 和 `data/latest-tag.txt`，不把此次看到的日期或版本写成永久最新值。
- 已核实的下载来源为 `cdntx.moecube.com/ygopro-super-pre/` 及其官方跳转 `cdncf.moecube.com/ygopro-super-pre/`。来源或包格式超出支持范围时显示错误并保留旧版。
- 原生引擎直接加载 `expansions/ygopro-super-pre.ypk`。网页卡库从同一包经校验的不可变副本读取 `.cdb`；补丁数据库按引擎的归档成员顺序在基础库之后加载，覆盖同编号卡牌。卡图、系列名称和脚本可用性也读取同包资源。
- 补丁归档摘要进入卡库来源和脚本身份，变更后清除内存推演缓存；已有方案和记录不被重写。新会话使用当前资源重新校验。
- 只接受已知卡库、Lua、图片、字符串和官方包辅助数据类型。检查 ZIP 路径、重复成员、压缩方式、大小、CRC 与 SQLite 结构及完整性，拒绝可执行文件、加密包、路径越界和链接。其他手工扩展包仍不混合加载，以免无法确定覆盖顺序。
- 不更新或替换 `YGOPro.exe`，不修改基础 `cards.cdb`、基础脚本、个人配置或原始安装。新卡仍取决于官方测试脚本和现有规则引擎能力；资源格式检查及代表卡验收不代表逐卡穷举验证所有效果。

## 恢复与本地文件

补丁目录是当前应用数据下的 `runtime/_trainer/patches/superpre/`（源码网页入口对应工作副本 `_trainer/patches/superpre/`）。`generations/<SHA-256>/` 保存已下载原包和只读用途的资源副本；`installed.json` 记录正在使用的版本，`latest.json` 记录最后成功检查的官方信息。各代恢复文件留在本地，不随 Git 或应用基础资源打包。

替换前写入 `transaction.json`，成功刷新资源后结束事务。下载、校验或资源刷新失败保留／恢复旧版；进程在替换中断时，下次启动先根据事务记录恢复旧版。若安装位置出现本应用未管理的文件或外部修改，停止覆盖或删除并说明冲突。不要手动修改受管理的归档及副本；需要移除时使用设置中的卸载。

所有桌面检查使用隐藏的 Electron 窗口和引擎内部验收接口，不发送全局按键或移动系统鼠标。构建验收可通过 `YGO_PACKAGE_DIR` 指定独立构建输出，完整回归可通过 `YGO_TEST_RUN` 指定测试目录后缀，避免并行开发共用验收数据。正式启动默认关闭内部输入和截图接口。

新旧版本替换、下架资源清理、网络失败、损坏包、外部文件冲突、事务中断、回滚失败后禁止启动引擎，以及应用基础资源更新后保留补丁，使用合成资源包和故障注入验证。未将代表卡的实测结果扩大为全部超先行卡的逐效果验证。
