# BO1 后攻辅助执行文档

状态：按阶段实施。基线：1.28.5 / b0acf30。用户已批准从分析进入实施（2026-09-18）。本文件区分已完成、实施中与待验证；未勾选条目不代表已实现。

## 目标与边界

在同一局内串联：对手首回合的条件化交康提示 → 我方首个回合的解场、展开、有限场景斩杀或妥协 → 实际偏差后的后续重算。

- 原始起手不可覆盖。当前状态由独立的已确认观察维护，不使用“原始五张 + 第六张”代替。
- 玩家在外部客户端操作。建议、已确认动作、实际处理结果和假设推演分别记录；查看或选择建议不执行游戏输入、不扣资源。
- 仅使用玩家已知信息；未知手牌、盖卡、牌序保持未知。候选卡组和响应假设不得变成事实。
- 卡片及效果以准确编号、卡文、裁定及固定版本规则核心为依据；缺少规则状态时停止依赖该状态的确定结论。
- 规则上合法、有限场景推演通过、策略建议分别显示；不宣称最优、必胜或未经统计的胜率。
- 保留正式方案、原始日志、旧报告、个人数据与现有先攻流程。重算仅替换未执行部分，换局拒绝迟到结果。

## 输入与状态契约

1. 局次身份：平台、连接身份、round_id、局面 revision、窗口身份；任何状态变化使旧建议失效。
2. 原始起手：独立 snapshot_id、卡号与重复份数、来源及时点。未采到时标缺失，不能由当前手牌倒填。
3. 当前局面：我方真实手牌、双方公开区域、实例、控制者、位置、表示、素材、LP、回合、阶段。
4. 规则状态：当前连锁、响应方、具体效果、费用与对象、次数使用、通常召唤权限、持续限制及到期条件。未知不等于未使用。
5. 来源与可知性：只读识别／人工确认／推导／假设／未知。读取与人工冲突需核对；假设不进入实际状态。
6. 事件：动作声明、费用支付、实际结算、抽牌、移动、窗口变化、人工更正分别记录；使用幂等事件身份避免重复扣牌。
7. 规则环境：平台玩法、卡池与禁限表版本、引擎／卡库／脚本及来源版本。MD 与本地自由练习分别标识。
8. 恢复：重新打开历史需要核对当前局面；不自动把持久化的旧窗口恢复为可响应窗口。

引擎重建优先使用可重放历史。仅摆出相同卡牌不能证明效果次数、残留限制或召唤手续一致；无法还原时只保留条件提示，不生成“已验证路线”。共享公开状态不能直接放开引擎的对手隐藏次数；已知次数必须来自公开事件。

## 用户操作与界面

沿用 BO1 → 手动／平台 → 卡组 → 先后攻入口。后攻工作区分对手首回合、我方首回合和复盘三个状态。

- 默认显示阶段、状态有效性、关键威胁和最多三项建议；理由、证据、历史和候选详情按需展开。
- 录入使用卡片选择、区域移动、费用／结果及关键窗口核对；支持同名多份，不要求用户编辑内部 JSON。
- 对手回合每项提示说明卡／效果／目标、合法条件与费用、预计阻止收益、我方机会成本、交与不交分支、未确认信息。
- 我方回合使用当前状态；列出操作顺序、资源投入、预期结果及对手响应分支。
- 对手不响应、改对象或追加干扰后，更新实际历史并重算未执行部分。
- 过期建议显示失效，不能继续采用；后台计算不阻塞手动记录。
- 保留现有场地／教程及分隔栏调节范围，辅助内容可收起，不新增固定最小占位。

## 评价与证据

实际卡差、实际移除、预计阻止的资源、关键起动点、墓地／除外利用、剩余干扰和续航分列。共享次数、共享费用和互斥效果不叠加。交与不交的共同历史费用不重复计收益。

先排除不合法路线，再按解除关键限制、消耗阻抗、可验证致胜或保持续航比较。攻击资格、目标、次数、表示、伤害变化和中间触发交给规则核心，不能把攻击力相加当作斩杀。对手回合优先预核验条件提示，窗口关闭后不采用迟到搜索结果。

复盘按当时可知信息评价，后揭示隐藏信息不回填旧决策。其他选择的结果只列为假设比较。
