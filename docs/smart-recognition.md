# YGOPro 智能化识别

1.27.0 在「自动选择 → 平台选择 → YGOPro」捕捉弹窗新增「智能化识别」。原「进入卡组识别」及手动模式保留。

## 正常流程

在正式发牌前点击一次智能化识别，再在游戏中正常准备、猜拳与选择先后攻。本局结束后自动关闭本局工作区和计算，回到“等待下一场对局开始”；同一 YGOPro 进程的后续对局自动重复识别，无需再次点击按钮。主动取消／退出此流程、切换连接或确认客户端关闭才停止整个监听。状态依实际数据依次更新：等待对局开始、获取本局卡组、识别 TAG、等待先后攻及起手就绪、自动校验。初始发牌采样自按钮启动起独立运行，不等待 TAG 工作完成。

校验完整构筑、有效卡号及份数、同一进程与局次、正式先攻和初始起手后，自动进入「卡组展开 → 方案选择」。匹配和四种偏好的模块化计算使用同一个不可变工作区。计算进度、失败和无结果分别显示，支持刷新匹配、重新生成路线；计算完成不替用户选择方案，不改变已选教程进度。

**TAG 直接复用现有本地系列统计规则**，保留主／副 TAG 语义，识别结果实际参与方案匹配。不需要模型服务或密钥配置。TAG 无命中是成功的空结果，与识别异常区分。

## 采集和隔离

- 仅支持已核实 SHA-256 的 YGOPro 1.036.2 x64 普通对局。沿用进程路径、创建时间、镜像指纹与动态模块基址，仅读内存。
- `read_initial_deck` 复用已验证的 `current_deck` 结构，要求正式 `MSG_START` 后、0–1 回合、非编辑／换副／观战／录像状态。该客户端在 Ready 加载并提交 `current_deck`；同时核对服务器初始化的我方牌库加手牌数、额外数量、空场及前后区域容器和完整构筑快照。主卡组须为 40–60，额外／副卡组各不超过 15，同名（包括别名）总份数不超过 3；自定义突破这些限制的构筑明确拒绝。
- 构筑只从完整构筑容器读取，不能用剩余牌库重建，不使用编辑器或历史缓存。主／额外／副卡组全量冻结，并在自动校验时再次核对当前提交构筑。
- 先后攻由正式开局字段并等待第 1 回合确认。初始起手使用第 0 回合我方 `MSG_DRAW` 与我方手牌区按份数核对；重复卡全部保留。抽牌、出牌、排序不会替换冻结结果。
- 独立后台采样每约 25 ms 请求一次，完成后降低频率；没有固定时间模拟进度。短暂读取不稳定会重试；超过 2 秒未成功采样不能证明连续性，关闭本局结果并保持连接，观察到下一场边界后再采集，不能用恢复后的当前手牌冒充起手。通过进程退出状态和创建身份判断客户端关闭；前端退出或断开超过 20 秒停止其订阅。
- `request_id` 标识持续订阅，每局另有递增周期、局次、起手快照和输入摘要。重复请求复用同一任务；提前取消保留失效标记，迟到的启动、TAG 分析、匹配或计算不能重新激活。智能任务使用独立监测器和界面草稿，不覆盖逐步监测器及手动选择。
- 取消并返回始终可用；停止采样，立即禁止旧工作区继续操作，异步释放其引擎任务。已经执行中的原生请求可能需要等安全退出，其结果不能回填。每局结束、重新开局或失去连续性均先使旧工作区失效，再等待下一场；旧 TAG 线程、界面响应及计算不能写入新周期。仅切换连接、客户端关闭或用户取消／退出流程才关闭整个订阅。

## 失败与后攻

TAG 分析失败、返回无效 TAG、资料变化或自动校验失败不自动跳转；可重试本局识别。漏掉初始发牌、构筑核对窗口或数据连续性无法确认时，本局显示失败原因并自动等待下一局，当前手牌不能替代起手。TAG 为空、没有匹配方案、没有可用展开来源或没有计算候选分别说明。

后攻显示「已识别为后攻，后攻展开暂未支持」，保留冻结起手，不建立先攻方案工作区，也不启动先攻计算。没有自动操作游戏、准备、开局或推进教程。

## 本地数据与验证记录
