# 1.36.0 验证记录

## 实际客户端

用户自行操作原已核实的 YGOPro 镜像，现场记录器只读，不发送游戏输入。

- 对手首回合抽卡阶段，读取我方一个手坑选项，用户报告选择发动；观察到手牌 5 → 4，原选项失效。资源变化没有被额外推断成效果结算或费用事件。
- 随后另一个手坑的选项由用户确认。
- 用户确认一个对手连锁 1 的公开卡名，以及我方“无限泡影”选项与画面一致。
- 记录器另捕捉到多条公开连锁及选项切换，但没有逐条人工认证，更没有宣称连续事件齐全。变化中途的一致性拒绝与原始日志一并保留。

现场记录器已停止。真人资料和核对记录在 `.local/ygopro-p23-live/`，包含个人卡组，保留本地，不用于合成夹具、不提交。布局研究在 `.local/ygopro-p23-research/`。实机核对证明这些观察窗口；完整桌面自动开局、预览、采用的真人端到端仍待验证。

## 边界与数据保留

本版是公开连锁列表与有限我方选择快照，不认证完整事件、稳定窗口身份、费用／对象、发动无效／效果无效、次数和持续限制。未从快照自动生成交康建议，未开放外部路线、战斗或 MD 卡池规则认证。单槽缓存可能漏消息，两次相同内容读取之间的新窗口不能被据此区分。

内置规则核心、卡库、Lua 和其他平台适配未修改，本轮未重跑全部原生或其他平台真人专项。开发及打包验收只使用后台 Electron、隔离数据和内部接口。正式方案、原始日志、个人数据、设置、截图、备份和旧版本保留；忽略规则没有扩大。

提交前仅清理本轮两个已退出的隔离桌面目录中的可重建规则／图片副本。逐项核对工作区边界、普通路径、进程、服务锁、资源清单和内容哈希；清单及执行结果在 `.local/evidence/bo1-p23-cleanup-inventory.json` 与 `bo1-p23-cleanup-result.json`。真人记录、失败证据、JSON／JSONL、截图和配置均保留。
