# 模块化展开与 Step 内部模型

## 数据归属与调度

模块化是内置的数据与决策核心。卡组编辑维护构筑原始数据；展开录制、Step 和 IF 妥协场提供来源快照、选择及实际结果；模块化维护派生索引、匹配与规则校验；决斗是请求并使用输出的窗口。

决斗的方案预选与临时方案计算均经过同一调度核心，1.17 的步骤确认与实际情况重算见[临时方案](duel-temporary-plans.md)。`POST /api/modular/dispatch` 接受调用方和请求类型，输出请求标识、本局冻结的构筑／引擎／脚本版本及结果。当前请求包括数据概览、方案预选、配置、搜索、执行、自动模式和状态；旧 API 保留兼容。方案预选只核对已保存条件，不冒充实际引擎验证。

数据提供方通过本地 `register_provider()` 接入，原始文件仍由所属功能维护。注册新数据提供方本身不会把其数据当成可执行动作，仍须提供原生决策证据并经过引擎。后续功能可使用同一调度接口；本版本实际接入的是卡组、卡库、展开与分支，以及决斗。

## 使用流程

1. 在「展开」中按原流程选择卡组、确认实际起手，在场地操作并保存正式方案。必要的效果选择、对象、素材、位置和连锁响应都由引擎记录。
2. 在决斗窗口生成临时方案，使用该页已确认的构筑与手牌，在原窗口查看步骤图、确认实际操作并按需填报偏差。独立的「模块化」页面提供数据来源、模块关系和调度状态；展开中点击「模块化续展」接入同一场对局，也保留可选的固定起手验证入口。
3. 路线偏好按顺序提供花费最少、终场最大、步骤最少、平均，默认终场最大；可填写希望终场保留的场上卡号。点击查找后，系统从当前真实决策窗口，逐次重绑来源动作并在隔离引擎中校验。以下执行与结束保存步骤适用于真实展开；决斗临时方案使用步骤确认流程。
4. 查看候选的终场、实际资源、具体效果、来源方案／分支／快照及版本。未知结果和未评估项目会保留标记；仅复核下一步的结果有独立标签。
5. 点击「采用路线并执行下一步」，或明确开启内置 YGO AI。进入页面本身不会执行。可以随时停止 AI，随后继续手动操作。
6. 手动改变选择、对手干扰或调整偏好后，后续从引擎的新状态重算。已经支付的费用、效果次数、通常召唤及起手均保留。没有候选时保留本局并暂停，不自动重开。
7. 展开结束后回到原回看／调整／确认保存流程。正式保存或修改来源会自动更新模块索引，并使相关旧候选及待提交指令失效。

查找只组合所选来源里实际记录的选择，不能补造未记录动作。修改目标可能使原路线排序改变；实际失败、缺少资源、条件不足与搜索达到限制分别记录。替代终场可在已开启的自动模式中继续采用，界面保留原目标及是否达成它。

决斗临时方案（手动模式及自动识别工作区）先合并本局卡组的主、副 Tag，只有方案 Tag 与之至少命中一项且具备可用决策记录的来源，才出现在「参与计算的来源」并进入后台计算。Tag 按稳定编号匹配；无 Tag、未分类或无匹配来源时明确提示，不自动使用整个模块库。来源分类或标签成员改变后重新核对并使旧候选失效。独立模块化页面仍可查看完整来源资料。

候选路线与普通方案一样使用并排卡片，默认显示剩余决策数、推荐标记和终场卡图；每张候选卡片直接显示最多四张终场缩略图，更多终场卡牌及步骤、来源在详情中查看。点击卡片采用路线，定时刷新保留已展开的详情。手动与自动模式使用同一展示规则。

### 精确匹配开关

默认关闭时，自适应绑定可调整区域坐标，并保留原始选择与实际绑定两份证据。身份、控制者、表示形式、具体效果、材料数值和时机不会被放宽；每个位置变体都由当前合法提示生成，再逐步交给隔离引擎。连接箭头、灵摆额外召唤区域、次数、代价和召唤限制始终生效。

打开后，核对模块中已记录的可见局面及精确区域。运行时实例编号、手牌排列和隐藏的牌序不作为跨对局相等条件；未记录的权限继续由引擎验证，未知结果不当作相同。开关与偏好一样具有版本，切换会撤销旧候选及未消费的执行指令。

### IF 妥协场也是模块来源

从原 Step 右键创建妥协分支后，可选择自动提取实际干扰、发动被无效、效果被无效、关键场上卡被效果移走，或不限定干扰的资源续接。原有受影响操作、对手场景手牌与说明保留；新增卡牌、区域、份数的补点入口条件。

设置条件不等于条件已发生。实际连锁事件、受影响的具体效果与移走原因构成 IF 证据；资源条件核对打断后首次决策快照，后续支付过的费用不会被要求“重新拥有”，也不会恢复已消耗权限。模块化同时保留操作来源和终场来源：共享补点操作可以来自主线，而终场与 IF 条件来自已保存的妥协分支。

正式保存包含分支的完整方案后，主线与已确认的 IF 后续共同进入模块库。未确认的 IF 不会仅因预设灰流丽或其他卡牌而满足。已有批注、主线记录、旧分支尝试和恢复文件均保留。

## Step 保留名称，内部使用模块图

`module_graph.py` 是决策边界的共享入口。报告、模块库提取、回退节点与妥协分叉共用原始 checkpoint。每个真实决策窗口有独立快照，包括连锁中的必要选择；它不是可以随意插入召唤的空闲场面。

`review.module_graph` 保存模块、已观察的连接及 Step 投影关系。Step 的稳定 ID、名称、批注和动作引用保持兼容；`module_id` 引用它显示的局面，`module_ids` 保存覆盖的决策边界。为了不把一条尚未结算的连锁拆成错误结果，同一展示 Step 仍可覆盖多个决策。基础决策模块本身独立存在，可按合法时机组合。

回看棋盘、前后导航、教程图、一图流及决斗详情读取模块图；兼容字段 `Step.state` 由模块快照重新投影。妥协分支保留原 `node_id` 并关联真实 `module_id`。时间轴继续只开放原有可安全恢复的窗口；模块化续展本身不回退、不载入来源快照。

旧方案在内存中适配为观察模块，不改写原文件和冻结 revision。缺少决策、准确效果或后继确认时，模块来源显示资料待补充；可在新版引擎中重录后保存替换，原批注编辑入口继续保留。报告升级另存新的派生报告，原始 journal 和旧报告仍在本地。

## 效果身份与规则依据

菜单位置和 `Stringid` 描述索引不是卡面效果编号。每次发动记录引擎效果对象／句柄、owner／handler 及实例、触发事件、类型、属性标志、作用范围、分支标签、效果值、次数标识、剩余次数与 Lua 条件、代价、对象、处理函数行号。来源决策在当前合法提示中按这些语义重绑；多个效果无法唯一对应时拒绝任选一个。

卡面编号是独立的显示映射。已核对的文本摘要、发动位置和脚本对应关系才显示具体编号；文本变化会使映射失效。比如狐狸墓地效果使用描述索引 2，灯火美洲豹墓地效果使用索引 0，莫邪的同调素材抽牌效果描述为 0；它们不能简单标为索引加一。其他卡仍可按真实引擎身份区分执行，但未核对的卡面编号明确待核对。

费用、发动、对象与处理结果分别保留。判断规则以项目卡库、脚本和固定版本核心实际运行结果为准。官方 [PSCT 说明](https://www.yugioh-card.com/en/play/psct/psct-3/) 用于核对发动与处理的边界；[莫邪](https://www.db.yugioh-card.com/yugiohdb/card_search.action?cid=16489&ope=2&request_locale=en)、[烙印融合](https://www.db.yugioh-card.com/yugiohdb/card_search.action?cid=17066&ope=2&request_locale=cn)和[神炎龙](https://www.db.yugioh-card.com/yugiohdb/card_search.action?cid=17070&ope=2&request_locale=en)核对 Token 的同调限制、整回合融合限制以及弃牌费用和素材回收。源码没有为测试路线放宽这些规则。

## 隔离验证与执行确认

- 原生线程从本局起手和所有实际核心调用重建独立决斗，逐批比较重放结果及状态；每次模拟输入必须匹配完整的当前提示，并处于真正的选择处理器中。动画／展示等待不当作输入窗口。
- 选择卡牌按本局实体与区域重绑。叠放素材关联承载怪兽和素材序号；场上位置、连接区域、同名效果次数及召唤限制交给核心重新判断。无关手牌差异不会要求整张快照完全相同。
- 候选绑定局面版本、来源版本及偏好版本。提交前重新绑定、检查版本，再使用可撤销的一次性指令凭证；来源更新或停止 AI 会撤销尚未消费的凭证。
- 输入写入不等于效果成功。实际响应和后继 checkpoint 确认输入；效果成败看连锁事件和实际场面。到达终场还要检查结算窗口、终场资源、叠放素材及最后有效操作结果，不能仅因为场上卡名相同就提前完成。
- 相同输入的确认由锁串行处理。输入已被引擎接受但回执未到时不重复提交；无法确认则保留记录并暂停。
- 对手隐藏卡的身份与相关次数信息不进入正常推荐。未来随机抽牌隐藏身份，同时隐藏可反推出抽牌的剩余卡组组成；后续只能使用此前已知的卡，且候选保持条件标记。实际抽牌后再据已知状态重算。

## 搜索和评价边界

当前实测后的默认搜索预算为 32 秒、320 次节点校验、24 个候选。深度以来源最长记录加余量自适应，最多 128 次我方选择；单次原生探测另有 4 秒上限和循环检查。上述是计算预算，不是“游戏规则上无解”的判断。

| 偏好 | 当前排序依据 | 限制 |
| --- | --- | --- |
| 花费最少 | 先比较投入手牌数，再比较主卡组与额外卡组投入合计，最后比较其他原有区域的投入 | 从本次计算起点按实体去重；不以抽牌抵消已投入手牌，不把生命值与效果次数混成卡牌张数 |
| 终场最大 | 已实际验证的一次应对下界、场上及手牌资源、场上怪兽、额外资源与 LP | 应对测试只包含下一回合一张假设魔法的发动，并要求实际无效事件；其他能力标为未评估 |
| 步骤最少 | 达成相应终场的剩余来源决策数 | 空响应窗口的自动确认不计操作数；不承诺全游戏最短 |
| 平均 | 资源、终场、步骤三个标准化评分各占三分之一 | 资源按手牌优先的消耗排序映射为 0–100 分，终场按终场排序映射为 0–100 分，步骤按数量反向归一；只比较本轮已发现候选 |

决斗临时方案的终场评分继续只比较明确标记且匹配的卡牌和效果。投入资源按卡牌离开计算起点所在区域计一次，回收不冲销投入，同一实体跨区复用不重复计费，生成 Token 不计初始资源。续算重建资源统计起点，保留实际前缀但不重复收费；资源身份不完整时显示未评估，不当作零花费。限定灰流丽场景的校验证据仍保留，但不再作为独立排序选项。

终场应对评价总预算 4 秒，单候选最多 2.5 秒。费用和效果次数均在模拟中实际消耗，不能把同一卡牌多个互斥效果简单相加。No.75 的怪兽效果响应、睡梦貘的持续压制等不属于上述魔法无效测试，保持未评估。此版本不声称完成通用终场强度模型或覆盖所有牌组。

### 堆墓、灵摆和仪式

- **白骨**：依据 [Jamesbroispx 的基础路线](https://ygoprodeck.com/deck/skull-servants-252856)，齐唱僵尸送白骨烤王，检索王子与梦魇并弃王子；王子继续送墓、支付除外费用叫出白骨王，梦魇复活除外的白骨夫人。测试验证了不同送墓诱发、同名视为白骨的费用处理和回收后复用。
- **炼装／机壳**：采用 [Metalfoes 指南的 Qli 引擎](https://ygoprodeck.com/article/intro-to-metalfoes-part-4-the-not-so-secret-techs-1913)。明确选金驰刻度 1、钢人刻度 8；工具检索汇编器后被炼装效果破坏，随后从表侧额外与手牌灵摆召唤、叠新星及无限。检查 800 LP、表侧额外区域、一次灵摆召唤限制和继承的 3 个素材。同刻度反例被当前合法提示拒绝。
- **影灵衣**：参考 [Nekroz 作者路线](https://ygoprodeck.com/deck/nekroz-81656)，万华镜以额外卡组虹光为素材召唤尤尼科，虹光送墓检索光枪龙。另测只有不匹配等级素材时，万华镜不会出现为可发动选项。
- **随机堆墓**：单独测试光之援军。原生隔离探测会记录读取牌组顶或直接堆墓的私有结果，预测中的墓地身份与剩余牌组组成被遮蔽；随机结果仍需实际发生后确认。

### IF、补点与站位

相剑龙渊的补点思路来自同一份 [Swordsoul 干扰应对指南](https://outof.games/realms/yugioh/guides/206-combo-compendium-swordsoul-making-plays-and-avoiding-handtraps/)。测试区分无限泡影的效果无效、[朱光](https://www.db.yugioh-card.com/yugiohdb/card_search.action?cid=7673&ope=2&request_locale=en)的发动无效及[幽鬼兔](https://www.db.yugioh-card.com/yugiohdb/card_search.action?cid=11708&ope=2&request_locale=en)的破坏，记录费用和实际结果后再使用龙渊补点。幽鬼兔的场景另检查莫邪已发动的造 Token 效果仍可处理，不能把破坏当成无效。缺少龙渊的反例应暂停并保留本局。

站位测试将调试瓢虫女郎从 1 号格改到 2 号格：精确模式拒绝，自适应模式完成相同检索；开关变化拒绝旧候选。日光狼从左 EMZ 换至右 EMZ 后，灯火美洲豹按实际连接箭头进入 4 号格，不会沿用已经不合法的 2 号格。

重放还覆盖了无效后 Lua 垃圾回收导致的引用编号差异。原记录保留 `effect_handle`，跨副本相等检查排除此临时编号，仍核对效果登记 ID、卡牌实例、标志、值、脚本位置、费用和实际状态。

## 运行检查与本地数据

```powershell
npm test
npm run test:desktop
npm run test:modular
npm run build:dir
npm run test:packaged
npm run test:modular:packaged
```

模块化验收可用 `-- --suite=core|preferences|routes|cross|mechanics|if|precision|pipeline|forecast` 单独运行。`core` 包含隔离性、来源修订、过期拒绝、真实 AI 和转生炎兽偏离；`preferences` 检查三种偏好和中途切换；`routes` 检查 Combo 4–15；`cross` 检查相剑与烙印；`mechanics` 检查堆墓、灵摆、仪式与随机堆墓；`if` 检查真实打断和补点；`precision` 检查换格、开关失效保护和连接区；`pipeline` 验证展开供给与决斗临时方案的页面闭环；`forecast` 验证实际抽牌、随机堆墓和手牌阻抗后的重算。

证据保存在 `.local/evidence/electron-*-modular*/`，包括检索 JSON、实际执行审计、错误原路线和修订结果；用户数据不进入 Git。模块版本位于运行目录 `_trainer/modular/versions/`，索引失败不会把旧结果变成可执行。原始 journal、回退证据、旧方案和备份均保留。正常启动不开放内部输入／截图验收接口，验收不移动系统鼠标、不发送全局按键。
