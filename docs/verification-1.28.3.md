# 1.28.3 验证记录

## 变更

- 对方手牌展示以等量随机卡背代替录制实例的牌面和名称，卡片详情使用同一示意。自己的指定卡和对方明确发动的卡保留具体身份；原始依据、方案与记录不改写。
- 一图流长 Step 按内容加宽，必要时将同一步的操作分栏；短 Step 保持内容高度，同行中线对齐。箭头仍沿原操作／Step 顺序，导出不裁掉内容。
- 模块状态增加普通通常召唤上限与额外通常召唤使用状态；完整规则依旧由隔离核心重放，见[持续规则说明](continuous-rules.md)。

## 验收入口

- `npm test`：原有检查及随机手牌、具体发动身份、旧报告不变、长短 Step 布局、导出资源、召唤状态保留检查。
- `npm run test:desktop -- --tutorial-presentation-only` 与 `npm run test:packaged -- --tutorial-presentation-only`：隐藏窗口中检查随机手牌数量、详情、指定卡保留、图形边界及 SVG/PNG 导出。
- `npm run test:modular -- --suite=rules` 与 `npm run test:modular:packaged -- --suite=rules`：真实引擎检查额外召唤、场地离场／替换及③的后续限制。

上述检查均通过：374 项 Python、206 项 JavaScript；开发版与发布包的展示／导出专项通过；两个版本的真实规则专项通过。原生客户端已重新编译，发布包已核对新客户端及修改后的前端资源。

另以本地旧冻结来源验证新版兼容性：准备好来源索引后，原有 5 张起手与 5 个来源仍生成 2 条经过引擎验证的候选，原方案文件哈希保持不变。完整私有样例只留在本地。

验收只操作应用创建的隐藏窗口与隔离数据，不发送全局输入。截图、导出文件、原生日志、规则验证样例和程序包保留在本地忽略目录；无个人牌组或对局记录纳入 Git。旧包与用户文件保留。
