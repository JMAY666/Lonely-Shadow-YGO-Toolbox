# 两阶段内置后攻流程与响应窗口复盘（1.32.0）

本次衔接 P1.2 的条件提示与 P1.3 的原生续算。可在对手首回合、引擎等待我方响应时关联同一内置练习，之后保留同一份起手、人工条件、计划和观察记录，进入我方回合后继续规划。第一期尚有未覆盖的规则与战斗验收，不将本次有限流程称为全部功能完成。

## 进入和使用

1. 在工具箱展开功能中开始后攻练习；沿用 BO1 手动后攻入口，选择同一构筑及原始起手。在填写独立人工资源观察之前点击“关联内置后攻练习”。
2. 可关联对手首回合的我方响应窗口，或我方首回合主要阶段 1 的已结算操作点。核对记录后，后台完整重放并比较当前规则状态；其他时点保留未支持提示。
3. 对手回合中，程序只对已登记的阿鲁伯①、莫邪①和烙印融合发动识别具体窗口。来源实例、具体效果及连锁必须与原生记录一致；不凭卡名把另一效果当成已有案例。
4. 当前手坑若出现在原生合法菜单中，次数核对可据此取得相应依据；菜单未开放的手牌效果不能靠人工勾选变成可用。菜单开放仍不等于已经验证所有对象、保护及后续处理，公开条件和手牌保留用途仍需核对。
5. 条件提示比较交与不交。记录计划只保存意图；实际出牌在原练习中操作，之后点击“同步实际局面”。费用、区域变化、实际抽牌和次数来自同一原生日志，不再重复手填扣牌。
6. 进入我方回合，自动展示后攻路线区域。选择已有来源和目标，计算未执行后续。对手不响应、不同对象上的干扰或连续干扰发生后，再同步真实节点并重新计算；此前已执行历史、原始起手、旧建议和计划不改写。

原练习进入新窗口时，旧建议立即失去采用资格；界面定期核对，采用请求也会再次核对。窗口超时、断流、资源变化、换局和应用重启都不能沿用旧权限。

## 人工记录与原生状态的分工

- 尚未关联原生练习的 P1.1/P1.2 人工流程保持原样，外部平台继续使用现有范围。
- 关联后，可保留用途、公开条件、玩家选择／观察备注，以及未结构化规则备注。核对回合、阶段、LP 或手牌数量时，必须与该原生节点一致。
- 卡牌移动、抽牌、效果次数、实际发动及处理结果不再允许另行手填覆盖；应在原练习操作后同步。重复请求不能通过手工事件再次消耗一张手坑。
- 未结构化的次数或限制备注不会自动变成引擎权限，也不会静默忽略；存在未核对的此类备注时，停止依赖它们的确定提示和续算，说明需要核对。
- 原先已有独立人工资源记录的局面不能直接绑定另一份原生历史；旧记录保留。1.31.0 已关联记录中的安全备注可以继续续接，独立人工资源改动仍拒绝静默合并。

## 窗口复盘

展开“提示与计划历史”，点击“当时信息与实际结果”，分别查看：

1. 生成提示时的原始已知状态、公开来源、手牌、比较及计划，不由当前局面倒填。
2. 玩家单独记录的选择／观察备注，显示记录时间，并标明尚未自动核实；它们不补入生成时的知识。
3. 该窗口之后直到首个已记录的空连锁节点的实际结果。原生事件分别显示发动无效、效果无效和目标位置；未完整解码的内容保留范围提示。
4. 两端公开状态中离开原手牌／场面的实例。这是状态变化，不自动等于支付费用、破坏或无效，也不与预计阻止获得的资源相加。

对手的私有菜单不解码成玩家已知动作；未知手牌、盖卡和牌序仍保持未知。后来公开的卡只出现在相应实际节点，不修改旧窗口的已知状态。不提供事后胜率、绝对最优评价或把未选路线当成实际结果。

## 范围与剩余验收

开发和打包验收使用转生炎兽小轴、灰流丽、阿鲁伯、雷击和无限泡影的固定原生场景，具体结果见[验证记录](verification-1.32.0.md)。沿用[条件提示的来源与规则范围](bo1-second-hints.md)和[后攻续算范围](bo1-second-routes.md)；引擎资源没有变更。

本期仍不接入外部 MD／YGOPro／YGOPRO2／MDPRO3 的完整规则状态，不认证 MD 卡池或禁限表。仅比较当前有限窗口与来源；复杂多重连锁的策略提示、主动枚举所有对手响应、完整威胁排序、假面变化等剩余材料核验及战斗／伤害／斩杀仍待后续。续算遇到搜索范围不足时说明缺项，不声称规则上无解。
