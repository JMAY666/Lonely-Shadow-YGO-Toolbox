# 内置后攻练习的规则重建与路线续算

1.31.0 完成 P1.3 的我方回合续算；1.32.0 将原生接入提前到对手回合，并允许安全备注与[两阶段流程](bo1-second-flow.md)连续保存。

在 BO1 后攻工作区增加本机内置练习的只读接入。完整原生日志用于恢复双方当前场面、实际手牌、已用次数、费用、召唤权限和持续限制；已有正式方案及妥协来源用于搜索后续。原始起手、真实练习、正式方案和原观察历史保持独立。

## 当前范围

- 仅接入工具箱内置的后攻主线练习，构筑及原始起手必须与后攻记录一致。可同步对手首回合的我方响应窗口；路线续算仍要求我方首个回合主要阶段 1、无正在处理的连锁、引擎等待我方操作。最近 100 个练习中筛选符合条件者。
- 原生日志、可恢复节点、引擎、脚本和卡库必须齐备且匹配。恢复使用独立隐藏引擎，不向原练习或外部客户端提交输入。普通场面截图、人工摆放的卡牌或相同手牌不能替代完整规则历史。
- 新记录可关联；已有独立人工资源观察不能被原生快照覆盖。关联后的用途、条件核对和选择备注可以保留并继续同步；卡牌、费用、次数及实际结果由原生日志维护。关联之后不能换练习，也不能在原练习回退、改写历史后继续冒充同一路径。
- 对手的未知手牌、牌序、盖卡身份和未公开次数不进入公开状态或策略依据。候选按“对手不追加响应”进行条件比较；依赖未公开卡牌揭示或必须由对手选择的分支会停在信息不足。内核为重放保留的隐藏数据不作为玩家已知信息输出。
- 只搜索主要阶段的有来源操作。当前目标可选“处理起点已公开的对手怪兽并建立来源终场”或“仅比较来源展开终场”。前者要求对应实例经规则处理后离开对手怪兽区，不能只匹配我方终场。
- 不把选定怪兽离场等同于解除全部封锁；其他魔陷、残留限制及保护仍按核心验证，策略上的完整威胁排序尚待扩展。战斗、伤害、斩杀、多种对手响应的主动分支比较尚未提供。
- MD、YGOPro、YGOPRO2、MDPRO3 外部实战仍使用观察和条件提示；本期没有可靠的完整外部规则历史，不开放外部状态重建。内置自由练习不代表 MD 卡池或禁限表验证。

## 操作流程

1. 在原展开功能准备后攻练习，并录制、保存可复用的正式方案或妥协来源。卡组及来源的 TAG 使用现有规则。
2. 沿用 BO1 手动后攻入口，选择同一构筑并填写原始起手，创建空白后攻记录。
3. 展开“我方回合路线续算 · 内置练习接入”，查找匹配的本机后攻练习，确认确为本局后，点击“重建并同步实际局面”。我方回合默认展开路线工作区，对手回合提示收起供回看。
4. 引擎先验证完整重放及当前场面一致，成功后导入该节点以前的公开历史。手坑费用和实际抽牌均来自日志，不将原始五张直接加成六张。
5. 选择已有来源、解场目标及偏好，计算剩余路线。最多展示三项，操作、费用、预期终场、来源和前提可展开查看。计算未完成或没有候选会说明搜索范围。
6. “记录计划采用”仅记录意图，不扣牌、不执行游戏。回到原练习自行操作；对手未响应、实际交康或操作顺序改变后，在工作区同步原练习的最新已结算决策点。
7. 新节点必须延续原生历史。保留已导入前缀、旧路线比较和计划；重新从当前状态核对来源动作及目标，已消耗的通召或效果次数不会返还。旧候选因原练习、观察、来源或规则变化而停止采用。

原练习已经结束时，界面说明正在依据最后节点进行复盘规划。候选仍是推演，不记成实际发生的后续；之后获得的隐藏信息不会补入旧节点或旧比较。

## 状态与持久化

`native_history` 只保存截至同步节点的公开规则快照，后续同步核对原前缀完全一致；`native_link` 绑定练习及节点；`route_history` 独立保存当时的候选、观察版本、目标、偏好与计划选择。原 `input.opening`、`events`、`advice_history` 不被重写。

原生日志和规则恢复材料保留在各自本地目录，隔离引擎沿用现有 `purpose=duel_planning` 生命周期。手工修改、关闭记录、换局或资源变化使结果失效。计算期间变化、迟到结果或保存失败均不发布可采用的旧候选；应用重启后不能恢复旧引擎权限。

## 已验证案例与依据

使用固定本地资源，在开发版和打包版分别验证转生炎兽小轴与雷击的有限场景：解场后连接召唤；实际先通召后的续算；对手实际以灰流丽无效羚羊后的续算；我方在对手首回合使用灰流丽，再正常抽一张，当前五张而原始五张不变。

雷击的破坏处理以[官方卡文](https://www.db.yugioh-card.com/yugiohdb/card_search.action?cid=4343&ope=2&request_locale=cn)和本地核心实际处理为依据，不称为发动或效果无效。灰流丽、阿鲁伯的规则依据见[条件提示说明](bo1-second-hints.md)。既有转生炎兽来源与素材／次数验证见[模块化说明](modular.md)。以上测试构筑是明确标记的自由练习夹具，不代表赛事或 MD 合法牌表，也不代表这些卡组的全部交互已经覆盖。

检查命令：`npm test`、`npm run test:modular -- --suite=second-routes`、`npm run test:modular:packaged -- --suite=second-routes`、后攻界面的 `npm run test:desktop -- --second-only` / `npm run test:packaged -- --second-only`。具体结果见[1.31.0 验证记录](verification-1.31.0.md)。
