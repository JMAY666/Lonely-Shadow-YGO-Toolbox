# 1.25.0 验收与性能记录

2026-09-17，在同一台 Windows 11 10.0.26200、Ryzen 7 9800X3D（8 核／16 线程）机器上执行。所有场地、构筑、方案与账户状态均来自 `.local` 隔离验收目录；不操作外部玩家窗口，不发送全局鼠标／按键。

## 行为验收

| 场景 | 结果与证据 |
| --- | --- |
| 羚羊送墓咆哮、猞猁检索圣域、圣域再次连接、咆哮盖放 | 开发版及最终包由当前规则引擎实际完成；分别识别卡组送墓、卡组检索与墓地盖放，最后一项关联前面的送墓 |
| 唯一圣域在手／仍有另一个副本 | 唯一副本上手时解释对应步骤卡组剩余 0 张；仍有副本时通过资源检查 |
| 额外手牌、同名份数、循环回收、费用 | 按步骤和实例核对；一次选择的两个副本合计数量，返回卡组后可继续使用同一实例；通用费用不抢占后续指定起手牌 |
| 随机抽牌、随机堆墓、实际阻抗 | 不把录制命中当作确定条件；真实引擎接受实际结果后续算；未确认结果隐藏身份 |
| 保存确认、管理、旧记录、一图流 | 两处条件一致，读取与补算不修改原文件；不完整记录待核对；SVG 保留检索、送墓等操作而不增加条件区 |
| 主线与分支 | 分别推导与核对；两条真实分支共同保存、重启重开、终场、批注与分支图导出通过。未发生的 IF 干扰不能被升级为无条件起手替代路线 |
| 无需打开面板的预计算 | 进入已确认局面后自动发起一个任务；四种偏好都得到各自评价，三种不同目标的录制来源得到正确的不同推荐 |
| 重复点击与偏好切换 | 同一有效任务只有一次 prepare；切换读取已准备结果，不启动新的全套搜索；部分结果继续标明范围未完成 |
| 改设置、取消和迟到结果 | 最终包在首次搜索仍运行时连续改变精确设置及来源，自动重建；旧任务采用请求被拒绝，新结果对应最新来源 |
| 失败重试 | 空来源明确失败；失败后切换偏好没有恢复旧候选；恢复来源后重试成功 |
| 真实展开及已确认进度 | 手动／自动模式的采用、确认、实际情况、普通 Step 续算和结束清理通过；后台和失败重试保留原教程，独立真实展开日志逐字节不变 |

## 同机测量

旧版为提交 `3f1d41c` 的独立源码副本；新版为本次实现。每版使用新的应用数据目录，前后顺序运行，测量期间没有其他本任务的验收进程。40 张主卡组、相同 5 张起手、3 个指定来源；逐项比对确认构筑、起手、卡片文本、引擎指纹、脚本指纹及非自动来源决策均相同。这里只测一个固定样本，不能外推所有卡组和来源规模。

“未命中”指新会话的候选／路径缓存，不代表清空操作系统磁盘缓存。后台时间从输入齐备后的自动准备到客户端拿到结果；首次点击按处理函数到候选 DOM 可用计时，不包含显示器最终绘制。偏好切换包含控件事件、读取结果与渲染等待。

| 指标 | 旧版 1.24 | 新版 1.25 |
| --- | ---: | ---: |
| 首轮搜索计算耗时 | 18.778 秒 | 18.847 秒 |
| 点击前后台准备 | 未启动 | 客户端 21.066 秒；服务任务 20.581 秒 |
| 首次点击后的等待 | 20.522 秒 | 已就绪时 4 毫秒 |

| 渲染器 100 ms 定时器最大／平均额外延迟 | 97.1／1.95 ms | 54.7／3.91 ms |

首次搜索计算没有实测加速；收益主要是计算提前、共享候选池及复用偏好结果。原版每次切换会利用旧路径缓存继续增加最多约 320 次新验证，新版四种偏好共享一轮预算，因此累计搜索范围不同，不能用总耗时比例宣称搜索算法加速倍数。两版每轮都到达预算边界，均为 `complete=false`，原来源检查为 3／3；界面如实标记仍有混合路径未搜索完毕。新版不是从“步骤最少”的前 24 条重排其他偏好，而是在完整已发现池上分别评价后截取。

采样工作集和 CPU 仅覆盖 Python 服务及其所属引擎，不是整机、GPU 或完整 Electron 内存。渲染延迟是本样本的辅助指标，不是前台帧率保证。重试虽然命中更多缓存，也会检查新的路径，未承诺固定耗时或任意规模“秒出”。

完整本地证据分别位于 `.local/implicit-baseline-app/.local/evidence/electron-development-modular-planning-measured-v124`、`.local/evidence/electron-development-modular-planning-measured-v125-final`，最终包的并发与恢复证据位于 `.local/evidence/electron-packaged-modular-planning-implicit-races-final`。

## 保留的边界

资源账本是必要条件检查；模块路线仍逐次通过当前规则引擎。无法可靠解码的选择、复杂随机处理或对手区域信息保持待核对，不用卡名猜条件。稳妥优先仍只有原有的限定灰流丽场景；没有重定义终场和均衡口径，也没有评估所有手坑与胜率。若外部直接改动运行中的规则文件，旧候选和后续确认被拒绝、教程保留，需重新建立引擎。临时结果不跨应用重启恢复，不自动存为正式方案。
