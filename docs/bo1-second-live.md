# YGOPro 公开资源只读核对（1.34.0 起）

这是 P2.1 的有限资源快照接入。它把玩家可知资源带入原后攻记录，同时保留原始起手、已确认历史及未知规则。完整事件流和规则状态仍未重建，不能将外部场面送入内置路线或攻击顺序验证。

1.35.0 增加[阶段、已观察的回合玩家及素材归属](bo1-second-context.md)；旧快照保留原有覆盖范围，不补写后来才读取的信息。

1.36.0 增加[公开连锁条目及有限我方客户端选项](bo1-second-chain.md)，仍为当时快照，不能代替完整事件或规则认证。

## 入口与操作

1. 沿用 BO1 → 自动 → YGOPro 的开局识别，确认后攻并完整捕获起手后进入工作区。仅支持既有镜像指纹 `55dd3e8ea4e9a0f24bb2b038e4c95f6e266140469be3480924ff1e57dda1e629`，其他版本、观战、录像、TAG、单人谜题和换副状态拒绝读取。
2. 展开“YGOPro 公开资源只读核对”，点击“读取公开资源”。预览显示手牌、可见卡牌、区域张数、LP 和未覆盖项，当前人工资源不被覆盖。
3. 核对预览后勾选确认，点击“再次读取核对并采用”。后台重新读取，只有局次、进程、场景、观察版本和快照内容仍一致才保存。期间变化时保留原记录并要求重新读取。
4. 采用后，已覆盖资源由读取维护，避免另行手工移动或再次扣牌。原人工记录留在观察历史；牌库仅保留数量。当前卡片重新作为观察实例，不能推断跨移动的同一实例或沿用实例权限，手牌用途需重填。
5. 1.35.0 可读取可见阶段，并在连续捕捉到对应回合切换时填写回合玩家；未读到的项目仍由玩家核对，不按奇偶推断。费用原因、发动／无效类型、次数及限制作为人工核对和备注分别记录，快照不会把它们自动证实。
6. 工作区轮询会只读核对资源是否仍相符。变化、断流或过期会停用依赖旧状态的建议，提示重新读取并采用；不会静默覆盖正在填写的内容。跨局、关闭或重启后拒绝旧局面的权限与迟到结果。

这是“读取 → 核对 → 采用”的流程；持续自动合并事件尚未实现。原未关联的人工流程、MD／YGOPRO2／MDPRO3 入口和内置规则推演边界不变。

## 字段覆盖和证据等级

| 字段 | 本版处理 | 验证与限制 |
| --- | --- | --- |
| 构建、进程、先后攻与原始起手 | 复用原开局识别；每次核对进程创建身份与模块基址 | 固定构建；跨局身份不以手牌相同代替 |
| 当前我方手牌 | 读当前区域，保留重复份数 | 实机用户逐项确认，另核对操作后 6 → 5 → 4 的变化 |
| 双方 LP | 读客户端本地视角值 | 实机用户确认，操作后的数值变化可读；不推断费用或伤害来源 |
| 场上可见卡、位置、表示及未知盖卡 | 公开／我方已知卡读取身份；对手里侧不读卡号 | 公开怪兽、未知盖卡和我方通召实机核对；更多控制权变化未验收 |
| 双方墓地、除外、额外及区域数量 | 依区域与可知性投影，隐藏额外只保留数量 | 边界测试通过，部分实际移动已读取；未逐张人工确认所有区域或所有特殊情形 |
| 双方牌库、对手手牌 | 只计数量，不输出未知身份或牌序 | 单元测试禁止访问这些身份字段 |
| 卡片详情 | 使用本地卡库的已知卡号资料 | 未逐项认证外部卡库、脚本及禁限表一致性 |
| 回合数 | 读取客户端计数 | 不凭奇偶判断当前回合玩家 |
| 阶段 | 1.35.0 读取阶段控件的可见文字 | 主要阶段 1／战斗／主要阶段 2 实机确认；不区分战斗细分时点 |
| 回合玩家 | 1.35.0 仅在观察到计数递增及对应新回合消息时填写 | 实机捕捉对手 → 我方切换；晚接入、漏读或中断保持未知 |
| 怪兽承载素材 | 1.35.0 读取数量与归属，核对素材回指；对手里侧承载怪兽下的素材身份保守隐藏 | 一个承载怪兽及两张素材实机核对；更多控制权／隐藏交互仍待验收 |
| 连锁列表、有限我方选择 | 1.36.0 读取已入列的公开条目，并交叉核对我方可选标记 | 完整事件、目标、费用、处理结果及规则权限未认证，详见[覆盖范围](bo1-second-chain.md) |
| 指示物、次数、持续限制 | 保持未读取／人工核对状态 | 不能据此证明合法响应或重建规则 |
| 相邻快照的差异 | 记录资源观察与时点 | 不推断完整操作顺序、费用、破坏或两类无效 |

字段布局来源及实机核对见[读取研究](ygopro-live-state-research.md)。同版本号不代表同布局，新增构建必须单独启用资源布局标识。同步过程没有注入、写内存、发送客户端输入或联网对战操作。

## 状态、复盘与数据保留

预览保存为独立 `live_reads`（每局上限 200 次）；采用后保存 `live_history` 和 `live_sync` 观察，原 `input.opening` 不变。读取与采用分开，不把预览当作已修改的当前资源。内存地址只用于服务端核对，不进入公开快照。

历史快照按当时可知信息保存，不以后来揭示的隐藏身份回填。同步不返还已用的共享效果次数；未证明同一实例的状态保持待核对。对局中手坑、抽牌、LP 或场面变化后，应核对当前资源，不能使用“起手五张加第六张”恢复。

已采用记录的当前资源标记需要最近 2 秒内读取相符；预览超时标为历史，采用时仍须重新读取。连接中断不能继续采用；原始日志、快照、正式方案、先攻流程、个人记录及备份保留。实际检查与未完成项目见[验证记录](verification-1.34.0.md)。
