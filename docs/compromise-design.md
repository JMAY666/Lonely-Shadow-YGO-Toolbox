# 妥协场构建

一套方案包含一条主线与多个独立妥协分支。本次不支持在分支内继续建立子分支；界面与服务都会拒绝嵌套创建。主线已有动作和终场保持完整。分支继承分支点之前的原始事件，后面的输入、结算和终场独立记录。

## 操作与保存

1. 正常完成主线，在“展开方案调整与保存”顶部时间轴右键目标步骤（或聚焦后按 Shift+F10），在就近弹窗中选择明确的恢复时点。“发动后的响应窗口”与“结算后”分开列出。
2. 在右键弹窗中点击“从此处创建妥协分支”，进入前置面板，核对方案、分支、源步骤与时点。设置对手场景手牌数量和预期受干扰的我方操作；这只是预设，不代表发动或结算。
3. 进入妥协场后，对手先处于手动接管。主窗口保留原生我方操作场地，对手窗口展示同一引擎的场面和合法选择。每次提交绑定当前选择版本，重复或过期输入不会推进另一窗口。
4. 多次接管和交还 AI 均保留当前状态。关闭对手窗口先完成交还托管；再次接管可重新打开。空连锁选择没有可选卡时自动通过，不运行 AI 策略选择。基础 AI 无法处理的复杂选择交回手动。
5. 结束妥协展开后回到所属方案。可调整分支步骤、逐卡说明与终场标记，补充未确定干扰的关联。保存时回到主线资源口径，所有分支一起进入二次确认；创建、配置或结束分支都不直接生成正式方案。
6. 对手手牌份数改变会开启新的模拟尝试，旧尝试原始文件及已编辑说明保留；仅改名称、条件说明或预期关联不清空已完成的模拟。删除只修改待保存分支集合，确认保存后才影响正式方案；不删除主线、其他分支或原始记录。

## 恢复边界

新原生记录在双方合法选择点保存恢复描述与引擎调用引用。普通实时回退继续展示结算后的我方操作节点；妥协分支另外使用精确的双方响应节点。

恢复先使用相同牌组顺序、随机种子与配置创建独立核心，按原顺序重放引擎处理、双方响应以及可能执行 Lua 的查询。逐项比较返回数据，再核对完整可观察状态。原生对象内的已支付代价、效果次数限制、当前处理栈、连锁和随机状态由重放恢复，而非根据卡图重新拼装。

场景手牌在生成目标选择的引擎处理之前配置。已有对应副本保留，不匹配的对手手牌仅从当前假设场景中移出，新增卡使用引擎初始化接口建立；配置不伪装成规则中的抽卡或发动事件，也不额外制造手牌洗切。之后重新运行目标处理，要求此前输出不变、仍是同一方的合法选择边界，且除场景手牌外的状态一致。单候选的是否发动窗口与多候选连锁选择均可表示同一个响应时点。

无法通过校验时拒绝进入，显示失败原因；主线不受影响。尤其不能在已结算步骤上补写一次无效，也不能沿用主线之后已经抽到的牌。历史方案缺少重放文件、脚本身份或准确的响应节点时只能回看。引擎、卡牌数据库、效果脚本版本不一致也拒绝恢复。分享导入的方案能查看分支，但不提供本机对局重放能力。

## 证据与统计

实际干扰使用引擎的发动编号、连锁结算区间和明确的无效事件建立关联。没有可靠来源时仅列“已发动／具体影响未确认”，不把效果对象自动认定为受影响卡牌。用户关联单独标记，不覆盖引擎事实。接管操作完整保存在分支原始日志和控制记录中。

默认统计沿用主线已有口径：本路线实际使用的卡牌实例及原有费用替代规则，并不宣称证明所有可能路线的最小资源。展开管理中的“统计包含当前分支的新增资源”只对当前选择的一条分支计算新增份数，共用资源不重计，不把互斥分支相加。途中随机依赖独立保留，对手场景卡不计入我方资源。

一图流用虚线边界划分主线与各分支。连接起点绑定原始动作所在步骤中的对应动作位置，并带恢复节点标识；终点进入该分支前提。起点失效时明确标记，不重新绑定其他步骤。各分支有自己的终场展示区，不重复列起手条件；默认导出仍只有主线；PNG 和 SVG 均包含所选分支卡图。

## 本地数据与恢复

- `_trainer/sessions/<主线 UUID>/core-calls.txt`：只追加的引擎调用记录。
- 同目录 `restore-<节点>.txt`：该节点的调用引用、提示与校验状态。原始 `native.jsonl`、牌组和旧报告保留。
- `_trainer/plans/branch-drafts/<主线 UUID>.json`：待确认的分支配置、归属和模拟尝试引用，使用版本号检查并发修改。
- 每次分支模拟使用独立 session 目录，包含继承的主线前缀、重放输入和新的实际事件；不覆盖主线目录。旧尝试保留在原目录。
- 正式方案 JSON 包含主线和分支冻结报告；修改前保留原有方案 revision 备份。分享只携带展示数据，不携带本机路径、原生调用文件或控制请求。

工作副本、验收资料与打包产物仍留在 `.local/`、`release/`，不进入 Git。忽略不删除本地数据。手动恢复用户数据时，先退出应用并备份整个 `_trainer`，将整份会话／方案及对应重放文件恢复到新的数据副本；单独复制场面截图不能恢复对局。

## 验收入口

`npm test` 覆盖节点边界、分支隔离、删除范围、版本冲突、未知因果、资源统计和一图流连接。`npm run test:desktop` 与 `npm run test:packaged` 包含 `desktop/compromise-smoke.cjs`：真实发动两张“苦涩的选择”建立墓地，主线发动“贪欲之壶”回收五只怪兽并抽两张；从响应窗口建立“灰流丽”分支，由对手窗口实际响应并核对效果无效、没有继承抽牌、继续展开、反复交接、同节点另一条不发动分支、统一保存、默认主线及导出。

调试单独运行此场景可使用 `node desktop/smoke.cjs --compromise-only`，打包版追加 `--packaged`。所有桌面检查使用隐藏 Electron、原生内部命中／截图接口与隔离数据目录，不操作系统鼠标或发送全局按键。具体执行结果以本次交付报告和 `.local/evidence/` 的验收产物为准。
