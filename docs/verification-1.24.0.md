# 1.24.0 自动模式方案与展开教程

## 实现范围

- 先攻的「确认起手，下一步」接入独立自动方案页，玩家选择方案后进入独立自动教程。
- 自动模式拥有自己的选择、排序、收藏过滤、图位置、临时推演、弹窗与快捷键会话。手动模式仍使用原状态和页面；共用卡牌展示、正式方案库、收藏配置与规则引擎基础服务。
- 支持普通方案匹配和详细预览、可用分支、教程导航、场面与区域查看、图高度调整、快捷键，以及后台临时方案生成、采用、步骤确认、实际情况填报和续算。
- 后端冻结已确认的构筑、TAG、起手和局次；核对实际提交卡组，拒绝串用其他工作区的推演。结束、重捕捉及新对局清理自己的后台会话；迟到响应不会控制新页面。
- 继续保留后攻起手。后攻教程、自动选方案、实际出牌跟踪和自动推进教程不在本次实现范围。

## 验证方式与边界

所有桌面验收在 `YGO_DESKTOP_TEST=1`、隐藏 Electron 与隔离 `.local/desktop-check-*` 数据目录运行。只向测试窗口及内部引擎输入，不移动系统鼠标，不发送全局键盘输入，不操作玩家的游戏。

1. 单元测试：`npm test`，268 项 Python 和 181 项 JavaScript 通过。包括快照冻结、卡组不符阻止确认、确认写入失败回滚、源方案变更复核、只读私有卡组、推演归属、关闭后的迟到请求、离开教程释放快捷键和旧流程回归。
2. 自动工作区桌面验收：`npm run test:desktop -- --automatic-workspace-only` 与 `npm run test:packaged -- --automatic-workspace-only` 最终均通过。以前置捕捉样例构造已确认输入，实际调用匹配、选择、收藏及关闭接口；检验独立 DOM、排序、详细预览、分支、图高度、快捷键、模式切换与源文件字节不变。
3. 前置自动流程回归：`npm run test:desktop -- --automatic-only`，进程失败重试、卡组保存与覆盖、先后攻确认、起手预览、后攻留存和新局重置通过。进程数据使用明确标识的测试样例，不宣称本次重新完成外部 YGOPro 实机猜拳或发牌测试。
4. 真实规则引擎：设置 `YGO_MODULAR_PIPELINE_ONLY=1` 后分别执行 `npm run test:desktop -- --modular-only` 与 `npm run test:packaged -- --modular-only`。从隔离展开中实际操作并正式保存来源，验证手动及自动五张起手的后台生成、偏好重搜、采用、步骤确认、无效结果填报保护、普通步骤续算、从起手重新生成与会话关闭。确认过程不写实际输入日志，不新增展开历史，不修改来源方案。
5. 手动模式完整交互回归：`npm run test:desktop -- --duel-only` 通过，包括原卡组与标记、起手、方案、分支预览、场面、快捷键、悬停点击安全、设置和结束清理。最后的快捷键变更另外通过自动工作区套件核对离开模块和返回教程。

初轮界面验收发现自动图高亮和候选采用仍引用旧 DOM 字段，已修正并重测。追加离开模块检查后修复快捷键未及时释放的问题，并验证其他模块的按键不被拦截。分支测试样例补足实际分叉后的事件，避免把继承事件误作新步骤；引擎测试样例补充已确认先攻状态。一次成品复测在共用启动检查的侧栏按钮等待可操作时超时，未到达业务页；新建隔离验收目录后的最终重跑已通过，原始失败日志留在本地。

本次未找到运行中的已适配外部 YGOPro 构建，因此本局提交卡组核对只完成内存接口单元验证，未做新的外部游戏实机联动。不将合成教程展示当作引擎合法性证据，也不将引擎模拟当作已读取真实玩家出牌。
