# 1.19.1 原生游戏画面绘制隔离

用户指出跳动发生在背景、场地和卡牌所在的原生画面。1.19.0 的窗口位置与裁剪次数检查不足以证明最终画面稳定，因此本次继续检查父窗口绘制边界。

## 定位与修复

隔离实例连续捕获的 60 帧原生画面完全一致。窗口检查发现游戏子窗口已具备兄弟窗口裁剪，但 Electron 主窗口缺少 `WS_CLIPCHILDREN`。按照 [Win32 子窗口绘制规则](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#clipping)，父窗口会向子窗口区域绘制，除非显式排除该区域；这条覆盖路径此前未被就绪检查识别。

现在仅对经过归属验证的本应用父窗口补上该样式，保留其他样式位，并刷新缓存样式；不移动、缩放、激活或额外重绘窗口。样式被外壳重置时可以恢复。原生就绪检查同时要求父窗口绘制隔离及没有分层兄弟窗口覆盖。规则引擎、起手、场地几何和操作接口保持原有行为。

## 验收

新增回归在修复前失败：父窗口允许向游戏区域绘制，且就绪状态未识别这个问题。修复后检查父窗口样式、原有窗口几何、样式重置后的恢复，以及不会修改其他进程的窗口。

后台 Electron 通过本应用渲染器反复生成新帧，同时采集 16 帧引擎画面的固定背景区域。检查背景不是黑屏、像素哈希一致、原生窗口位置不变、父窗口绘制隔离持续启用；随后继续验证真实操作和重启。

最终结果：

- `npm test`：234 项 Python、164 项 JavaScript 通过。
- `npm run test:desktop -- --native-only`、`npm run test:packaged -- --native-only`：两种构建均通过，渲染器错误列表为空；覆盖画面采样、实际操作、时间轴恢复、缩放、保存、重启与关闭。
- 两种构建各 16 次外层重绘下，游戏背景区域均只有一个像素哈希，全部采样像素保持非黑色；没有坐标跳变，父窗口保护始终启用。证据：`.local/evidence/electron-{development,packaged}-native-parent-paint-final/`。
- `npm run build:dir` 通过；本地包的 79 个 trainer 文件与源码一致，28,888 项运行资源通过允许范围检查。

早期完整单元检查中，超先行事务测试出现间歇失败；加强安装成功的前置断言和预期恢复错误断言后，单独检查及完整检查通过。本次没有修改补丁业务实现。新增画面检查最初在 Electron 的评估上下文中调用了不可用的 `require`，已将哈希计算移回测试进程并重新通过。

测试仅操作隐藏的隔离实例，没有接管用户当前窗口；物理显示器上的实际跳动是否消失仍需在新版确认。旧版本、个人卡组和对局记录保留，本地包及截图不纳入 Git。
