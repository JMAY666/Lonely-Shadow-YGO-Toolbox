# 1.38.1 统一标注与并列备注

根据用户补充，终场标注从「选择一个来源替换」改为「同一卡牌合并维护」。支持合并单卡全部来源、一键合并全部卡牌，以及单独追加一个来源。卡牌用途与每个效果的备注都使用独立条目并列展示，可添加、编辑、移除。

## 数据与兼容

- 卡号去重；效果只按相同文本或完全相同的文本快照内编号对应，其他效果保留原文与备注并标为待核对。允许用户核对后归入当前效果。
- 相同备注合并来源，不同备注并列，不覆盖已有手写说明。已合并的相同来源版本不会撤销后续手动修改、恢复删除的备注或推翻效果归入结果；来源内容修订后可追加新版本快照。
- 旧单条备注在读取时映射为一条备注，纯读取不改写文件；首次实际写入前仍备份原 TAG 文件。数据继续保存在现有本地词库中，没有第二套卡牌或 TAG 数据库。
- 应用到展开实例时，将多条备注用空行分隔放入原有字符串字段，效果对象仍只有原格式的备注属性。超过原方案单处 4000 字限制时保留通用数据并阻止截断应用。通用条目与备注数量不自动增加原有路线评分或阻抗次数。
- 所有来源读取、合并和通用修改均不改写历史方案；测试对合成来源文件逐字节核对。批量合并使用同一次原子提交，来源过期或写入失败不会部分落盘。

## 范围

本轮针对情报站的合并、编辑、复用和持久化进行验证，不重新运行全部原生决斗、外部客户端识别或真人联机。合并表示集中维护用户资料，不验证不同备注在同一局面中都有效。来源文本不能确定对应关系时保留待核对，不猜测效果对应。

沿用现有 `.local/`、`release/` 等忽略规则。个人资料、备份、旧版本包与验收证据均留在本地；清理只针对已退出测试实例中经过路径、进程和资源哈希检查的可重建资源。

本轮清理两个已退出开发验收实例的 57,774 个资源副本，共 2,557,888,322 字节（约 2.6 GB）。其 JSON／JSONL、备注、来源方案、备份、截图和检查结果保留，最终打包验收与情报站回归环境继续保留供复现。
