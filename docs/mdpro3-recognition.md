# MDPRO3 智能化识别

1.29.0 补充：后攻冻结起手后进入[独立局面记录](bo1-second.md)，后续资源人工核对。下文保留此前开局验收背景；本次不增加 MDPRO3 真人后攻或完整局面跟踪的验证声明。

平台选择新增「MDPRO3 · 仿官方作品 Master Duel」，使用当前客户端内置图标，并沿用工具箱的深青色背景、浅绿色调和方形卡片。按用户要求，三个入口统一缩小到最高 270px；常用窗口宽度下并排，窄窗口自动换行。选择后捕捉 `MDPro3.exe`，支持多进程选择和重试；只开放智能化识别，不提供编辑器卡组识别。YGOPro、YGOPRO2 和手动流程保留。

在房间内启动一次识别，再正常准备、猜拳和选择先后攻。正式先攻、完整构筑、TAG 和初始手牌全部校验通过后自动进入方案页，调用现有方案匹配及模块化计算。后攻只保存起手，沿用后攻展开暂未支持的提示。每局结束关闭旧工作区，同一连接继续等待下一局；取消、连接切换和进程关闭使旧任务失效。

## 支持构建

仅支持以下四个 SHA-256 同时匹配的 Windows x64 构建。MDPro3 使用 IL2CPP，不能沿用 YGOPRO2 的 Mono 对象地址。

| 文件 | SHA-256 |
| --- | --- |
| `MDPro3.exe` | `73f8a589192da5833a637f87da1fde95b63591e0e3109c482f1be9df84a3001a` |
| `GameAssembly.dll` | `9807f77924e30d216a5700474e6263e23705d4ecc6772c7657d720d1ce0ae8a9` |
| `UnityPlayer.dll` | `40e6f3bf23ba46e8db03b75a307f87f2008601719d4e12bbabd4453f0243812e` |
| `MDPro3_Data/il2cpp_data/Metadata/global-metadata.dat` | `f3b9acf0d253674edb97e7a1968386486deb772c03d93469ade57cd291b76056` |

其他构建显示未适配。BO3、双打、换副、观战、录像和残局模式不在支持范围。初始手牌必须在第 0 回合捕获；中途进入不会拿当前手牌代替起手。卡号须存在于工具箱本地资料库，并满足现有智能识别的构筑限制。

## 只读来源与一致性

实现见 [`mdpro3_capture.py`](../src/trainer/mdpro3_capture.py)。参考 [MDPro3 上游源码](https://code.moenext.com/sherry_chaos/MDPro3/-/tree/228e4ae652d23cb0e6e466a35e2281ce9b1d630a/Assets/Scripts/MDPro3)，并通过上述本机构建的元数据及实际采样核对字段布局。开发时使用 [Il2CppDumper](https://github.com/Perfare/Il2CppDumper) 离线查看元数据；该工具和研究材料不随应用发布。

仅读取进程，不注入、不调用目标函数、不写入内存、不操作游戏窗口、不发送网络消息，也不读取卡组文件。每次采样重新解析 `GameAssembly.dll` 基址并核对进程路径、创建身份。类型名称及命名空间必须匹配；指针、数组容量、列表版本、消息长度和字段值均有边界检查，所有使用的数据在采样结束时再次核对。

| 数据 | 本构建已核对的来源及限制 |
| --- | --- |
| 完整构筑 | `TcpHelper.deck` 的 `Main/Extra/Side`，在提交构筑时赋值；不是编辑器选择或剩余牌库 |
| 正式开局 | `OcgCore.allPackages` 中已处理的 `GameMessage.Start`；通过待处理 `packages` 数量与队首引用确认处理边界，排除预加载阶段 |
| 先后攻 | `Start` 玩家字节与 `OcgCore.playerType/isFirst` 一致，且正式回合号至少为 1 |
| 开局区域 | `Start` 的我方初始牌库／额外数量，与提交构筑和我方场地数量一致；怪兽、魔陷、墓地和除外必须为空 |
| 初始发牌 | 首次 `NewTurn` 前、第 0 回合的我方 `Draw`；在发牌动画中先留存候选，全部手牌按份数匹配后冻结 |
| 我方手牌 | `OcgCore.cards` → `GameCard.p` 的控制者／位置／序号；只读取我方手牌的 `Card.Id` |
| 局次 | 房间／结束边界及本局 `Start` 对象标识；换局后旧构筑、起手、TAG 和计算不能回填 |

对方区域只读取位置以跳过对象；对方发牌只读取玩家与数量头部，不读取对方卡号。MDPro3 的独立猜拳弹窗尚未映射为细分提示，界面在正式开局前显示等待；这不影响正式先后攻校验。

## 本地验收

真实联调使用 `desktop/ygopro-smart-live.cjs`，设置 `YGO_SMART_PLATFORM=mdpro3` 与独立 `YGO_TEST_RUN`。工具箱在后台隔离实例运行，所有游戏操作由用户完成。个人构筑、手牌、截图、时间线和元数据研究材料只保存在被忽略的 `.local/`，不纳入 Git。

2026-09-18 已完成三套不同卡组的真实先攻联调。三个构筑均自动到达方案页，冻结 5 张起手，用户逐轮明确确认与游戏画面完全一致。全程保持同一连接与订阅，没有为第二、第三轮重新点击智能识别；构筑、TAG、起手、局次及工作区随换局更新，前局工作区关闭。

| 轮次 | 主／额外／副 | 先后攻 | 初始手牌 | 人工核对 |
| --- | --- | --- | --- | --- |
| 第一套 | 40 / 15 / 15 | 先攻 | 5 张，保留重复份数 | 一致 |
| 第二套 | 44 / 15 / 0 | 先攻 | 5 张 | 一致 |
| 第三套 | 48 / 15 / 3 | 先攻 | 5 张，保留重复份数 | 完全一致 |

上述隔离资料库没有匹配的模块化来源，方案页正确提示来源缺失；这些结果不代表生成了展开路线。后攻、真实进程重启和异常模式未进行 MDPro3 真人联调。合成内存测试覆盖完整发牌、重复卡、先后攻、预加载旧状态、重连、异常布局、进程身份变化、未适配构建和不读取对方牌号；合成测试不替代真实对局。
