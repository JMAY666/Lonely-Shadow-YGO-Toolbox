# 本局临时方案 · 1.25.0

MDPRO3 1.44.0 [实时跟随](mdpro3-live-follow.md)是下述“前进即确认”的例外：跟随教程中的箭头与节点点击只用于浏览；自动完成证据或明确的“手动确认当前待执行步骤”才更新 `plan-confirm` 和操作历史。其他原有流程的确认方式保留。

## 操作流程

1. 在决斗页确认构筑与起手，可用来源齐备后自动在后台准备四种偏好。点击「生成临时方案」打开已有任务及结果；来源、偏好、目标和精确匹配在同一页面调整。
2. 采用候选后进入步骤图。前进一步或点击相邻下一节点，表示当前操作已经照做。浏览旧节点不撤销确认；不能跳过未确认步骤。
3. 随机获得卡牌或随机堆墓后，选择实际卡牌，可重复添加。遇到阻抗，选择对应步骤，填写对方发动的手牌阻抗及实际支付的手牌费用。
4. 后台根据填报重放。确认的前缀保留，旧后续被替换，优先采用当前偏好排在首位的新后续。没有后续时保留已确认部分，显示待生成；可调整来源后重试。
5. 结束本局、改换起手或重新开始会释放该局后台推演。临时方案不自动成为正式方案，也不进入展开草稿列表；关闭应用后不恢复临时教程。

在教程和方案选择页之间浏览时保留原教程进度。返回方案选择页时，会为本局起手另行准备结果；点击「生成临时方案」打开该起点的候选，原教程和已确认进度保留。只有明确采用新候选才替换当前教程；来源、偏好、精确设置与目标保留。在临时教程中点击「重新生成后续」则从已确认操作后的局面计算，保留已确认前缀。方案选择页不会显示已推进教程的续接面板。

生成面板右上角的箭头可以反复收起、展开；收起期间继续计算，候选、设置和进度保留。临时步骤使用与原日志相同的卡图、箭头、素材组合、场地位置小图及区域流向，文字细节和来源放入可展开的详情。图示以推演前后状态和引擎素材记录为依据，不根据效果文本猜测结果。

普通教程也支持续算：选择已完成的 Step（例如 Step 9），点击「生成展开后续」。后台先将本局起手按冻结来源的决策重放至该步骤之后的我方决策边界，采用候选后保留前缀步骤与批注。旧记录缺少决策、前缀存在未确认随机结果、对手响应不明确或本局资源不足时拒绝近似续算并保留原教程。点击此按钮表示按该来源前缀继续推演，并不表示软件识别了实战。

标准连接召唤的条件、目标、操作回调在脚本更新中整体移动行号时，只要召唤类型、所属卡牌、标识和其余属性一致，可将来源素材选择重绑到当前合法窗口；素材、卡牌效果、不同分支和实际结算仍逐项校验。其余效果仍严格匹配；同一效果属性下无法适配的脚本行号变化会提示重新记录来源，不把未验证当作没有合法路线。来源原文件不改写。卡牌已经进入手牌而来源要求从卡组选取时，仍按当前卡组剩余数量检查。

## 终场、排序与缓存

临时终场只使用所选来源中明确勾选的 `annotations.final_marks`，按卡号、归属、区域和对应份数映射到本局实例；精确模式另外要求场地位置一致。备注与标记效果一起保留。未标记的场上、墓地、除外区、手牌不自动列为有效终场；无标记、部分标记缺失和随机结果未定均明确提示。实际局面快照仍保留全部卡牌供步骤复核。搜索在已结算的我方决策边界检查这些标记目标，不再要求复制来源中未标记的整片场面；路径可以由其他来源的合法决策组成。一个操作路线同时满足多组标记时合并展示，保留匹配标记更多的一组及满足的来源，位置差异不会在自适应模式中冒充新路线。

临时路线支持步骤最少、终场最大、平均值（均衡）及原有稳妥优先。临时路线的步数按非自动规则决策计数；终场大小只按匹配到的标记卡牌数、标记效果数比较，当前无效卡牌不计分。平均值为步骤得分和终场排名得分各占 50%；未确认标记效果不等于已经验证的阻抗次数。普通方案收藏与排序见[决斗辅助](duel.md#方案排序与收藏)。

缓存仅存在本次应用进程内，总量最多 48 MiB / 1,200 项，结束本局即释放。相同局面、来源版本、目标和精确设置下，后台共享完整候选池的搜索与评价，在截取展示数量前分别准备四种偏好。单个后台任务保存本轮部分结果供切换和回看，但仍标明搜索未完成，不把它写入已完成搜索缓存。点击重新生成继续搜索并复用已验证路径。后台任务单线程，最多保留 4 个活动任务，每个偏好结果集合限制 16 MiB，超过容量明确失败并提供重试，不静默截短搜索。新增来源、确认推进或实际填报后的搜索可以复用相同重放路径的步骤校验，仅缺失的校验再调用引擎。本轮节点预算按新增引擎校验计数，已验证的相同路径不重复消耗该预算；总时长、深度和候选容量仍有限制。缓存键包含会话、引擎状态版本、规则资源、完整有序路径、实际填报及干扰场景；不同随机结果、来源版本和本局状态不会复用旧候选。失败与超时不写入步骤缓存；新路径仍由原规则核心重放验证，不保存可执行引擎内存快照。界面显示耗时及缓存命中情况，首次计算仍受来源规模和搜索预算影响。界面明确显示搜索未完成、当前仅一条可比较路线、原路线缺少的卡牌区域，以及当前推荐对应的偏好。多个偏好可以在同一路线同时占优时得到相同结果。

## 状态与边界

「已确认」指用户确认照做或填报了实际结果，软件没有识别外部对局。尚未完成的步骤与终场是推演。确认只推进独立的本局模型，不向真实展开提交输入，不伪造实战操作日志。

随机结果在用户填报前隐藏具体身份。填报仅调整一次性重放副本中现有牌组实例的顺序，并要求实际处理结果与所填卡牌的区域、份数一致；效果、费用、触发、通常召唤次数与限制仍由原规则核心处理。不能把库中不存在、剩余份数不足或当前步骤没有发生的抽牌／堆墓当成事实。

阻抗根据用户报告的卡片，在该步骤的重放副本中由规则核心处理，要求确实产生针对当前操作的无效或移除事件。当前入口支持手牌发动及可完成复核的选择；复杂目标、额外费用、盖放卡、持续限制等不能仅凭卡名完整表达时会拒绝近似续算并保留原进度。新的随机结果和额外对手响应仍需继续填报。来源不足和搜索达到预算不等同于规则上无解。

每项计算保留构筑、引擎、脚本和来源版本；改换构筑、起手、来源、规则、目标或搜索设置后旧候选不能采用；采用前再次核对本局与版本。单纯切换四种偏好复用同一有效状态的结果。低层选择归入对应的召唤／效果步骤，但原始决策顺序仍用于重放。此前已确认前缀可以回看；重算前缀之前的更早历史暂不提供再次改写入口。

## 实现与检查入口

`/api/modular/dispatch` 的 `duel` 调用方使用 `plan`、`plan-adopt`、`plan-confirm`、`plan-observe` 与 `plan-close`。后台实例带 `purpose=duel_planning`，原生窗口始终隐藏，不覆盖展开场地，不保存用户窗口设置。退出时回收自身进程；原始资源、卡组、正式方案与其他展开保留。

来源续接按轮次检查，先尝试各原路线，再探索混合路径。规则核心额外开放且只有“放弃响应”一个合法选择的空窗口可以自动确认，不跳过任何仍有选择的效果、费用或目标窗口。临时方案按终场标记比较，不执行未参与该排序的未来对手回合测试。四项偏好为花费最少、终场最大、步骤最少、平均，默认终场最大；花费优先比较手牌，再比较主卡组与额外卡组合计，平均由资源、终场、步骤三项标准化评分等权计算。限定灰流丽场景的证据仍保留，但不再是独立排序选项。

自适应模式中，本局起点若在抽卡／准备阶段的我方响应窗口，而来源从同回合主要阶段开始，会用来源已记录的“放弃响应”决策在隔离引擎中进入主要阶段，再从原路线首个动作校验，不将其误接为路线中途的响应。存在可选发动时保留这次放弃响应为明确决策，不当作无选择的自动确认；精确模式、连锁处理中、对方回合和无合法放弃选项的窗口不使用此适配。

同一个发动动作在“选择连锁”与“是否发动效果”两种窗口之间切换时，自适应模式要求卡牌、完整效果标识和上下文一致，且当前合法选项唯一，才重绑对应的肯定选择；效果文本相同、资料缺失或多个选项无法区分时不近似匹配。精确模式仍保留原窗口约束，每次重绑仍由规则引擎复核。

原生位置同步合并过期的等待请求，最多保留当前发送与最新等待布局，避免滚动后长时间重放旧坐标。独立模块化页面与展开继续使用原场地。

- `npm test`：基础逻辑、状态保护与布局请求合并。
- `npm run test:modular -- --suite=pipeline`：后台生成、折叠恢复、偏好切换命中缓存、收藏持久化与筛选、普通 Step 续算、仅标记终场、图示、确认与回看、无实战输入、错误填报保留原进度、结束释放。
- `npm run test:modular -- --suite=planning`：同一起手下三条有真实取舍的路线分别验证最少、最大、均衡推荐；确认切换偏好重新计算、手动生成绕过候选结果，且不提交实战输入。
- `npm run test:modular -- --suite=forecast`：原生录制抽牌／堆墓来源，用户填写具体结果后重新生成后续，以及报告灰流丽后改走通常召唤路线。
- 对应发布包使用 `npm run test:modular:packaged -- --suite=pipeline` 与 `--suite=forecast`。
- `npm run test:desktop` / `npm run test:packaged`：原有桌面流程回归。

验收实例使用隔离测试数据和内部接口，不使用全局鼠标或按键。测试数据、截图与成品包保留本地，不纳入 Git。
