# 卡组知识包：实施范围与数据契约

1.42.0 提供主程序内独立的「知识包」工作区：已安装内容与可编辑的制作项目分开管理。本功能独立于已停止并封存的 AI 学习计划，不启动模型训练或旧实验。验证范围见文末，已加载资料不等于模型学会或路线可执行。

## 使用流程

1. 打开左侧「知识包」→「制作项目」，新建项目、打开可编辑导出文件，或创建内置烙印示例。项目信息中填写主题、环境和最低应用版本。
2. 在「导入来源」复制已保存构筑、正式展开及其分支，或保留一份原始文本/JSON/YDK 附件。导入操作不修改原有资料。原始文件保存文本及原字节；正式方案按现有分享白名单复制，不携带本机进程、路径或原生控制文件。
3. 按类型新增/编辑记录。构筑分主、额外、副卡；副卡未披露可保持未知。可检索卡名/卡号加入卡牌。展开选择有序步骤，妥协选择实际步骤锚点和所属路线；来源、终场和对策通过引用关联。引用的反向导航由程序计算，不需要建立循环依赖。
4. 保存后查看结构问题、受影响条目与可复用条目。结构检查、人工核对各自保存记录。「查找重复」只列候选，不覆盖或自动合并人工内容。删除为逻辑移除，旧内容与修订快照保留；仍被引用的已移除条目会阻止发布。
5. 需要规则验证时，在「规则验证与任务」明确选择原始决策路线、构筑、每组已确认起手、场景和预算。未提供原始决策证据的教程不会开放此能力。结果、未知原因、进度、取消和恢复入口均在同处显示。
6. 填写新的三段版本号，例如 `1.0.0`，点击「发布并下载」，确认随包包含的原始资料范围。导出完整 `.知识包.json`，也可单独导出可编辑项目。发布后继续维护同一项目，无需重采所有资料。
7. 在「已安装」选择文件，检查内容、依赖和兼容情况后安装；默认不启用。启用后，构筑浏览、展开管理、情报站分别显示来自该包的内容，点击可回到相应记录及关联条目。
8. 需要计算时另行允许「已验证路线参与计算」。这个许可仍不能替代本机验证、实际构筑/起手/资源检查及原有对局操作权限。安装和启用资料本身不开始对局、不自动出牌。

现有 TAG 编号用于分类与筛选，改名不改变内容身份。未解析的外来 TAG 仍保留编号，作者或个人副本可选择当前本地 TAG；不会按同名标签静默改写个人词表。不同包的相似内容并列保留来源，不自动去重。

## 版本与个人修改

同一版本同一摘要重复安装不会增加记录；同一版本不同内容拒绝替换。不同内容必须发布新版本。首版使用完整文件，不做差分下载。

「编辑个人副本」把本地改动与原文分开保存。更新时比较原文、本地修改、新版；独立变化合并，同字段冲突逐条选择保留本地或采用新版，未解决前旧版继续可用。选择采用新版冲突字段不会丢弃其它个人修改。

查看版本与启用版本分开；选择已安装旧版可以回退。已经采用的教程/计算场景固定原始来源快照，更新后不会中途换步骤，旧版本不会再提供给新场景。停用会撤销该包待使用的计算指令；原教程快照、个人批注和历史记录仍保留。卸载后仍可查看保留的历史资料；首版不自动回收这些版本文件。

## 数据与存储边界

安装文件封装为 `ygo-deck-knowledge-bundle` schema 1，内含 `document` 与完整内容摘要。`document` 的格式是 `ygo-deck-knowledge` schema 1，包含包元数据、记录、引用及验证证据。摘要检测内容变化，不是作者签名。记录种类：来源、构筑、路线、步骤、共用片段、妥协、终场、对策。所有实体使用稳定 ID、独立修订；名称、TAG 和显示顺序不承担身份。

制作项目保留原始导入资料与修订快照。运行数据只存于应用 `_trainer/knowledge/`；开发材料、模型调用记录和验收证据存于忽略的 `.local/`。既有个人构筑、方案、TAG、批注、收藏和对局记录不迁移、不覆盖。发布前预览所有包含的来源；未随包附带的原始资料不能宣称已携带。

已安装版本不可变。新版本和索引完成后才切换原子注册表；失败时原指针不变。个人覆盖保留原文与修改，升级做三方比较；未解决冲突阻止切换，旧版可用。停用和卸载不删除个人覆盖与必要历史快照。同一版本不同摘要拒绝替换。

依赖关系只表达输入，不以循环引用制造双向链接；页面反向导航由索引生成。验证绑定完整传递依赖的语义摘要。标题、TAG 分类和专门的「整理备注」不改变规则语义；使用说明、费用、限制、普通备注可能包含实际前提，保守参与失效判断。未知字段同样参与摘要。缺失、删除及语义变化使依赖结论失效；原验证历史保留。

文字教程、结构化策略和原生决策证据分别保存。结构通过、人工核对、引擎验证和策略评估分别显示；安装、TAG 命中、作者标记都不能自动授予计算或执行资格。缺少状态或不适配时明确提示。

安装索引按记录内容生成并复用，项目修改会报告依赖影响；完整安装文件仍可重新生成。检查结果与搜索缓存使用输入、场景和环境摘要，不能因包版本号相同而复用失效结果。引擎、卡库、脚本或适配语义变化使对应本机证明失效；共用脚本无法精确缩小影响时按整个规则环境保守重验，并显示原因。

## 规则验证和消费边界

- 正式记录中的原生决策、快照、费用/对象/素材及实际结果通过既有分享校验和模块化格式校验进入适配器。仅勾选「原始决策记录」或填写步骤无效。
- 制作步骤与原始决策绑定。规则相关内容或依赖改变后，原始对应关系进入待核对，不能拿旧动作验证新文字；需要重新录制或导入对应的正式证据。标题及单独的整理备注可继续编辑。
- 本机规则验证只使用指定构筑与已确认起手、所选原始记录的动作及既有必要响应，当前提供「无额外干扰」与已有的「灰流丽」场景。每个任务最多 8 个场景；每场搜索最多 32 秒、320 次节点预算、128 层决策。另有引擎启动上限 30 秒、单次原生探测上限 4 秒及关闭等待，不把这些耗时伪装成搜索进度。
- 深度不会为迁就来源自动扩大，验证任务不额外运行用户未请求的干扰评价。预算内未确认终场记录为未知，不证明规则上无解。
- 取消后不发布迟到结果；恢复以已完成场景为检查点，重新建立被中断场景的隔离引擎。应用重启后任务暂停，不自动恢复。输入改变时拒绝继续旧任务。已通过且依赖/场景/环境完全相同的证明可以复用。
- 本机通过记录是特定场景中原始决策的可行证据，不证明文字解释正确、所有妥协分支已验证或策略最优。由别人制作的包内引擎记录仍是来源声明，本机计算资格单独核对。
- 允许计算后，完整、仍有效的原生来源进入现有 `ModularLibrary` 和展开匹配；TAG 后仍核对具体资源和起手，候选及下一步继续通过隔离规则核心。验证实例拒绝真实执行与自动打牌，不能被当作对局教程接管。
- 终场保存卡牌、区域/资源说明、效果资料及共享费用、互斥/次数约束。效果资料可用高级结构编辑；当前不提供通用的「总阻抗数」或最优终场评分，不能把效果条目相加当作次数。

结构化文本教程可以浏览、筛选和关联，不会自动编译成引擎操作。当前记录引用限包内；不加载跨包可执行代码、模型或卡牌脚本。应用兼容检查与本机规则指纹不等于 OCG/MD 当期禁限合法性检查。

## 样例与容量

内置烙印示例重组已有 2026-09-20 核对的公开资料：两套 8/9 月 MD 构筑、两条展开、一条条件妥协、一份对策，以及必要终场和来源。原始资料快照保留；妥协中的后续说明属于条件资料，尚未录制完整原生分支，示例整体不宣称逐条引擎通过或符合当前禁限。

项目/包文档上限 32 MB，原始附件单份上限 8 MB。超限或格式不支持会明确失败，原项目保持可用；不静默截断。不随包携带完整本机原生恢复带，保留的决策资料仍可在本机按上述条件重新检查。

## 验收

单元测试覆盖来源失效、未知副卡、循环与缺失引用、版本保护、修改合并、失败恢复、索引复用及任务取消/恢复竞态；桌面验收使用隐藏 Electron、隔离目录和应用内部接口，不使用系统鼠标或全局按键。

```text
npm test
npm run test:desktop -- --knowledge-only
npm run test:packaged -- --knowledge-only
npm run test:modular -- --suite=knowledge
npm run test:modular:packaged -- --suite=knowledge
```

真实引擎专项使用明确标记的普通召唤测试牌表，验证原生证据导入、本机预算限制、缓存复用、匹配/计算接入和使用中版本固定。它是自由练习规则下的合成验收，不是公开烙印示例的规则验证，也不证明所有卡组或手坑场景可用。最终执行结果见 [1.42.0 验收记录](verification-1.42.0.md)。

## 第三阶段判断

当前安装、编辑、查找与可执行记录接入已经有明确的数据和引擎接口，暂不需要模型训练。实际剩余内容工作是补齐原生记录、适用条件和更多真实场景证明；训练不能替代这些证据。若未来需要优化检索、条件提取或策略排序，应另立目标与留出评测，明确样本和模型产物的区别、推理接口、版本更新成本及资源预算；本版本没有恢复封存计划。
