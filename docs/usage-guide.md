# 使用与开发手册

[← 返回项目主页](../README.md)

以下保留当前版本的完整功能、操作、构建、迁移与验收说明。命令均在仓库根目录执行。

本地游戏王工具箱，提供独立卡组编辑、展开前置设计、练习记录、逐步回看、方案管理与 BO1 先攻决斗辅助。

基于精简后的 YGOPro 工作副本，提供“选择已有卡组 → 只读预览与确认 → 展开前置设计 → 展开场地 → 当前展开方案调整 → 保存前二次确认 → 展开管理”。Electron 桌面版复用现有 HTML/CSS/JavaScript 界面、Python 服务、YDK/JSONL 数据格式与原生引擎，不写入原始 YGO 安装目录。

本仓库公开源码、适配补丁、依赖锁定文件、测试与文档。Windows 成品包、卡牌数据库、卡图、效果脚本和个人数据保留在本地，不随 Git 发布；从源码运行时需按下方说明准备运行资源。

## Windows 桌面版

### 1.15.1 · 起手排布、教程聚焦与统一快捷键

本次修正：起手槽与标题居中，候选卡组限宽并按类型、等级和卡号排序；鼠标点选与快捷键统一聚焦教程步骤；悬停使用固定延迟并清理过期计时器，移入详情可持续阅读。快捷键独立成窗，教程页与全局设置内的入口共用同一套配置，软件内外即时生效；起手张数单独保存。

- **代表卡**：卡组编辑中的「代表卡设置」提供三个展示位，从当前主／额外／副卡组选择；应用后随「保存构筑」保存。卡组管理、展开选卡与决斗选卡共用紧凑的卡组盒子和扇形代表卡。Tag 与详细卡组信息移到悬浮预览，盒子外只保留名称。旧卡组默认三个空位，沿用原构筑；保存时只增加兼容 YDK 的展示注释。
- **决斗导航**：顶部紧凑步骤栏直接跳转已到达阶段；卡组选择包含「选择卡组／卡牌预览」两步。模式与先后攻使用居中放大的正方形按钮；按钮内部以同色系卡牌、建场与突破图形区分含义。先手点击后直接进入准备起手。「开始决斗」「方案选择」与教程操作悬浮在视口右下角，不占整条底栏。
- **起手录入**：在卡牌悬浮详情中标记候选，主卡组中的标记通过加强边框显示。点击卡图加入起手，点击槽位选择替换位置，右键槽位移除该张卡；右键候选退回最近选择的同名卡。右上角显示剩余份数，用尽后为 0 并灰显。默认五张，起手张数移到顶部齿轮「全局设置」，修改用于尚未准备起手的流程及后续对局。
- **方案预览**：列表使用起手与终场卡图，备注紧随名称；悬浮窗内切换简略／详细。简略终场标明怪兽区、魔陷区、场地区、手牌、墓地等区域，详细一图流保留具体场上位置与本次可用分支。
- **展开教程**：上方步骤复用展开日志的简略卡图动作，悬停显示对应步骤的详细记录；下方显示该步骤的真实快照棋盘，并可查看墓地、卡组、素材和卡牌详情。两区之间的分隔线可拖动调整教程图高度，步骤先自动加宽并排列操作，再按可用高度缩放；保留完整内容与横向路线滚动。分隔线也支持方向键调整、Home／End 和双击恢复。鼠标点选与快捷键共用一个当前步骤，原方案、原始事件和展开编辑缓冲区保持原有归属。
- **统一快捷键**：教程页与全局设置内的「教程快捷键」入口打开同一个设置窗口，软件内外均使用其中的同一组按键，默认 ←／→ 后退／前进、↑／↓ 选择分支，结束默认未绑定。进入教程启用，可统一暂停；按住连续移动，松开停止。切换模块、弹窗编辑、结束和关闭时释放后台绑定；注册冲突显示具体错误。原默认组合键自动更新为方向键，用户自定义配置保留。Windows 长按辅助只读取已配置按键的当前按下状态，不注入输入、不记录文字。相关接口：[Electron globalShortcut](https://www.electronjs.org/docs/latest/api/global-shortcut)、[Windows GetAsyncKeyState](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate)。

BO1 仍使用已保存卡组与正式方案，按 Tag ID、主／额外资源和实际起手条件筛选。每条妥协分支单独核对资源；不把互斥分支累加。BO3、自动识别、自动决定先后手与后攻突破尚未实现，当前使用手动选择。到达终场仍由用户点击「展开结束」，不自动判定真实对局胜负。

实现与验收边界见 [BO1 决斗说明](duel.md)。后台自动化操作隔离实例，验证实际注册、内部回调、按键重复逻辑及释放。跨软件的真实按键和个人快捷键冲突由用户自行验收。

1.13.0 为卡组编辑加入共用 TAG 标签：名称下显示标签总数及主／副标签摘要，左侧“TAG 设置”支持自动上 TAG、文字搜索、按本卡组卡牌关联、多主标签与多副标签选择。这里仅选择已有标签；标签名称、别名与包含的卡牌仍在“TAG 管理”维护。TAG 管理、展开管理、方案调整与回看、日志、保存确认、妥协分支、对手操作窗口及相关弹窗统一使用深蓝灰背景、浅色文字和浅绿选中状态，保留蓝／红玩家标识及警告区分色。共用颜色变量位于 `src/trainer/web/theme.css`，原有布局和卡图不变。

网页和桌面渲染界面的纵向／横向滚动条统一为细窄圆角样式，轨道透明，不显示原生箭头；悬停与拖动时滑块增强对比。Electron 使用 4px 可见滑块和 8px 拖动区域，卡组、TAG 管理、回看、日志、弹窗及对手窗口共用 `src/trainer/web/scrollbars.css`；滚轮、键盘与拖动滚动继续可用。

1.12.1 将展开的第一步改为独立“选择卡组”页：仅列出已有卡组，点击直接进入只读预览，主／额外／副卡组占满内容宽度。悬停卡图查看详情，点击固定浮层，支持移入阅读、Esc／关闭按钮收起；不再占用左侧详情栏。预览浮层、候选按钮与起手选择弹窗使用深蓝灰背景、浅色文字和绿色强调。右上角“确认卡组，下一步”进入前置设计。选择和预览页不提供新建、导入、改名、删除、排序、保存、收藏、增减卡牌或卡牌库。返回列表可重新选择；预览期间源卡组发生修改时，先刷新预览并清空旧标记，再次确认后继续。读取失败保留返回与重试入口。

在详情浮层中点击“添加标记／取消标记”保留候选，已标记卡牌使用绿色边框强调，取消后恢复；卡图上不覆盖复选框或标记控件。标记的主卡组卡牌带到下一步“已标记卡牌”，填写方案名称后可点击候选填入下一个空起手槽位，也可拖到指定槽位放置或替换；打开某个槽位时仍有快捷候选。拖动中显示卡图跟随和目标槽位提示，移到窗口边缘可滚动，Esc 可取消。同名候选合并，点击和拖放均校验实际份数、禁用条件和槽位数量，不自动指定起手。额外与副卡组的标记仅用于复制卡名。浮层可复制单个卡名，预览和前置设计可复制标记卡名；同名合并，以 ` + ` 分隔，方便粘贴到方案名称，复制不会自动改写名称。标记与候选仅保留在本次界面状态，不写入源卡组或方案记录。

### 模块入口与状态

- **首页**：仅提供卡组编辑、展开的快捷入口，点击后同步选中左侧导航。
- **卡组编辑**：独立完成新建、打开、导入、保存、删除、搜索、详情、三个分区编辑、排序与撤销；没有“方案前置设计”等后续流程入口。
- **展开**：内部流程导航为选择卡组、展开前置设计、展开场地、方案调整与保存、妥协场构建前置、展开管理，以及回看和方案导入导出。选择已有卡组并在预览页确认后进入前置设计；进行中的展开会禁用预览页的下一步。
- **决斗**：使用已有卡组与已保存方案，录入实际起手，筛选主线与合格妥协分支，手动导航教程至展开结束。
- **TAG 管理**：统一从主栏目最下方进入，集中维护名称、别名和卡牌范围。“展开”内不再显示 TAG 管理入口或名称／别名编辑弹窗；方案自身的添加标签、主标签选择和自动分类继续保留。
- 独立卡组编辑与展开选择共用 `_trainer/decks/` 卡组库。预览只读取已保存卡组，保留原顺序和份数；不会替换独立编辑中的未保存内容、撤销记录或搜索状态，也不会写入源卡组。前置设计中的临时玩家／对手卡组编辑继续使用单独缓冲，原有应用与取消行为保留。
- 切换模块保留卡组预览、前置设计、临时玩家／对手卡组编辑、草稿和 TAG 修改；正在进行的展开继续记录，原生场地随模块隐藏或恢复。编辑器中返回卡组管理或打开其他构筑、新建、导入等会替换当前编辑内容的操作提供保存／放弃／取消选择。退出提示覆盖独立编辑与前置设计临时编辑。
- 已开始展开与已保存方案继续使用各自的冻结快照；源卡组的新修改不会追溯覆盖。左侧主导航、三栏卡组编辑器及日志浮层各有可用空间；收起／展开导航及窗口缩放时，原生场地按实际内容区域重新定位。
- 更名不改变默认数据目录、应用标识、数据格式或迁移规则，无需搬动旧数据。`%LOCALAPPDATA%\YGOTrainer`、开发目录和自定义 `--data-dir` 均继续使用。

### 已有展开能力

1.10.0 将方案回看的时间轴移到场面上方，支持抽屉收起。路线图显示主线、具体分叉步骤与妥协分支，点击路线直接切换，悬停或键盘聚焦可查看分支时点、预设条件和实际干扰。右键步骤创建分支的操作继续保留；调整页不显示资源统计，资源核对保留在保存确认与展开管理。

「转生炎兽 烽火猞猁」的墓地除外，在原记录明确带有自身代替破坏效果来源时显示“适用② · 代替破坏”。简略日志把同一步中的我方发动、对方响应（例如无限泡影）和无效结果连在一起，保留双方费用、对象、备注及记录依据。已明确被无效的效果不再同时提示“处理结果未记录”；泡影这种延后出现的无效事件，按实际对象与相邻结算记录连接并注明依据；没有可靠关联的记录仍独立显示。以上均为只读展示，旧方案与原始记录不改写。

展开管理采用文件夹浏览：点击系列文件夹进入、通过路径或上一级返回，搜索支持方案名称、标签别名以及主线／妥协路线实际使用的我方卡片名称和准确编号，不把构筑中未使用的卡牌或对手卡牌计入卡片搜索。一图流仅主线保留起手条件，箭头连接的分支区显示终场；确认操作使用绿色按钮，删除／放弃使用红色按钮。

1.9.1 将创建妥协分支集成到时间轴节点的右键弹窗中，取消列表底部的独立创建区域。右键目标步骤，即可在附近选择分支时点并创建；支持 Shift+F10、Esc、点击外部关闭和窗口边缘避让。右键其他步骤会同步回看对应场面；无可恢复时点、正在展开或位于妥协分支内部时，弹窗说明禁用原因。分支的规则恢复、条件、记录和保存方式不变。

1.9.0 新增“妥协场构建”：完成主线后，在“展开方案调整与保存”的时间轴右键目标步骤，在弹窗选择明确的恢复时点，创建同一方案内的妥协分支，再进入“妥协场构建前置”配置对手场景手牌。主线上可以创建多个独立分支，本次不支持分支内嵌套子分支。没有有效分支时，前置入口保持可见且禁用。

新记录保留完整引擎重放所需的调用、输入与随机起点。进入分支时先独立重建并校验原始对局，再构造场景手牌和合法选择窗口；代价、效果次数限制、双方区域、LP、阶段与连锁由规则引擎继续处理。旧方案缺少重放记录、引擎／卡牌／效果脚本版本改变，或场景会改变分支点之前的实际结果时，明确拒绝恢复，原方案仍可回看。不会用截图或近似场面代替可运行的对局状态。

妥协场的对手窗口与主窗口连接同一场对局。进入时先接管对手，暂停 AI；可多次“接管对手”和“交还 AI 托管”。关闭对手窗口会先交还托管，不结束对局。没有可发动卡牌的空响应窗口自动通过；存在合法选择时由当前控制方决定。对手使用原有基础 AI 决策，复杂到超出其策略范围的选择会保留并交回手动处理。

预设手牌与实际干扰分别显示。只有实际连锁记录支持时才展示“灰流丽 → 贪欲之壶：效果被无效”等结论；未知影响保留事件，允许用户补充关联和说明。分支终场、动作、前提和说明随主线一起经过二次确认保存，不另建独立方案。打开管理与回看默认主线；点击顶部路线图切换路线，展开管理中的“统计包含当前分支的新增资源”独立控制统计，按主线与当前一个分支的资源份数取较大值，对手手牌单独展示。一图流默认只有主线，可选择加入哪些妥协分支，以虚线区域和连接具体步骤／响应点的箭头区分；分享文件也保留分支的冻结展示内容，但不携带本机引擎重放文件。

恢复边界、数据文件与验收说明见 [妥协场实施说明](compromise-design.md)。

1.8.0 在“展开管理”后新增独立“TAG 管理”页面，可新增标签、改名、编辑别名、搜索并增删包含的卡牌。默认按系列编号收录，人工增删覆盖默认归属；自动分类使用最新范围，人工分类保留。标签编辑可跨页面保留，保存前也有退出提醒。

卡牌详情支持停留 400 毫秒后悬停预览，短暂划过不打开；移入浮层可继续阅读，点击可固定，Esc 或关闭按钮可收起。超量素材在同一资料浮层内保留上一级上下文，点击或悬停素材查看其详情，可返回原超量怪兽的素材列表。适用于方案回看、日志、终场展示和 TAG 管理里的卡图；不改变场地状态。

1.8.0 为一图流的操作卡牌和终场展示补上与简略日志一致的 30×24 位置图示，预览、PNG 和 SVG 导出均包含。图示按每次记录的场上位置高亮，蓝色表示我方、红色表示对方；缺少位置记录时不猜测。图示使用内嵌矢量绘制，离线导出仍完整可见，卡名与备注自动留出空间。

展开管理支持方案分享文件和系列标签分类。卡片本身的发动与卡片效果的发动分别显示，例如“发动场地魔法卡－转生炎兽的圣域”。卡片发动已完成但没有额外动作时，简略日志和一图流不再显示“处理结果未记录”；未确认结算、被无效或无法确定发动类型的记录仍保留状态提示。已有正式方案通过只读展示兼容，不改写其冻结动作。

### 开发与打包

开发需要 Node.js 22.12+、npm、Python 3.12+ 和已构建的 `.local/YGOPro-Lite` 工作副本。首次准备需联网下载固定版本的嵌入式 Python/Electron；正常运行不联网下载资源。

```powershell
npm ci
npm run desktop:prepare
npm start

npm test
npm run test:desktop
npm run build:dir
npm run test:packaged
npm run build
```

`desktop:prepare` 校验 Python 归档哈希，按白名单生成 `runtime.zip`，只携带所需资源与干净的默认配置；个人卡组、展开方案、训练记录、旧配置、账号、Bot/WindBot、录像和日志不进入应用包。`build:dir` 生成 `release/1.15.1/win-unpacked/`；`build` 另生成上述 Windows ZIP 包。整个 `release/` 与 `.local/` 均留在本地，不进入 Git。

`test:desktop` / `test:packaged` 使用后台 Electron、内置 Python 和真实原生引擎，以隔离数据目录验证卡组盒子、新建与 YDK 导入、名称与分区编辑、悬停预览、收藏与组合筛选、未保存提示及保存失败恢复、编辑删除、场地嵌入与缩放、效果发动、通常召唤、报告、重启和关闭，并覆盖 1／2／3／5 张起手、双方配置、返回修改、计时和草稿／方案删除。验收同时检查场地没有被重叠的分层窗口覆盖，不能仅以原生截图或鼠标命中成功判断场地可显示。测试通过引擎自己的命中检测和 Irrlicht 事件接口点击，通过渲染驱动捕获场地图像，不使用系统鼠标、全局按键或其他应用窗口。

测试脚本显式启用 `YGO_DESKTOP_TEST=1` 与 `YGO_DESKTOP_BACKGROUND=1`：仅测试实例提供内部输入／截图接口并固定随机种子，日志开始行标记 `test_control: true`。正常启动不启用这些接口，继续使用随机起手。一图流验收还覆盖真实保存方案的 PNG／SVG 下载、各环节卡图嵌入、多张素材换行、节点与卡图环节的文字边界、导出失败恢复、键盘跳转原步骤及冻结方案保持不变；终场摘要回归检查完整效果原文、位置与备注，并核对简略模式保持原有显示。

验收另外覆盖首页跳转、独立编辑与前置设计临时编辑隔离、展开选卡与只读预览、源卡组更新后的再次确认、展开中的模块切换、窄窗口与左侧导航边界，以及品牌资源和升级数据读取。预览页检查 900／1100／1600 像素下卡牌区占满宽度、滚动与右上角下一步的位置；右键、双击、撤销快捷键和拖入文件不会改动预览卡组或打开导入。还验证详情悬停／固定、浮层标记、下一步及槽位弹窗中的快捷候选、拖放与份数校验，以及卡名复制失败重试；剪贴板验收通过隔离写入替身完成，不覆盖用户的系统剪贴板。`npm run test:desktop -- --selection-only` / `npm run test:packaged -- --selection-only` 可单独检查最终选卡流程、深色浮层及按钮文字对比度。合并标题栏的检查覆盖启动页拖动区域、900／1280／1600 像素宽度、125% 页面缩放、滚动固定及系统按钮避让。

保留旧版应用包时，可运行 `npm run test:upgrade -- --legacy-exe "release/1.10.0/win-unpacked/YGOTrainer.exe"`：在隔离的 `LOCALAPPDATA` 下先运行旧版，再运行新版，对比卡组、方案、历史、窗口设置与备份。该测试只读取旧包和自动验收生成的测试方案，不访问生产用户数据。

图标源文件为 `src/trainer/web/brand/app.svg`；修改后运行 `npm run build:icons`，生成供窗口及 EXE 使用的 PNG 与包含 16/24/32/48/64/128/256 像素图层的 ICO。

验收资料保存在 `.local/evidence/electron-development/` 和 `electron-packaged/`，不覆盖生产数据。

### 用户数据与旧数据迁移

打包版默认数据目录为 `%LOCALAPPDATA%\YGOTrainer`，与程序解压目录相互独立。开发版默认使用 `.local/desktop-dev/`；测试使用 `.local/desktop-check-development/` 与 `.local/desktop-check-packaged/`。完整数据目录结构：

```text
YGOTrainer/

    system.conf                    原生配置，后续资源更新不覆盖
    deck/                          迁入的旧副本构筑
    _trainer/decks/                 工具保存的 YDK
    _trainer/card-favorites.json    本地卡牌收藏
    _trainer/backups/               构筑覆盖前备份
    _trainer/sessions/              训练记录，内部格式见下文
    _trainer/plans/                 正式方案快照及删除恢复副本
    _profile/                      原生隔离配置与日志
  migration-backups/<UUID>/         迁移前快照和 SHA-256 清单
  migration.json                   迁移结果、来源、备份位置及校验和
  electron/                        Electron 本地配置与缓存
  window.json                      桌面窗口尺寸
  logs/desktop.log                 启动和服务错误日志
```

`npm start` 在首次运行时自动从 `.local/YGOPro-Lite` 备份并迁移到开发数据目录。打包版本不会携带或自动扫描其他机器上的私人数据；首次迁移当前工作副本时使用：

```powershell
.\release\1.15.1\win-unpacked\Lonely-Shadow-Yu-Gi-Oh-Toolbox.exe --import-from "$PWD\.local\YGOPro-Lite"
```

先正常结束旧版训练并停止旧网页服务；源服务仍占用目录或原生训练存活时拒绝迁移。迁移顺序为：完整清点 → 独立备份 → 核对备份和源文件哈希 → 复制到空目标 → 逐文件核对 → 写入完成标记。旧数据保留原处；中途退出可从验证过的备份继续，不覆盖已经产生新修改的目标文件。已使用的桌面数据目录不会被再次导入覆盖；如需另行迁移，使用 `--data-dir "另一个空目录" --import-from "旧副本目录"`。

## 卡组编辑

- 卡组管理以盒子网格显示已有卡组和自定义名称，已有副本与“我的卡组”有来源标识。悬停或键盘聚焦盒子，在附近查看最近保存的主／额外／副卡组、实际卡图及每种卡的份数。浮层可滚动并限制在窗口内，移出盒子和浮层后关闭；打开盒子不会用未保存编辑替换预览。
- “新建卡组”窗口支持输入名称后创建空白卡组，或导入 `.ydk` 文件、单文件拖放、粘贴完整 YDK 原文（每次最多 32 KB、1000 行）。目前不解析其他平台的卡组码或网页链接。创建后进入未保存编辑，点击“保存构筑”才写入卡组库，取消不生成文件。
- 导入预览显示三个分区的张数、卡名、卡号和同号张数，完整保留分区、重复卡和顺序。未知卡号、无效格式、分区错误、衍生物和数量超限会阻止导入，并保留输入供修改；主卡组不足 40 张可先导入编辑。同名名称明确提示更换，已有卡组不会被自动覆盖。
- 编辑页左栏从上到下为排序／保存／撤销、卡图与名称／属性／效果、收藏和卡牌操作。点击中间或右侧卡图更新详情；选择“操作分区”后每次增加或减少一张，点击中间卡图时自动选中它所在的分区。目标分区不存在该卡时不能减少，分区类型和上限沿用现有校验。
- 返回管理页的“←”内嵌在名称旁，不再单独占一行。中间依次显示可编辑名称、主卡组、额外卡组和副卡组，每张卡保留独立缩略图，标题张数即时更新。卡图按可用宽度换行；三个分区在中栏滚动，卡图不通过无限缩小来塞入窗口。
- 右栏“全部卡牌／已收藏”标签页共用名称搜索和类型、属性、种族、等级／阶级／LINK 筛选，所有条件取交集并在分页前筛选。提供清除名称搜索和重置筛选按钮，无结果时显示提示。双击卡库卡牌仍自动加入主卡组或额外卡组。
- 收藏状态在左栏显示，取消收藏后立即从当前收藏查询中移除；数据保存在 `_trainer/card-favorites.json`，两个编辑工作区共用，重启后保留。写入失败不会提交新的收藏状态，损坏文件不会被静默清空。
- “排序”分别按类型、等级和卡号排列三个分区，只改变顺序。右键卡组卡图可移除所点的一张；“撤销”或非输入框中的 `Ctrl+Z` 撤销最近的加卡、移除或排序，最多保留 50 次卡牌编辑。
- 保存同步写入名称、三个分区及顺序。已有练习室卡组改名保留原文件标识，以兼容 YDK 的 `#name:` 注释保存显示名称；旧文件继续从文件名读取名称。训练引用保持不变；已有训练和正式方案的冻结快照不改写。编辑已有副本构筑仍创建练习室副本，覆盖练习室构筑前自动备份并校验版本。
- 名称下方显示 TAG 数量及主／副标签摘要，点击数量或左侧“TAG 设置”打开选择窗口。支持添加、移除、主副转换及多个主 TAG／副 TAG，总计最多 30 个；同一 TAG 不重复。可按正名、别名、关联卡名或准确卡号查找，也可从本卡组的主／额外／副卡组点选卡牌（多选取并集），再与文字搜索取交集。仅选择已有标签，不在此处新增、改名或修改标签卡牌范围。
- “自动上 TAG”以主卡组＋额外卡组的实际张数为分母，同卡多张分别计数，副卡组不计入浓度。关联卡牌最多的 TAG 为唯一主 TAG；其余至少 2 张且占比达到 5% 的为副 TAG，同浓度优先更具体的子系列，再按名称稳定排序。候选显示张数、占比与依据卡牌；没有关联时留空。结果替换窗口内选择，仍可手动调整、取消或应用，不在后台改写卡组。
- 点击“应用到卡组”只更新当前未保存编辑，再点“保存构筑”持久保存。取消／Esc 放弃本次窗口选择，切换模块保留已应用的未保存编辑，保存失败保留选择；清空后保存会持续保持无标签。卡组标签通过 `#trainer-tags:` YDK 注释与卡牌一次原子保存，共用版本校验、改名、覆盖备份及删除恢复机制，旧 YDK 默认无标签、读取不改写文件。卡组与方案共用同一标签库但各自保存选择，既有方案冻结内容和自动分类规则不变。复制／导出标准 YDK 仍只包含名称与卡牌；卡组标签是本工具本地元数据，外部 YDK 导入不自动携带它。
- 返回管理页或打开另一卡组时，未保存修改提供“保存后离开／放弃修改／取消离开”。保存失败保留编辑内容；单纯切换模块继续保留各自工作区。桌面最小窗口 900×650 保持三栏与独立滚动；更窄的网页视口可横向滚动编辑区域。
- 在卡组管理页右键盒子，或点击右上角“···”，可选择“打开编辑／改名／复制 YDK 代码／导出 YDK 文件／删除”。改名只更新名称注释，保留文件标识、卡牌顺序、原有注释与三个分区；同名冲突或写入失败保留输入。选择“删除”并确认后删除；删除前校验版本，在 `_trainer/backups/deleted/<UUID>/` 保留 YDK 与元数据，训练报告及冻结快照保留。正在训练的构筑禁止删除。恢复时退出应用，将备份 `deck.ydk` 按元数据 `id` 中的相对路径复制回 `decks/` 或 `deck/`，不要覆盖同名新文件。
- “复制 YDK 代码”将最近保存的完整 YDK 文本写入剪贴板；“导出 YDK 文件”生成以卡组名称命名的 `.ydk` 文件。两者均保留主／额外／副卡组、顺序和重复张数，不混入未保存编辑，也不改动源卡组。桌面复制通过仅供主窗口使用的接口完成，不读取剪贴板或开放通用系统权限。复制失败有明确反馈；网页模式使用浏览器剪贴板权限，也可以改用文件导出。自动验收以隔离写入替身检查剪贴板链路，不覆盖用户当前系统剪贴板。

界面沿用自由练习规则：主卡组最多 60 张（训练需要 40–60 张），额外和副卡组各最多 15 张，不限制禁限卡和同名张数；副卡组保存但不参加训练。未接入 MDPro3 禁限表或关联卡牌功能。

## 展开报告

### 前置设计、重试与保存

- 先填写非空方案名称，再设置实际起手数量。默认 5 张，提供 1／2／3 张快捷选项和其他正整数输入；最多为当前主卡组实际张数与自由练习上限 60 张的较小值。额外和副卡组不参与抽取。卡牌选择只列出选定主卡组，显示总数、指定数和剩余可指定数。
- “添加卡牌”要求起手至少包含指定副本。指定 1 张不会排除随机抽到剩余同名副本；指定总数不能超过牌组中该卡数量。
- “添加禁止卡牌”始终可用，包括单张起手或全部指定时。禁止条件对整副初始手牌生效，不占用槽位。同一卡不能既指定又禁止；冲突、超量或满足条件的卡牌不足时明确提示并阻止开始。空槽位从扣除指定副本、排除禁止卡后的牌组中不放回抽取；禁止卡仍保留在剩余牌组中，后续规则正常。
- 缩减数量或编辑卡组后，原有指定与禁止条件继续保留。超出数量的指定槽位会标记，已移出主卡组的卡牌会提示；必须手动移除、替换或增大数量，不会静默丢弃选择或放宽条件。
- “启用对手 AI”默认关闭。开启后可以选择已有对手卡组、编辑本次训练卡组和设置部分或全部起手；默认仍为 3 张灰流丽、37 张魔物狩人，指定起手 1 张灰流丽与 4 张魔物狩人。双方“编辑卡组”复用同一编辑器，点击“应用卡组并返回条件”只改变本次设计，不覆盖来源卡组。导入和选卡能力继续可用。
- “允许对手 AI 响应玩家操作”默认开启。关闭时，内核 AI 放弃对玩家操作的可选发动，强制效果、目标选择、费用与规则结算仍执行；AI 自身回合沿用基础通常召唤、随后结束的逻辑。仍为内核简单 AI，没有新增复杂策略或战斗策略；不保证任意复杂卡组的策略质量。AI 的效果、费用与结果进入同一原始事件记录。
- 玩家默认先手；选择后手时，对手先走第 1 回合。双方初始 LP 独立设置，默认 8000，范围为引擎接受的 1–2,147,483,647 的整数。起手数量指规则开始前实际发出的初始手牌：后手到自己的抽卡阶段仍按规则额外抽 1 张，例如设置 1 张，正常进入第 2 回合主要阶段时会有 2 张（无其他卡效时）。
- 计时默认关闭；正计时默认起始 0 秒，也可填写起始时长；倒计时填写正整数总时长，单位为秒，显示为时:分:秒。进入可操作场地后开始，场内查看记录或临时切换其他区域仍计入整体用时；返回修改条件、结束或重试时停止，新的尝试按配置重置。倒计时归零只停止计时并提示，场地仍能继续操作。
- 场地顶部“返回修改条件”确认后停止当前尝试，保留双方卡组、起手、禁止条件、AI 开关、先后手、LP 和计时设置。修改并再次开始时，随机位置重新抽取（仍可能偶然得到相同卡牌），使用新 UUID 和独立记录；旧尝试的原始记录保留。确认框可取消，正式方案不会因此改变。
- “重新展开”经确认后恢复双方初始状态，保留方案文字、条件、实际起手、牌组顺序及本次随机状态。旧尝试标为已放弃并从常规列表隐藏，独立的原始文件保留；后续草稿只使用新尝试日志，绝不混入旧步骤。
- “展开结束”生成待确认草稿；“保存方案”只生成确认摘要，只有“确认存入”写入正式方案。可以编辑方案和步骤名称、备注、终场逐卡说明、具体效果补充及条件核对，不改写动作和规则状态。记录中断、终场连锁未结束或逐步快照缺失时不能作为完整新方案保存。保存失败保留内容，重复确认同一草稿只产生一个正式方案。调整页可“放弃草稿”；正式方案可继续调整说明或确认删除。
- 正式方案保存完整牌组、卡牌文本、起手条件、实际起手、操作及最终状态快照。修改或删除源牌组不改变方案；历史记录仍可访问。切换区域保留当前填写内容并提醒其保存状态；切换另一条草稿前确认是否放弃未保存的文字。
- “展开管理”提供列表、查看、调整、删除和“生成一图流”。教程取自当前已保存方案的冻结快照与已保存说明，不混入未保存草稿；旧方案缺失条件或终场标记时明确提示，生成和导出不改写方案。PNG 适合直接分享，SVG 包含嵌入卡图、无需本地服务即可离线打开；过长路线的 PNG 达到画布限制时提示改用 SVG。原始资源与起手条件核对仍保留在方案详情及保存确认中。“以此条件再次展开”从冻结方案恢复全部配置，旧方案缺失的新字段使用旧版默认值（5 张、先手、双方 8000 LP、响应开启、计时关闭），新尝试独立保存。删除确认显示方案名称；删除只将目标正式快照移入本地恢复目录，不影响源牌组、其他方案或原始历史。

### 方案分享与系列分类

- 在展开管理点击“导出方案”下载 `.ygoplan.json`，分享内容包括构筑、起手条件、冻结卡片文本、步骤和事件依据、回看快照、人工说明、终场标记及标签正名／别名／主标签。文件不包含本机路径、进程信息、账户、原始 JSONL、卡图或可执行脚本；卡图使用接收方本地资源，缺图显示占位图。需独立离线看图时，可另外导出一图流 PNG／SVG。
- “导入方案”先校验文件版本、大小和数据结构，并展示名称、操作数量、标签及缺失卡牌。单文件上限 20 MB；确认后生成独立方案 UUID，同名方案不覆盖，重复文件打开此前导入项。失败时保留原有方案。导入后可回看、编辑说明、生成一图流与按条件新建展开；实际训练仍须通过本地卡库和脚本校验，分享记录不会被声称为本机重新验证过的对局。
- 标签使用卡库的系列编号与系列表识别归属，支持同一卡牌属于多个系列及子系列。当前内置已核实官译“转生炎兽”（含繁体／日文／英文别名）；其他系列默认采用本地系列表名称，来源在管理界面可见，不宣称全部译名已逐项官方核对。“TAG 管理”可新增自定义标签、编辑正名及多个别名，并搜索添加或移除标签中的卡牌；改名保留旧名为搜索别名，同一名称不能混归到两个标签。导入按系列编号合并，保留本地正名，冲突别名不改变已有归属。
- 新方案保存时自动分类；旧方案可即时显示自动分类，但不会仅因查看而改写文件。默认按实际参与路线的我方不同卡号统计（重复使用、同名副本不增加浓度；未使用的抽牌、对方卡牌不计入）。某系列至少 2 种且占比达到 20% 才自动添加；浓度最高者为唯一自动主标签，同浓度优先更具体的子系列，再按名称稳定排序。没有足够证据时留空，不猜测。自动模式随标签卡牌范围更新而重新计算显示，不改写冻结步骤；手动和导入的分类保持原选择。
- “编辑标签”可添加、移除、指定或取消主标签，允许人工设置多个主标签；“自动识别标签”重新计算并供保存前检查，不会在后台覆盖人工选择。标签面板列出浓度与卡牌依据。自动识别为本地确定性辅助，无需大模型或联网。每方案最多 30 个标签，每标签最多 30 个别名；标签的人工卡牌范围也随分享文件导出。导入遇到同名或同系列已有标签时保留接收方的卡牌范围，并提示差异。
- 列表用文件夹浏览系列，支持路径返回及未归类文件夹；单一搜索框支持方案名、系列正名／别名和实际使用的我方卡名／准确编号。分类单独保存，修改前备份正式方案；标签库也保留修订备份。手动清空标签会持久保存，不会在重启后重新补回。

### 展开场地中的操作回退

- 左侧包含“初始状态”、步骤序号、关键卡牌、摘要和当前节点。步骤与同一原始记录生成的展开报告共用动作投影，不单独猜测卡效。同一次连锁或连续选择中的多个步骤按原顺序展示在一组内，点击后恢复到整组完成的状态；处理中显示待完成步骤。
- 点击节点回到它完成后的状态；撤销某一步应选择前一个节点。初始状态是本次自动准备完成后的第一个玩家决策点，通常为主要阶段；后手时会包含此前的对手自动行动与规则抽卡。恢复保留双方实际起手、全部区域与位置、牌组顺序、LP、回合阶段和规则内效果限制。
- 回退后，尚未改写的后续节点暂时标为“待替换”，仍可以点选恢复；第一次实际规则响应发生后，旧后续节点退出当前有效路线。查看记录、结束并保存只使用当前路线。已保存方案独立冻结，不会因另一尝试回退而被覆盖。计时仍表示本次尝试总用时，不随规则状态回退。
- 恢复期间场地暂停输入，时间轴显示处理状态并防止重复点击。引擎在独立的第二个核心与 Lua 实例里，使用本次种子、载入顺序、完整响应和查询顺序重演，核对消息字节、查询结果与全区域状态后切换；恢复校验失败保留原可操作引擎。正常训练仍为随机种子，固定种子只用于显式验收实例。
- 支持范围：本次仍在运行的单人规则引擎。除初始决策点外，可恢复节点仅在主要／战斗阶段的操作选择且当前连锁为空时生成；选素材、选对象、支付费用、连锁处理中不建立单独的恢复节点，但可以从这些选择界面回到此前节点。纯规则流程不增加报告动作，但需要恢复的阶段／战斗状态会作为状态节点保留。
- 引擎没有可直接反序列化 Lua、处理器栈及效果次数状态的快照接口，所以不能只用 JSON 场面恢复。重演耗时随路线长度增加，超过 20 秒或结果不一致会取消恢复；该期限在核心调用之间检查。已关闭的场地、历史方案和旧版日志不提供继续操作式回退，仍可查看或按原条件新建尝试。
- 原始 `native.jsonl` 始终追加，保留退出路线的证据；新增 `checkpoint`、`rewind`、`branch` 和 `route_input` 控制记录。报告先选择有效路线再生成原有 `events` / `actions`，旧战斗过滤和事件格式保持兼容。内存中的完整调用序列仅服务本次存活的引擎，关闭后不承诺恢复。

### 记录展示

调整区左侧从“初始手牌”到“终场结果”连续编号为 Step N，自定义名称不改变序号。中间展示节点结束后的真实区域、手牌和素材。点击卡图在附近打开详情浮层，显示冻结资料和截至该节点的来源；点击日志里的卡牌也不会切换当前步骤或滚动到页首。浮层可用关闭按钮、Esc 或点击外部关闭，卡牌随页面滚动移位或切换页面时收起。右侧固定小开关随时打开或收起日志，顶部保留原入口。日志顶部可切换“简略／详细”，默认简略版横向展示发动 → Cost → 对象（如有）→ 处理结果；场上位置小图缩为 30×24 像素，墓地等区域保留文字。费用、无效与结果缺失仍保留，长流程可横向滚动。超量召唤上方已表示素材与结果，不再重复素材去向；连接等召唤的逐卡去向在详细版查看。Esc 优先关闭卡牌浮层，再关闭日志。只读回看不调用场地回退、不重新抽牌或执行规则动作。

- 优先以原生 checkpoint 分组，旧日志使用完整消息批次；跨边界的连锁合并到记录齐全后的节点，并标出记录范围。原始动作投影的噪声过滤继续保留。
- 超量怪兽显示素材数量及“本体／素材”切换；墓地、除外和额外卡组可查看列表。主怪兽区按记录标 1—5 号，共享额外区独立展示，灵摆与场地区保留。未知身份使用卡背，连接怪兽的异常守备状态显示待核对。
- 不相关的对方区域隐藏。对方响应、目标及效果文本涉及对方时保留相关区域，并提供动作前的对方状态参考；效果文本只用于提示关联，不证明条件已被独立验证。对方未公开区域的身份在回看投影中隐藏，原始证据保留。
- 我方途中效果抽卡和规则抽卡按实例在日志、节点场面、卡牌浮层、保存确认和已保存方案终场摘要中显示“随机抽牌”卡背；起手保持实际手牌，检索得到的同名副本不受影响。缺失实例的旧记录不按卡名猜测对应关系。真实抽到的卡名仍保留在原始报告与依据中；若路线后续实际使用指定随机命中，条件摘要继续列入随机依赖。显示切换不改写冻结快照或重新抽牌。
- 终场整体说明与每张卡的实例说明分别保存；步骤名称、备注和效果补充也独立保存。返回修改保留编辑，改动后重新生成确认摘要。未确认的编辑仍在当前页面内存中，退出应用前应完成保存。
- 保存前分别展示实际使用资源、起手条件和随机依赖。按实例去重，回收再使用不加份数，未参与操作的随机牌不列为指定资源。途中随机抽到且用于路线的指定牌单列随机依赖。
- 明确、无附加身份限制的单张手牌费用可自动显示“任意手牌 ×1”；其他费用可人工核对真实限制。此卡后续还有非费用用途时不能简化。人工补充需填写数量、关联步骤和用途，与记录事实区分。统计针对本次路线，不声称推导所有替代路线的最小条件。

- 起手单独展示；起手和正常回合抽卡、阶段、选择、占位方跳过及连锁流程不占用展开步骤。
- 普通攻击宣言、伤害步骤、战斗结果、紧随战斗结果的单纯伤害及普通战斗破坏送墓不占用展开步骤；战斗中发动的效果、效果伤害、回复及费用照常展示。最终 LP 与场面仍取自真实快照，原始事件可随时查看。
- 按每组连锁和对应结算区间关联实际结果，按“费用 → 处理”展示。多段连锁保留各自结算顺序，不仅凭卡名合并。
- 支付 LP 的发动费用也归入对应效果，先于检索、特殊召唤等处理显示；依据发动费用区间、付款方和连锁快照关联，不根据文本中的数值补造支付。
- 卡牌详情保留完整效果文本。简版日志使用记录中已核实的效果映射显示编号与简述，悬停或键盘聚焦显示对应详细文本；无法匹配时显示“具体效果待补充”，用户补充单独标记。发动、结算完成、无效和结果未记录分别表达。
- 同一次效果中的多张同类费用合并展示卡名。例如金满而谦虚之壶的 6 张里侧除外费用合成一项；翻开、取走一张和剩余卡排序回到卡组底部分别显示，不称为“加入卡组”。
- 按核心召唤类型、素材与区域事件区分连接、同调、超量、融合等召唤。素材移动归入召唤，效果特殊召唤不重复列出入场移动；复活融合怪兽不会仅因卡片类型被称为融合召唤。原怪兽区 6／7 显示为额外怪兽区 1／2。
- 省略已确认的普通魔法／陷阱常规结算后送墓；效果移动、费用、无效及未完成状态仍保留。
- 效果全文直接可见，另可展开“查看依据”核对事件，或切换原始事件、打开 JSONL。效果文本不会用来补造尚未发生的结果。

效果抽卡统计排除起手和规则抽卡。当前为自由练习：检查主卡组 40–60 张、额外及副卡组各不超过 15 张、卡号、分区和脚本，不执行禁限卡表及同名三张限制。副卡组保存在构筑快照中，不参加训练场地。

## 复用与数据来源

当前副本核实有 14,981 张卡牌资料、14,980 个卡图文件及 13,538 份 Lua 脚本。

| 能力 | 来源 |
| --- | --- |
| 卡名、数值、效果文本 | SQLite 只读读取 `cards.cdb` 与支持的松散扩展 CDB |
| 卡图 | 副本 `pics/`、`expansions/pics/`，缺图使用占位图 |
| 构筑兼容 | YDK 卡号及 `#main`、`#extra`、`!side` 格式；原生 `DeckManager` 再读取 |
| 操作与结算 | 原生场地、`SingleMode`、`ygopro-core` 和副本效果脚本 |
| 事件 | `process()` 完整消息批次，在动画前落盘；另记玩家响应 |
| 状态 | 核心全区域快照与 `cardid`，包括叠放关系、召唤类型、素材实例与原因卡牌 |
| 效果归属 | 连锁编号和结算区间；新记录增加原因效果的 Lua 句柄与所属卡牌实例 |

展开直接创建本地单人核心。关闭 AI 时对手为空场占位；开启时使用上述基础对手及内核 `DUEL_SIMPLE_AI`，不启动 WindBot、Bot 或网络对局。联机、原客户端录像播放和音频保持排除。详细规则与限制见 [记录说明](recording.md)。

## 本地保存与恢复

```text
.local/YGOPro-Lite/_trainer/
  decks/                     工具保存的 YDK
  backups/                   覆盖保存前的备份
  tag-library.json           本地标签正名、别名与修订号
  backups/tags/              标签库修改前的恢复副本
  plans/<尝试 UUID>.json      正式方案的完整冻结报告（原子写入）
  plans/deleted/<UUID>.json   删除的正式方案恢复副本，防止迟到的保存请求重建方案
  sessions/<训练 UUID>/
    session.json             冻结构筑、卡牌文本、时间和结束原因
    deck.ydk                 本次交给模拟器的构筑
    opening.cfg              版本 2 原生配置（双方发牌顺序、实际数量、先后手、LP、AI 响应）
    opponent.ydk             启用 AI 时冻结的对手卡组；原生端校验副本数量
    timeline-state.json      当前节点与输入版本；回退防重复及过期校验
    rewind-operation.json    最近回退的处理状态
    ready.json               只读可操作状态标记，用于启动本次计时
    native.jsonl             原始事件与状态
    report.json              当次生成的报告
    report-v8.json           当前动作投影及只读节点快照，旧版报告保留
```

只有“展开结束”标为手动完成；关闭模拟器、引擎提前结束或缺少结束标记均按中断保留。服务重启根据进程创建时间重新关联存活训练，避免误认被复用的进程号。异常时保留最后成功落盘状态，尚未写入的数据不能保证恢复。恢复误删方案时先退出应用，备份数据目录，再将对应 `plans/deleted/<UUID>.json` 移回 `plans/`；不要覆盖同名文件。

新正式方案内冻结 `review`（节点状态、实例来源）、`annotations`（用户说明）、`requirements`（确认摘要）和 `edit_revision`。更新正式方案说明前，原版本备份到 `plans/revisions/<UUID>/<版本>.json`；恢复时退出应用、备份当前文件，再用所需旧版本替换该 UUID 的正式文件。源卡组修改不会改变方案。旧正式方案缺少逐步状态时显示未知，原文件不在读取时升级；旧会话可从保留的原生日志派生 v8 报告。详见[记录说明](recording.md)和[视觉与规则参考](review-references.md)。

`.gitignore` 排除 `.local/`、依赖、缓存、日志、构建产物和凭据，排除不会删除文件。源码、补丁、依赖锁、合成测试和说明纳入 Git，个人构筑及训练数据留在本地。

## 构建与检查

当前副本已经准备好。重新构建需要 Visual Studio C++ x64 工具链（当前验证 VS 2026），先结束运行中的副本模拟器：

```powershell
python scripts/apply_lite.py
.\scripts\build.ps1
python -m unittest discover -s tests -q
node --check src/trainer/web/app.js
node --check src/trainer/web/report-view.js
node --test tests/deck_editor.test.cjs
```

Node 用于 Electron 开发、打包和编辑器测试；打包后的桌面应用已经包含所需运行时。原生构建使用经校验的 ASCII 目录联接，实际源文件仍在本副本。

从空目录准备时，依次运行 `python scripts/prepare_copy.py <原始YGO目录>`、`python scripts/fetch_sources.py`、`scripts/prepare_runtime.ps1`，再应用补丁和构建。复制工具逐文件校验，已有副本时拒绝覆盖；精简只处理副本。下载版本与校验和固定于 [source-lock.json](../scripts/source-lock.json)。`python scripts/fetch_sources.py --verify-only` 只校验本地归档。本次验证已准备副本的重建，没有在全新目录重复完整下载、解包和全量构建。

[验收记录](verification.md) 区分实际运行与合成测试；[第三方来源](third-party.md) 说明上游版本与许可证。

[引擎与卡牌资源更新机制设计](update-mechanism-design.md) 记录上游更新包检查、兼容边界、安装恢复和验收方案；该更新机制尚未实施。
