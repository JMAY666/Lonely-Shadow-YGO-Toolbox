# 1.19.0 功能选择与场地刷新

日期：2026-09-16。

## 改动

- 决斗流程在模式与卡组之间增加功能选择。手动选择进入原有流程；自动选择置灰并标注待开发。插画、尺寸、配色和居中布局沿用模式页。
- 流程阶段使用统一名称引用，同步卡组预览、先后攻、方案收藏、临时教程、快捷键与再来一场。返回功能页后继续手动流程保留本局准备。
- 原生窗口修复兄弟窗口层级时只调整层级，禁止此次调用额外触发重绘；仅尺寸或裁剪模式变化才重设裁剪区域，仅显隐变化才调用显隐接口。监控、布局请求与状态读取串行使用同一状态，避免交错应用和读取半完成的更新。
- 窗口更新计数只在测试参数启用时通过内部状态接口返回，正常启动不提供这些诊断字段。

## 验收范围

使用隐藏的 Electron、隔离测试数据和引擎内部输入／截图接口。新增检查覆盖新步骤的入口、未来步骤禁用、自动入口禁用、返回后保留卡组与标记、重新开局重置、1280/960 宽度居中与插画实际加载。

原生窗口回归主动改变测试子窗口层级八次，修复前因未设置禁止移动／缩放标志而失败；修复后验证不会重复裁剪、移动／缩放或显隐。另检查可见和隐藏窗口的重复同步均不重绘。完整桌面流程新增十二轮历史、时间轴与布局刷新，检查场地位置、裁剪次数及显隐次数稳定。

初次界面验收发现两张插画尚未加入静态资源允许列表，已补齐；布局测量改为等待悬停动画结束。初次完整桌面验收已通过卡组、导航和手动决斗部分，在侧栏恢复后的场地检查中捕获到过渡期间的额外裁剪更新。将状态读取与布局更新同步，并让稳定性检查先等待待处理布局收敛；随后使用 `--native-only` 直接建立同类隔离卡组，重跑原生嵌入、真实动作、记录保存和重启验收，不重复已经通过的卡组编辑部分。

拆分后的专项脚本补齐了重启检查所需的收藏初始化；并行启动时曾争用旧测试迁移源的锁，专项现在默认使用各自的空白迁移源。应用资源仍由同一个已校验运行资源包提供，正常用户迁移逻辑没有改变。

## 最终结果

- `npm test`：231 项 Python、164 项 JavaScript 通过。
- `npm run test:desktop -- --native-only`、`npm run test:packaged -- --native-only`：均通过，渲染器错误列表为空；覆盖真实效果、召唤、回退、缩放、切换页面、记录保存、重启保留、正常模式禁用测试接口，以及关闭时保存中断记录和退出引擎。
- 两种构建的十二轮连续刷新中，场地坐标保持一致，位置更新、裁剪和显隐计数均保持为 6；没有重复裁剪或隐藏／显示。证据在 `.local/evidence/electron-{development,packaged}-native-stability-verified/`。
- 新功能页和完整手动决斗在前述两种构建的完整流程前半段通过，截图已核对；后续只修改原生宿主和验收脚本，前端文件保持一致。
- `npm run build:dir` 通过。最终包中 79 个 trainer 文件与源码逐项一致，28,888 项运行资源通过允许范围检查，未包含个人记录；打包 EXE 名称及七种图标帧检查通过。应用位于 `release/1.19.0/win-unpacked/`。

本次未重复与改动无关的模块化搜索及对手策略矩阵；完整命令的早期失败和后续专项复验范围如上，不将其描述为一次完整命令全部通过。

个人卡组、方案、对局记录、旧版本与备份保留；应用包及验收截图仅在本地。未接管用户正在使用的窗口，用户显示器上的最终观感仍需在新版确认。
