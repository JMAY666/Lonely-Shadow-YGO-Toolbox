# 条件牌 · 1.26.0

在前置设计的选卡窗口选择“条件牌 · 创建／编辑”。提供“任意等级 1／2／3 调整”预设，也可复用当前玩家、对手设计中的条件。点击条件卡可查看、编辑或替换，原来的移除槽位按钮继续可用。禁止列表中的条件卡有独立用途标识、编辑和移除入口。

## 规则与预览

- 支持嵌套“全部满足（且）”“任意满足（或）”“排除（非）”，组合最多 6 层、80 项；空组合和未知字段会报错。
- 卡牌类别、怪兽种类（调整／非调整等）、属性、种族、指定卡号支持多选包含或排除。多选包含表示命中其中任意选项；要同时满足两种怪兽种类，创建两个条件并使用“且”。
- 等级、阶级、连接值分别配置等于、上下限或闭区间；缺少对应属性的卡牌不匹配，在排除组合中也不会被错误纳入。灵摆刻度不会被当作等级。
- 系列使用卡库中的十进制系列编号，支持数据库父系列／子系列语义与 64 位打包数据。显示名、用户 TAG、效果文本和自由文本备注不作为自动判定规则；缺少必要卡牌资料时阻止开始。
- 预览仅使用本次选定主卡组，列出卡图、名称、投入数量、匹配种类数和副本数。编辑起手条件时另外显示结合全部指定槽、条件槽、禁止规则之后仍可填入此槽的种类，以及每种卡的最大余量。
- “最大余量”是先满足其他必要槽位后，该种卡最多剩下的副本数，供本槽及随机补齐使用。不同种类的最大值独立计算，不能相加。整套规则无解时明确显示不可分配；禁止条件零命中时提示没有实际影响。
- 可以保留暂时无候选的设计以继续编辑，但不能开始展开。修改起手数量保留超出范围的指定槽并提示处理，不静默删除。

一个条件槽占用一张实体副本，同一副本不能重复满足其他槽。指定卡或条件卡只规定必要出现，剩余同名副本与其他符合条件的卡仍可进入随机槽。禁止集合排除整副初始手牌，不占槽位、不移除牌组中的卡，后续抽牌、检索继续正常。分配使用实体副本的完整匹配，候选和处理顺序随机化，不固定取首项；不承诺在所有可行整手组合之间数学等概率。

## 保存与历史

旧槽位继续使用卡号或 `null`；条件槽新增以下可执行定义，禁止列表使用相同结构：

```json
{
  "kind": "condition",
  "version": 1,
  "rule": {
    "op": "all",
    "items": [
      {"field": "level", "op": "eq", "value": 3},
      {"field": "monster_kind", "op": "in", "values": ["tuner"]}
    ]
  }
}
```

存储完整规则，不保存预览卡号列表作为规则。开始时将规则解析为真实卡号，`expansion.conditions` 保存设计，`expansion.actual_opening` 保存本次实例。引擎配置、动作、回放和快照仍只包含真实卡牌。

“重新展开”复用冻结的实际起手、牌序与种子；“返回修改条件”或“以此条件再次展开”创建可编辑设计，下次开始重新解析并生成新的实例。保存后的原方案和历史记录不随修改或换牌组改变。现有具体卡数据无需迁移；没有对生产数据做批量转换，原备份、旧版本和记录保留本地。

## 影响清单

| 模块／入口 | 条件牌处理方式 |
| --- | --- |
| 起手设计与快捷填卡 | 专用卡面、可编辑规则；实际卡快捷填入后重新整体校验，冲突阻止开始 |
| 对手起手、禁止上手 | 与玩家共用编辑器和校验器，使用对手自己的主卡组与数量；禁用 AI 时保留配置 |
| 随机生成／开始展开 | Python 统一解析、按实体副本匹配，不放回随机分配，真实卡号写入原生配置 |
| 重新展开／返回设计 | 重试保留本次实例；返回设计重新校验并生成新记录 |
| IF 妥协分支 | 继承主线的冻结起手与具体回放；中途配置的对手场景手牌属于局面输入，继续使用具体卡牌，不套用初始发牌约束 |
| 草稿、保存、编辑、展开管理 | 规则与实例独立保存，详情标记条件集合与实际实例；修改起手通过新设计进行，不改写旧记录 |
| 分享、导入导出 | 保留完整规则；校验字段、版本、实际副本和冻结发牌的一致性，拒绝伪造实例；旧格式继续读取 |
| 一图流／方案详情 | 集合卡面、完整括号化条件、禁止范围及本次实例；步骤仍是实际记录的路线 |
| 手动／自动决斗筛选 | 对实际整手匹配所有必要槽位，处理数量、交叉和禁止规则；训练时的随机补齐空槽不额外限制手牌数量，路线实际使用的任意手牌费用仍按记录核对 |
| 教程与路线替换 | 起手集合满足而已记录的必要卡不足时显示“替换尚未验证”，不列为可执行匹配 |
| 模块化来源、组合与执行 | 来源附带原始起手条件与实例；决策绑定保持具体卡号，费用／素材／效果及连接由引擎验证，不建立属性替换关系 |
| 临时方案与续算 | 输入仍为已确认的真实手牌，内部设计使用真实卡号；生成的步骤和快照不会被条件替换 |
| 后台预计算 | 来源版本包含完整规则；实际手牌、构筑版本、来源版本、卡库／脚本变化使旧结果失效 |
| 卡库补丁变更 | 前端预览键包含卡库版本，重新校验当前设计；冻结方案资料保持原样 |
| 回放、训练、原始记录 | 保持原数字卡号协议、引擎、操作格式及原记录，不向原生端传入条件对象 |

条件满足只证明存在合法起手分配。即使两张卡都是等级 3 调整，也不能推出效果、费用、素材身份或整条路线相同；新的替换必须有规则引擎及后续步骤的证据。

## 验证

针对性用例位于 `tests/test_opening_conditions.py`、`tests/opening_rules.test.cjs` 和 `tests/plan_tutorial.test.cjs`。全量入口为 `npm test`。桌面用例 `desktop/condition-cards-smoke.cjs` 已纳入 `npm run test:desktop` 和 `npm run test:packaged`，也可通过 `node desktop/smoke.cjs --conditions-only` 单独定位。

桌面验收只操作测试实例的渲染器和内部引擎接口，使用隔离数据，不操作系统鼠标或发送全局按键。日志、卡组、发牌实例和截图位于 `.local/`，应用包位于 `release/1.26.0/`，均不提交 Git。实际执行结果见 [1.26.0 验收记录](verification-1.26.0.md)。
