## 图解和推演怎么读

每份资料先声明示例起手、已知场面及资源。图中的有序步骤说明对手操作、得到的资源和适用断点；断点编号是资料内索引，不是所有对局的固定第几步。一个动作可以包含已经说明的召唤及随后的触发，属于教学图解节点，不冒充引擎原始操作日志。

随后比较放行、在指定节点阻抗、对方仍有补点三种情况。例子可以节选公开展开前段，也可以是完全列明前提的卡文机制例。资料不预测未知手牌；“没有其他起动才不能继续”会写明，已明确拿到的补点也不会隐藏。

例如味美喵先检索到惊喜，再连接、放场地和复活。场地复活被阻止时，惊喜已经在手，仍可能补素材。VS K9的例子则说明：灰流丽挡住赌魂后，手牌怪兽效果的发动可能满足K9饭纲／野狼的特召条件。这些是手工条件推演，**没有逐局规则引擎验证，也没有胜率或必停保证**。

## 证据层次

- **环境证据**：牌型被纳入的原因、样本窗口及数量。MDM Power按最新100份社区赛事上位牌表计算，既不是百分比也不是天梯使用率。Rating Duel未披露的名次保持未知。
- **对策参考**：署名攻略或赛事分析给出的展开／建议。旧路线注明原文月份，再核对目前卡文；不能把用户投稿当成官方裁定。
- **官方卡文**：每个断点的对象、所用应对卡及相关保护文本均可查。卡文支持效果适用范围，不证明该节点在任意手牌下最优。
- **人工推演**：明确起手与连锁前提后，比较资源得失。与引擎验证分开标记。

资料特别核对了：灰流丽的效果范围、幽鬼兔仅破坏、屋敷童无效发动、锁鸟的实际卡组加手时点、泡影手发的空场条件、效果遮蒙者的对方主要阶段限制、费用与效果处理的区别，以及多触发连锁不能任意跨环响应。

发现的第三方简写错误没有照搬：狄娜／抢夺猫的纯放置不吃灰流；白色灵堂的送墓不写成费用；耀圣狱神精升星后做鲜花女男爵须另行正规同调，不能写为其效果内限定同调；MD当前禁限页中的墓穴的指名者不作为可用对策加入。

## 导入与维护

界面：情报站 → 断点管理 → 导入主流对策。记录、主题继续保存在当前用户的 `runtime/_trainer/tag-library.json`，不引入第二份个人数据库；旧文件备份仍为 `runtime/_trainer/backups/tags/<修订号>.json`。

同一版本已存在的记录不覆盖，包括用户的修改。删除整条后可重新导入。同名主题会给新资料添加版本后缀；旧主题保持独立。卡库缺失的准确卡号仍保留，页面显示缺失，不用相似名称替代。手动改步骤后旧来源不再自动绑定新步骤。

维护命令限已关闭的个人实例，默认只读预览，`--apply` 才写入并取得独占服务锁：

```powershell
python scripts/import_matchups.py --runtime "<个人运行目录>/runtime"
python scripts/import_matchups.py --runtime "<个人运行目录>/runtime" --apply
```

更新资料时需重新核对来源、适用环境、卡号与连锁条件，再更新资料版本。个人文件、导入备份、下载的公开原始页面、验收截图和应用包均留在本地忽略目录。不要用旧版本程序编辑新导入的图解资料。
