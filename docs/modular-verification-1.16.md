## 已修复的实际问题

- 把展示／动画等待误当成决策窗口：现在确认核心选择处理器确实在等待输入。
- 效果描述索引与卡面编号错位：使用准确效果元数据并独立核对文本编号；灵摆卡发动、灵摆效果和怪兽效果分开显示。
- 多个回看／决斗功能直接使用旧 Step 数组：改为共享模块图投影，保留批注与历史 ID。
- 只对照场上卡片会提前判定终场：增加有效操作结果、手牌净变化、实际伤害、已标记资源和素材检查。
- 源于随机堆墓的偶然墓地内容被当成固定前提：普通附带资源与显式终场标记区分，预测不公开私有结果。
- 输入已提交、后继状态先于回执被读取：按指令标识接收回执，不重复提交；确认过程加锁。
- Lua 回收后两个虚拟机的 `effect_handle` 不同：跨副本比较排除此临时编号，原始证据保留；其他效果和状态字段继续比较。
- Windows 状态轮询与结束保存偶发共享冲突：对短暂文件占用做有限重试，持续权限错误继续失败，保留原数据。
- 大方案导致历史轮询相互覆盖：缓存方案名称版本并合并同时发出的历史请求。
- 结束未绑定引擎的普通决斗教程时空对象报错：只停止确实绑定的本局引擎。

文件占用重试修复后，单元测试、开发版精确与调度专项均重新通过；最终发布包的调度与结束保存专项通过。完整打包回归在此修复前通过，修复后没有重复运行全部桌面场景；发布包不包含测试构筑或个人记录。
