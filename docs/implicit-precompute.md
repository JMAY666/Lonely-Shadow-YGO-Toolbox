# 隐性条件与后台预计算 · 1.25.0

隐性条件是路线中特定步骤需要从指定区域取得的确定资源，不是禁止上手卡名。保存前确认紧接起手条件显示这些资源；展开管理读取同一推导。一图流不增加条件说明区，仍展示检索、送墓、回收、召唤与盖放操作。

## 依据与资源流转

`requirements.implicit` 包含推导版本、条件、步骤时间序列和待核对原因。每项条件保留卡号、份数、来源区域、关联步骤、用途、实例与事件依据；同一次选择的不同副本合计数量。同一实例离开区域、返回卡组或重复使用，按时间推进，不重复当成开局资源。

识别使用冻结模块图中的实际选择及事件区域变化。公开卡组快照刻意不包含洗牌顺序和实例编号：卡组选择只在对应决策的结算范围内，通过实际离开卡组的事件绑定实例，不从名字、效果说明或卡组顺序猜测。墓地的咆哮盖放关联到前面的送墓事件；不会要求开局墓地已经有咆哮。界面步骤沿用项目原有编号（包括初始节点），不是说明文字的七行编号。

随机抽牌不会产生确定卡名条件。没有明确选择依据的卡组移出事件（包括随机堆墓）及其后续使用不会被提升为确定条件，显示随机或待核对。老记录缺少选择、实例或完整快照时保持原文件，按冻结证据在读取时补算，并明确标注缺失依据。调整、重新保存和分支报告分别重新推导，不改写原始日志、批注、收藏或构筑。

## 普通匹配与模块组合

普通匹配保留 Tag、起手、手动禁止上手及主／额外资源条件，扣除实际起手后按实例流转检查每个区域。通用手牌费用先避开后续需要的指定起手资源。同名卡在手中但卡组仍有副本时继续核对；无关额外手牌不会使最低起手条件变成全手牌相等判断。

不满足的方案在方案选择页提供具体步骤和剩余数量。缺少证据与随机依赖分别说明，不列为完全满足条件。分支独立校验；主线不满足而无额外干扰前提的录制分支满足时，明确展示该分支及主线失败原因，不把分支冒充原主线。

1.26.1 修正定向选卡后的中间选择：同一次效果处理中，选择加入手牌／特殊召唤、召唤区域或表示形式后才出现的移动，按冻结的效果标识继续对应。中途换效果、重新选卡、响应缺失或实例不唯一时保留待核对。因缺少选择依据而无法确定取得方式的卡牌列为“来源待核对”，不再直接列入“随机依赖”。旧方案展示与普通匹配重新计算这部分摘要，人工补充条件和原文件保持不变。

这层检查证明必要的区域资源条件，不替代所有规则合法性判断。模块组合继续使用当前决策窗口、实际资源、动作重绑和隔离规则引擎逐次验证；完整来源的开局条件没有被机械用于每个模块。临时候选显示来源和接入／跨来源调整。没有已验证的替代路线时，不静默跳过检索或任意换卡。

## 后台任务与版本

手动确认构筑和起手、或自动模式建立确认的本局上下文后，即加载来源索引并启动任务。无需打开面板。输入缺失、来源不完整或规则未就绪时不猜测输入生成已确认候选。

一个任务共享与偏好无关的候选搜索、状态／路径去重、引擎重放及原有干扰评估。保留本轮发现的完整候选池，再分别按步骤最少、终场最大、均衡、稳妥优先评价和截取展示集合，未先按一种偏好截取。标记终场、均衡归一化和限定灰流丽评估口径沿用原实现；未充分评估的稳妥性仍明确提示。

点击加入已有任务，计算中可查看进度和部分候选；评价完成前不能采用这些预览。准备完毕后切换偏好只读取对应结果，不再次加载和搜索。有限预算的一轮可以有可用候选，同时标明搜索尚未完成；它不是“所有路线已搜索完毕”。重试继续使用有效的路径校验缓存，失败与超时有独立错误状态，不显示成没有路线。

任务绑定本局标识、构筑版本、已确认手牌、起点／续接局面、来源版本、规则资源、目标和精确设置。快捷键会话变化不改变本局任务标识。输入改变后取消旧任务；迟到结果不能发布到新状态。采用前在服务端再次核对版本，正常 UI 不能采用过期候选。

起手准备与教程续接分开。浏览回方案页会准备起手候选，但保留原教程及已确认前缀；只有明确采用新候选才替换教程。后台不确认步骤、不执行真实对局输入、不自动保存正式方案。结束、重开和关闭工作区释放任务、缓存和所属后台引擎。

规则资源在应用内已有运行中更新保护。若在外部直接改动规则文件，旧候选及后续确认被阻止，保留教程，明确要求重建引擎；不会把旧引擎的结果标为新资源版本，也不会静默把已确认续接重置为起手。

## 范围与容量

- 单个预计算工作线程，至多 4 个活动任务，闲置 15 分钟回收；候选集合每任务上限 16 MiB，超过时明确失败，可减少来源重试。
- 原有公共缓存保持 48 MiB／1,200 项上限，按会话和完整路径隔离；候选结果仅在内存中保存。临时引擎的本地验收／诊断记录沿用原私有数据目录，不进入正式方案库或 Git。
- 每轮沿用 32 秒／320 次新增校验预算；限定干扰另有 4 秒／80 次预算。深度与候选上限沿用原实现，每种偏好最多展示 24 项。本轮未完成时明确说明范围，重试可因命中旧路径而检查更多新路径。
- 结束后的校验缓存不跨局复用，也不缓存可执行引擎内存快照。来源索引仍按文件版本复用。

## 验证与测量

检查入口：`npm test`、`npm run test:desktop`、`npm run test:packaged`，以及 `npm run test:modular -- --suite=implicit`、`--suite=planning`、`--suite=pipeline`、`--suite=forecast`。全部使用隐藏 Electron、内部规则接口及 `.local` 下独立数据；不发送全局鼠标或按键。

真实引擎的转生炎兽验收执行羚羊送墓、烽火猞猁检索、圣域同名连接和咆哮自行盖放，核对当前卡片文本与引擎／脚本指纹，并检查圣域唯一副本上手、额外副本、保存前后和一图流。单元验收补充循环回收、重复份数、随机身份、分支、旧记录、并发复用、版本变化和迟到任务。手动／自动流程验收检查采用、确认、来源变更、普通步骤续接和结束清理；随机验收检查实际抽牌、堆墓和阻抗，另有并行真实展开日志不变验证。

性能报告比较同一机器、相同五张起手、40 张主卡组和三个录制来源，分别记录后台计算、点击到结果、偏好切换、引擎调用、服务／引擎工作集、CPU 时间及渲染器定时器延迟。原版来自提交 `3f1d41c` 的隔离副本。测量文件保留在本地验收目录；不会上传用户构筑或对局数据。

首次计算与点击等待是两个指标。原版连续切换偏好会借助缓存继续扩大搜索范围；新版四种偏好共享一轮预算，所以跨多次切换的累计校验量不相同，不能据总耗时比例宣称规则搜索快了几倍。完整数值和最终检查结果见[1.25 验收记录](verification-1.25.0.md)。
