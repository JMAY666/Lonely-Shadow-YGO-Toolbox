# 1.35.0 验证记录

## 实际客户端

用户自行操作原已核实 YGOPro 镜像，工具只读，不注入或发送客户端输入。

- 读取器捕捉对手第 1 回合至我方第 2 回合的切换，回合玩家来自观察到的计数变化及新回合消息。
- 用户确认当前主要阶段 1、双方 LP、承载怪兽及其两张素材；工具重新读取并核对当前资源一致。
- 用户分别切换到战斗阶段和主要阶段 2，两次读取与用户报告一致，素材归属保持一致。
- 观察日志中能看到展开期间素材数量变化，但未把这些差异解释为完整取除事件或费用。更多控制权变化、隐藏交互和中断／跨局真人场景未据此认证。
- 已结束对局的阶段控件仍保留旧文字，确认必须由正式对局状态过滤；没有把该残留值作为当前阶段发布。

真人资料在 `.local/ygopro-p22-live/`，源布局研究在 `.local/ygopro-p22-research/`。包含个人卡组的原始资料保持本地，不用于合成夹具，不提交。现场记录器已停止；完整桌面从自动开局到采用快照的真人端到端验收仍待后续。

## 隔离检查

- 最终全量 `npm test`：458 项 Python、219 项 JavaScript 全部通过，包含新增的客户端限制查看标记保护。
- 回合观察检查覆盖晚接入、漏消息、2 秒中断、场景变化、计数跳号／倒退、重复缓存及不按奇偶覆盖实际玩家。
- 阶段检查覆盖不可见／未知文字、控件 ID 错误、短文字边界和读取一致性。
- 素材检查覆盖未知对手承载怪兽不读素材身份、控制者残留字段、承载回指、导入的本次实例关系及孤立素材拒绝；跨区域重复对象不能重复计数。
- 客户端禁止查看墓地的标记经固定源码和二进制写入分支核对，单元检查确认在读取卡号前停止；补充保护后，实机无该限制时的正常读取仍通过。本次未在真人对局中触发该特殊限制。
- `npm run test:desktop -- --second-only` 与 `npm run test:packaged -- --second-only`：原人工／条件提示流程及新的阶段、回合玩家、素材归属合成界面通过。
- 两种版本的 `--second-live-only` 最终定向检查通过；已查看常规／900px 窗口及素材归属截图。旧快照没有被后来新增的素材回填，未知回合玩家仍显示待核对。

## 边界与保留

没有新增完整连锁、合法响应窗口、具体费用／无效事件或外部规则重建。内置引擎、卡库、Lua 和既有原生案例未修改；本轮未重跑全部既有原生或其他平台真人专项。

桌面检查使用后台 Electron、隔离测试数据和内部截图接口；真人核对仅观察用户自行操作的客户端。发布只包含源码、脱敏测试和说明；安装包、截图、原始日志、真人资料及失败证据保留本地，提交前只清理核对过的可重建测试副本。

最终目录包／ZIP 的程序、文档、ASAR 版本、EXE、规则资源与个人记录排除逐项核对，证据为 `.local/evidence/bo1-p22-package-check.json`。本轮两个隔离桌面测试目录的可重建资源经路径、进程、服务锁、清单与内容哈希核对后清理，证据为 `.local/evidence/bo1-p22-cleanup-result.json`；真人资料、日志、截图、设置、备份和旧版本保留，忽略规则不扩大。
