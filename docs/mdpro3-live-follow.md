# MDPRO3 实时跟随 · 1.44.0

## 现状与边界

原有适配只识别已提交构筑、先后攻、初始手牌和跨局边界；自动工作区的教程不读取游戏动作。临时方案原来的“前进”同时调用 `plan-confirm`。这两项能力不能证明此前已有完整对局跟踪。

本版为[同一指纹构建](mdpro3-recognition.md)添加只读跟随，范围为 BO1 我方先攻第一回合主要阶段一。玩家自行选择方案、操作游戏。进入教程后核对进程连接、本局开局消息、冻结起手、工作区与方案版本，再从客户端保留的已处理消息回放已有操作；已提前操作时不会直接认定还在第一步。

| 来源 | 自动支持 | 保持待确认的情况 |
| --- | --- | --- |
| 正式方案 | 所选主线（包括匹配流程已经投影出的路线），有完整逐步快照与原始操作事件的连续前缀 | 旧方案缺失证据、分支操作、结果不一致；不自动替玩家切换分支 |
| 临时方案 | 从冻结起手采用的候选；按现有操作分组编译本地引擎证据，确认整个 `index…through` 范围，写入原有 `forecast_steps`、投影与审计 | 带有续接前缀的候选、随机结果、无法验证的效果、步骤位于未结束的连锁内部；不会把箭头位置作为确认 |

这是有限消息和步骤判据的首版，不是所有卡组、效果或客户端版本的完整对局协议适配。只读检查既有本地方案可发现可跟随前缀，但不等于这些方案已通过 MDPRO3 实际对局联调。实际验收范围见[验证记录](verification-1.44.0.md)。

## 完成证据

采集 `OcgCore.allPackages` 的连续序号，用 `packages` 的数量与队首引用核对已处理边界；动画中或尚未处理的消息不算完成证据。每批指针、列表、消息长度和使用的字段在读取结束时再次校验。新增跟随读取不写内存、不注入、不调用游戏函数、不操作游戏窗口，也不读取对手隐藏牌号或双方牌库顺序。

支持召唤开始／成功、区域移动、表示形式变化、盖放、发动描述编号、加入／处理／结束连锁、对象／选择结果与 LP 结果。步骤需要其**全部**操作事件对应，且召唤和连锁均已完成。已处理消息推导出的我方场面还必须与独立读取的当前我方场面一致。方案的事件与其结果快照自身也须一致；只有发动／连锁结束而缺少可核验结果的效果不自动确认。

卡牌按位置和连续移动建立实例身份；首次对应同时核对卡号、来源区域和操作上下文，之后绑定同一实例。怪兽／魔陷区格位和叠放宿主／素材位置参与核对。支持素材先叠放到额外区宿主，再随宿主入场，以及取除素材后的索引变化。手牌洗切在卡号唯一时更新同一实例的位置；同名卡洗切造成实例歧义时暂停，不能只靠卡名继续。不支持的交换、计数器等消息也会暂停，不能静默忽略。

重复采样不重复确认；同序号不同内容、序号缺口、乱序或游标回退均不推进。单次补收上限为 4096 条消息，本局保留上限为 8192 条，临时候选证据编译上限为 256 次决策；超限显示原因。这些上限用于停止不可靠的处理，不截断路线并宣称完成。

## 使用与人工控制

教程上方显示连接状态以及“尚未执行／执行中／待确认／受阻／已暂停／路线已完成”，已完成节点有独立标记。提供开始、暂停、恢复、重新同步、返回实时进度、手动确认当前待执行步骤和重新选择方案。

- 进入 MDPRO3 跟随教程后，箭头、快捷键、回看及点击未来节点只改变浏览位置。实际进度继续记录，自动更新不抢回页面；点击“返回实时进度”才恢复页面随进度移动。
- “手动确认”只针对实际下一步，记录 `source=manual`。操作或连锁还在处理中、实际场面与该步结果不同、实例不能重建时拒绝确认。人工确认后保持暂停，恢复前再次读取消息前缀及实际场面。无法核验的后续仍逐步待确认，不能跳到终场。
- 临时方案的自动确认使用同一 `duel_planner.confirm`，审计为 `live_confirmed_step`、`source=mdpro3-read-only`。执行本地引擎校验后、写入投影前再次校验局次和路线，旧响应不能写入新方案。手动确认仍记录原有人工来源。
- 受到无效、对方干扰、随机抽牌／堆墓、不同操作或资料不足时暂停。临时方案保留“报告实际情况”入口，由玩家明确发起既有填报／续算；本版不默认自动重规划，带续接前缀的新候选暂保留手动教程。
- 短暂读取或页面连接中断后，恢复读取不会自动恢复推进，须点击恢复／重新同步；它会重新读取保留的消息前缀、比较已有记录并核对新场面。原智能识别认为进程／局次失效或采样中断过长时，沿用其失效策略，等待下一局，不能强行复用旧起手。

“实时场面”折叠区来自本次我方只读采样；教程棋盘明确标为“方案预期场面”。初始起手始终冻结，回看不撤销历史，不修改原方案、个人牌组或已有展开记录。

## 生命周期、接口与本地数据

读取适配位于 `mdpro3_capture.py`；`duel_follow_events.py` 是消息隐私过滤、实例归一化与事件匹配；`duel_follow.py` 编译完成判据、管理局次和确认历史；`duel-auto-follow.js` 管理显示和浏览位置。其他平台可提供相同的带身份、序号、采样时间和实测场面的接口，但本版仅开放 MDPRO3。

跟随绑定捕捉连接（已含 PID、创建身份和构建检查）、核心对象、本局 Start 对象、冻结起手、自动工作区、选择版本，以及正式方案修订或临时路线／规则版本。换局、进程重启、切换方案和结束工作区会令旧请求失效。停止旧会话的迟到请求也不能撤销新会话。

运行资料保存在个人运行目录 `_trainer/live-follow/`：状态、确认来源、事件范围与时间，以及独立的 `.evidence.json` 原始消息证据。验收副本、截图、人工标记和延迟记录只放 `.local/`；现有忽略规则继续排除这些资料及 `release/`，不上传个人记录。

## 实际对局验收步骤与延迟口径

使用 `desktop/ygopro-smart-live.cjs`，`YGO_SMART_PLATFORM=mdpro3` 和独立 `YGO_TEST_RUN`。工具箱保持后台隔离实例，游戏由玩家操作。`YGO_SMART_PACKAGED=1` 使用当前构建包；预先建立的隔离资料副本配合 `YGO_SMART_IMPORT=none`，不导入或覆盖原个人目录。

1. 启动已适配版本，停在主菜单；工具箱建立智能识别后再开 BO1 先攻局。使用有正式先攻方案的卡组，起手后先不操作，人工核对冻结起手。
2. 玩家选择匹配路线。先做一步召唤；成功后应标记该步并显示下一操作。随后发动效果，在选对象／素材和连锁处理中检查仍显示执行中，结果成立后才推进。
3. 连续完成两步、回看旧节点后继续操作；实际进度应继续累计，回看位置保持，返回实时进度再对齐。另测同名副本、无效、偏离、暂停／恢复和跨局。
4. 对正式与临时路线分别验收；临时路线同时核对本地 `forecast_steps`、确认范围和审计来源。只录制或回放合成输入不算真实对局通过。

本地 `follow-latency.jsonl` 保存已处理完成事件首次观察时间、前一采样时间、服务确认时间和渲染器观察时间。客户端消息没有原始动作时间戳，因此报告“完成消息处理到界面观察”的上下界（包含验收观察器轮询），并单列采样到显示的时间。首次进入教程补收旧操作时没有延迟上界，不把它计入正常实时统计；操作员文字确认收到的时间也不冒充游戏动作时间。没有真人样本时不填写实测延迟。

工具箱的后台验收可以独立运行。所适配客户端的[命令行实现](https://code.moenext.com/sherry_chaos/MDPro3/-/blob/228e4ae652d23cb0e6e466a35e2281ce9b1d630a/Assets/Scripts/MDPro3/Game/Program.cs)提供连接、卡组、回放和残局入口，没有出牌或素材选择 API；本版没有给只读适配增加游戏控制通道。
