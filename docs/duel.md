# BO1 决斗辅助

## 进入决斗

顶部流程依次为「模式选择 → 功能选择 → 卡组选择 → 决定先/后攻 → 卡组展开」。选择 BO1 后先选择功能，下方显示「手动或自动 / 平台选择」两个子步骤。「手动选择」直接进入原有卡组列表、卡牌预览、先手起手录入、方案筛选与教程；「自动选择」进入平台选择。

功能页与模式页沿用居中方形插画卡片。步骤条可返回已到达的阶段；返回功能页后再次选择手动，保留本局已选卡组、预览标记及后续准备。开始新一场时重新选择模式和功能。

## 自动选择与实时卡组捕捉（1.21.0）

1. **平台选择**：点击「YGOPro · 初代原版游戏」立即打开捕捉弹窗并查找 `YGOPro.exe`。显示进程名、PID、窗口标题、路径和适配状态；失败可重新捕捉，多个进程时明确选择一个。成功后点击「进入卡组识别」。弹窗与后续识别页均持续提示：先在游戏主菜单点击「编辑卡组」，打开目标卡组并停留在编辑页面后再获取。
2. **卡组识别**：在 YGOPro 中打开「编辑卡组」并停留，点击「获取卡组」。以只读内存接口取得当前主／额外／副卡组的顺序与重复份数，包含未保存修改。读取前后校验编辑器状态、容器边界及两次连续快照；离开编辑器、正在换副、读取不完整或本地卡库缺少卡号时提示错误，禁止继续或保存上次结果。游戏修改或切换卡组后需重新点击获取，并非持续后台监听。
3. **卡牌预览**：复用三分区卡牌、详情浮层、逐副本标记及取消标记。右侧输入名称、搜索真实 TAG、切换主副 TAG 或移除。「自动识别 TAG」使用现有本地系列统计规则，不调用云端 AI。重新获取时保留名称和 TAG；卡牌变化会清除旧的逐副本标记，避免标记错位。卡牌标记仅用于本次预览。
4. **保存与重名**：卡牌和 TAG 一起持久化为工具箱卡组库中的 YDK。与库中卡组同名时先显示覆盖确认，取消不写入；确认时核对原 ID 和 revision，原子替换并备份旧版本，不创建重复条目。名称按 NFKC 与大小写归一比较。原始导入资源中的同名卡组要求另取名称，不覆盖源文件。
5. **开始决斗**：点击进入「决定先/后攻」，持续监测已连接的 YGOPro。玩家仍在游戏中点击开始、完成猜拳和选择；工具箱仅只读观察。

## 自动识别先后攻（1.22.0）

- 进入该步骤后连续读取，不叠加并发轮询。等待起手时每次读取后间隔约 80 ms，冻结起手后约 350 ms。依次显示等待开局、正在猜拳、轮到我方选择或等待双方完成选择。猜拳和选择期间先后攻留空，不能确认；不会把上一局 `isFirst` 残留值当作新结果。
- 最终结果使用当前客户端收到 `MSG_START` 后的 `DuelInfo.isFirst`，同时要求 `isStarted`、`isInDuel`、未结束且已进入第 1 回合。猜拳赢家可选择先攻或后攻，因此不以猜拳输赢或手牌数量推断最终顺序。由对手决定时也读取同一最终标记。
- 检测成功后显示先攻／后攻；用户可点「先攻」「后攻」手动更正，或恢复自动结果，再点击「确认，下一步」。服务端重新读取并核对本局 ID 与观察版本，避免确认上一局或过期状态。
- 先后攻确认后，先攻进入「准备起手」，后攻进入起手留存页。完成先攻起手确认后进入下一阶段并停止轮询；后攻展开仍待开发。返回监测页面恢复读取；离开模块、返回卡组阶段或更换连接停止旧请求，迟到响应不会覆盖新状态。
- 新一局重新生成独立 ID、清空手动更正与界面结果。识别事件和确认历史保存在运行数据目录的 `runtime/_trainer/automatic-duels/<id>.json`（源码运行时为相应 runtime 下的 `_trainer/automatic-duels`）；包含自动结果、最终选择、来源、时点及阶段变化，保留已结束对局记录。
- 游戏关闭或读取失败时不提供可确认的旧结果；会持续重试并提供重新连接入口。当前仅支持已适配构建的普通玩家对局，不将观战、录像、TAG 或单人谜题状态当作本功能的有效结果。

## 自动准备起手（1.23.0）

- 在游戏选择先后攻之前开始监测。工具箱读取第 0 回合我方 `MSG_DRAW` 初始发牌消息，再与我方手牌区全部卡号、重复份数交叉核对；手牌未发齐、读取变化或包含未知卡号时继续等待，不把部分手牌当作完整起手。
- 发牌数量取自本局实际消息，不依赖手动模式的默认起手张数。卡牌全部就绪后生成独立 `snapshot_id`，保存卡号顺序、张数、捕捉时点、原始先后攻及来源。之后抽牌、使用卡牌和洗手牌不会重写这个快照。
- 先攻在「准备起手」显示逐张预览与卡名，可打开卡牌详情；同名卡多张分别显示。点击「确认起手，下一步」会重新验证局次和快照 ID，核对本局实际提交卡组与先前捕捉的三分区卡牌和份数，落盘确认后进入独立的「方案选择」。游戏中换过卡组或起手与构筑不符时拒绝继续，提示重新捕捉。
- 后攻同样保存和预览最初起手，但没有先攻的准备起手子步骤、确认下一步按钮或方案入口。后攻随后抽到的第六张牌不会被加入初始快照。
- 若连接太晚、未观察到初始发牌或中途读取中断超过 2 秒，不能证明手中牌仍是最初起手，界面会说明需要下一局重新采集，不以当前手牌替代。之前保存的快照继续保留在历史文件中；再次监测已进行的对局可能只能标记为未捕获。
- 快照及确认保存在原局次文件 `automatic-duels/<id>.json` 的 `opening` 字段；卡号与对局记录属于本地个人数据，不上传到仓库。

当前适配 Windows x64、YGOPro 1.036.2 中 SHA-256 为 `55dd3e8ea4e9a0f24bb2b038e4c95f6e266140469be3480924ff1e57dda1e629` 的客户端构建。版本号相同也可能有不同内存布局，因此必须匹配完整可执行文件指纹；未知构建明确拒绝，不尝试猜测地址。使用进程创建时间避免 PID 被复用；游戏重启后需重新捕捉。该接口不向游戏写内存、不注入代码、不模拟输入，也不读取磁盘卡组冒充实时结果。卡牌文字、图片及 TAG 使用工具箱当前本地卡库。

后台桌面回归中的游戏捕捉使用明确隔离的测试响应；真实验收另运行 `node desktop/ygopro-live-smoke.cjs`，连接用户已打开的 YGOPro，所有保存写入 `.local/ygopro-live-*` 独立目录。第一轮完成后等待 `phase2`（用户修改卡牌，同名覆盖）、`phase3`（用户切换卡组，保存第二套）或 `close`。测试不移动系统鼠标，不发送全局按键。草稿在刷新或退出后清空，已保存卡组保留；手动模式的源卡组、标记及编辑器缓冲独立。

## 数据与匹配约定

### 自动模式的独立方案与教程（1.24.0）

先攻确认起手后依次进入「准备起手 → 方案选择 → 展开教程」。软件根据本局构筑、TAG 和初始起手筛选已有正式方案；玩家选择其中一个，再按实际游戏操作推进教程。没有匹配结果时展示原因，可返回查看冻结起手、刷新列表或生成本局临时方案。

- 方案页支持步骤最少、终场最大、平均值排序，收藏与只看收藏，以及简略／详细预览。收藏仍是同一方案库的个人收藏；自动、手动两边的筛选条件与当前选择独立。
- 教程支持主线与可用分支、步骤前后切换、场面及区域卡牌查看、节点详情、可调节图高度和教程快捷键。快捷键配置共用既有设置，每个模式使用独立会话标识；切换页面、离开模块或结束后释放本次绑定。
- 自动教程同样支持后台生成临时方案、采用路线、逐步确认、报告随机结果或阻抗、从普通步骤生成后续。返回方案页重新生成从冻结起手开始；教程内重算保留已确认前缀。
- 返回功能选择并切换模式，保留两边独立的选择和教程位置。查看准备起手使用原快照；重新捕捉、更换卡组、重新开始监测或新建对局时关闭旧自动工作区与所属后台推演。

自动模式使用 `duel-auto-workspace.js`、`duel-auto-views.js`、`duel-auto-forecast.js` 与独立样式，DOM 以 `auto-duel-*` 标识，状态保存在 `automatic.workspace`。不将自动数据塞入手动模式的卡组、手牌、方案或图位置。共用部分限于卡牌／报告展示、图模型、方案筛选和规则引擎等基础服务。

后端入口为 `/api/automatic-duel/{context,match,select,dispatch,close}`，从已确认局次冻结卡组、TAG、起手和顺序。私有输入保存在 `_trainer/automatic-contexts/<id>.json`，不新增或覆盖用户卡组；`automatic/<id>` 为只读内部卡组 ID。已保存方案选择时重新核对内容版本；推演请求绑定当前自动工作区，拒绝手动模式或其他自动工作区的会话 ID。输入、方案快照和确认记录仅保存在本机，页面刷新后不自动恢复教程位置。

这些接口为后续自动对局扩展保留独立入口。目前完成起手确认后不持续识别真实出牌，不会自动选择方案、自动推进教程或代替玩家操作游戏。后攻继续只留存起手，不进入本流程。

后续对局读取的已验证地址、结构和限制保留在 [YGOPro 对局数据读取路径](ygopro-live-state-research.md)。完整局面跟踪仍未接入；先后攻、起手与本局卡组核对使用独立的只读接口。

`POST /api/duel/match` 只读取当前卡组、Tag 库和正式方案。传入卡组稳定 ID、读取时的 revision、起手张数和完整卡号列表；服务端再次核对主卡组来源和份数。请求和筛选结果不写入对局、卡组或方案文件。

1. 卡组 `tag_selection.tag_ids` 与方案经现有 `PlanLibrary.selection()` 得到的 Tag ID 至少相交一个。沿用方案自动／人工分类规则；不按相似名称、别名或父子标签扩展匹配。卡组主／副 Tag 都参与关联。
   明确记录为后手的方案不进入本期先攻教程；旧数据没有 `turn_order` 时沿用原项目的先手默认值。
2. `requirements.main` / `extra` 由原 `review.requirements()` 按卡牌实例统计，表示构筑中需要包含的资源，包含起手使用实例。检查完整构筑，不额外扣起手；副卡组不可代替主／额外资源。相同卡号的多行数量相加。
3. `requirements.opening` 是最低起手要求，同一张实体卡不能同时满足两份数量需求。明确的「任意手牌」占用满足指定卡之后的剩余手牌；现有结构为并列条件同时满足，没有结构化的 OR／属性表达式。无法自动解释的自由文字限制、缺少条件摘要和原摘要中的来源／份数警告均标为条件待补全。明确保存的空条件数组可读取为无额外限制。`random` 保留为途中随机依赖提示。
4. 当前已保存分支为主线上的独立分支，分支报告包含从起手至分叉前的共同路径。分别核对各分支报告的资源，并保留真实 `source.node_id` / `source.seq` 时点。主线或其他分支的后续资源不累加到这一条替代路线。无效、缺失或不可达分叉不展示；分支共用主线起手条件。原项目尚不支持嵌套分支创建，本次不新增嵌套存储格式。

服务器返回本次可用方案的独立副本和逐项排除原因；教程图与详细一图流预览共用这份副本。教程图的步骤关系复用一图流投影，步骤主体与悬停分别复用原展开日志的简略／详细渲染，棋盘直接读取同一冻结节点快照。渲染函数显式传入报告上下文，不切换展开页的当前报告或编辑器。首个位置为主线 Step 1；允许退到「起手」查看首次操作前的分叉。分支终场不自动接回主线，不自动判定真实操作已经完成。

教程图与棋盘之间提供水平拖拽分隔栏。每次高度变化，步骤先自动加宽，必要时将同一步的多项操作分列，再按区域高度缩放完整格子；布局使用实际测量尺寸重绘分支连线。支持拖动、方向键调整、Home／End 与双击恢复默认高度，当前步骤和报告内容保持不变。

鼠标点选与快捷键跳转共用同一聚焦规则：当前步骤在教程图可滚动范围内水平居中，纵向保证步骤可见，只移动教程图内部。步骤详情统一等待 280 ms 后打开，离开触发区后保留 220 ms 供移入阅读；跨子元素不会反复重启等待，旧关闭计时器不会关闭新预览。移入详情及其卡牌浮层可继续阅读，滚动导致触发节点移动时关闭旧预览。

长步骤详情优先放在流程图下方，空间不足时在图上方显示并限制高度；内容在浮窗内滚动，无可用空间时不强行盖住步骤。方案预览优先放在方案卡片侧面，空间不足时放在卡片外侧并限高。前进／后退／结束按钮位于自动详情上方，移入按钮即关闭详情。按下步骤或底部按钮会取消待弹出的详情，图随点击移动时不会重新触发；鼠标实际移动后恢复悬停。

方案卡片及简略预览显示主线操作步数和本次可用分支数量，不计起手／终场展示节点，不展开分支信息。主线计数与实际教程使用同一份投影，可用分支按本局筛选及图中可达路线统计。终场整体说明、逐卡备注和勾选效果备注完整显示并保留换行；详细预览另外显示效果原文以及分支名称、起点、对手预设手牌、实际干扰与分支终场。预设条件不当作已发生的干扰，主线和分支各读取自己的冻结备注。

## 方案排序与收藏

方案选择支持「步骤最少」「终场最大」「平均值（均衡）」。步数与教程主线投影一致；终场按明确标记的有效卡牌数比较，同数再比较标记效果数，未标记卡牌不参与。平均值将步骤数归一为 0–100 分（越少越高），将终场排名归一为 0–100 分，各占 50%；同分再按终场与步数排序。这是当前匹配集合内的比较，不代表实战胜率或阻抗次数。

展开管理列表、方案详情和决斗方案卡片均可点击星标收藏；两个列表均支持「只看收藏」，已收藏方案边框高亮。收藏写入本地个人数据目录 `_trainer/plan-favorites.json`，独立于方案正文和来源版本，跨重启保留，不写进方案分享文件。

## 状态与保存

流程只在当前窗口内保留。查看前一步不清空输入；修改上游值立即清空匹配结果、方案选择和教程位置。源卡组 revision 改变时刷新只读预览并清空旧标记和起手，要求重新确认；返回模块时也重新验证当前方案匹配结果。

卡片标记沿用现有展开选择的会话范围，使用区域及实际副本索引。在预览卡牌的浮层中标记，起手页同一候选列表用加强边框表示已标记的主卡组卡号。角标是投入份数减去当前起手份数；为零时灰显。右键槽位移除指定位置，右键候选移除最后一个同名已选副本。

起手槽及其标题居中，主卡组候选位于居中的限宽容器，窄窗口自动换行。候选按卡组编辑器的类型、等级和卡号规则排序，同名份数合并展示；排序只影响候选展示，源 YDK 的牌序、份数及已选起手位置不变。

Tag 列表和预览使用卡组 API 的 `tag_selection` 和同一标签库提供的 `tag_names`。编辑中未保存的 Tag 仍归编辑器缓冲区；保存后刷新卡组列表和其他预览。已开始的原展开、历史记录和已保存方案继续保留其原始卡组快照。

## 快捷键

Electron 主进程通过窄范围 IPC 接受当前教程状态和经过格式／重复校验的按键配置，只接受本应用主窗口及本地服务来源。软件内外共用一套绑定，默认左／右／上／下，结束默认为空。进入教程自动启用，可统一暂停。旧版本默认组合迁移为方向键，已自定义的绑定保留。

教程页的「快捷键设置」与顶部齿轮内的「教程快捷键」打开同一个窗口、读写同一个配置文件，默认值与校验规则由主进程和渲染器共用。快捷键窗口仅显示动作和按键；保存不会更改起手张数。全局设置单独保存默认起手张数，打开任一设置窗口时暂停教程快捷键，关闭所有模态窗口后再按教程状态恢复。旧回放页仅在展开模块内响应方向键。

- 主窗口聚焦时释放全局绑定，由渲染器仅处理配置的同一套按键，并接受 keydown 的重复事件。输入框、选择框、可编辑区域和模态弹窗不推进教程，录制中的按键只用于设置。
- 主窗口失焦后按当前教程状态注册；注册失败会释放本轮所有绑定并明确显示失败动作。
- 退出教程、切换模块、暂停、结束、窗口关闭、导航刷新和渲染器异常均释放绑定。每个教程具有独立 session ID，迟到回调不能控制下一场。
- Windows 后台注册时启动 `tutorial_keys.py`，仅读取配置键和修饰键的当前状态。首次回调后等待 350 ms，以 100 ms 间隔重复导航；松键立即清除，结束动作不重复。聚焦、暂停、会话变化与退出销毁辅助进程；辅助进程也检查父进程存活。无全局输入注入、文字采集或按键日志。
- 设置保存到当前个人数据目录的独立 JSON，通过临时文件替换，保留上一版本备份，不迁移或改写旧业务数据。
- 正常启动不暴露验收回调；`YGO_DESKTOP_TEST=1` 才提供主进程测试句柄。测试不发送系统按键，也不切换用户其他窗口。

## 展示与全局设置

代表卡通过 YDK 的 `#representatives: [code, null, code]` 注释保存三个位置，卡组 ID、牌序和份数不变。读取旧卡组返回三个空位；显式保存校验来源卡号，隐式保留时清空已移出构筑的代表卡。原文件在覆盖前备份，保存失败保留旧文件。

`GET/POST /api/duel/settings` 将默认起手数保存在本地 `_trainer/duel-settings.json`，范围 1–60。已准备的起手继续使用本局数量；还没进入起手页或新对局从全局设置读取。

## 模块化与本局临时方案

Step 的显示名称和批注 ID 保留。棋盘、前后连接、一图流和教程从同一 `review.module_graph` 投影；实际可执行动作仍须通过当前引擎的决策窗口。旧冻结方案缺少原始决策时仅提供观察快照。

自 1.17 起，方案选择页点击「生成临时方案」，后台读取本局构筑、手牌及所选展开来源。候选的「采用临时方案并进入下一步」打开本局步骤图，整个过程留在决斗页面，不创建供用户继续打牌的场地，也不跳转到数据中心。

临时方案中，前进到下一步或点击相邻下一节点，表示用户确认当前操作已照做；返回旧节点只查看，不撤销确认。召唤／效果及其选位置、素材等选择合并显示为一个操作步骤。随机结果处会要求填报具体卡牌；也可在对应步骤点击「报告实际情况」，填写抽牌、随机堆墓、手牌阻抗及其手牌费用。后台从保留的历史重放并计算新后续，不改写正式方案或实战原始日志。无法复核时保留原路线；确认结果后没有候选则保留已确认部分并明确显示后续待生成。

直接选择已有正式方案时先进入只读手动教程；选中已经完成的操作 Step 后，点击「生成展开后续」，后台用本局起手复核此前决策，再从该步骤完成后的合法决策边界计算后续。前面的步骤及批注保留；缺少决策记录、未填报随机结果或无法重放时保留原教程并说明原因。真实展开与模块化页面继续保留原生场地及 AI 执行功能。临时方案的确认记录来自用户，不表示软件识别了实际对局。详细边界与检查见[临时方案](duel-temporary-plans.md)。

详细的来源版本、偏好变化、干扰后续与验证范围见[模块化展开](modular.md)。
