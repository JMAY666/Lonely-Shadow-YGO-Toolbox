# BO1 决斗辅助

## 数据与匹配约定

`POST /api/duel/match` 只读取当前卡组、Tag 库和正式方案。传入卡组稳定 ID、读取时的 revision、起手张数和完整卡号列表；服务端再次核对主卡组来源和份数。请求和筛选结果不写入对局、卡组或方案文件。

1. 卡组 `tag_selection.tag_ids` 与方案经现有 `PlanLibrary.selection()` 得到的 Tag ID 至少相交一个。沿用方案自动／人工分类规则；不按相似名称、别名或父子标签扩展匹配。卡组主／副 Tag 都参与关联。
   明确记录为后手的方案不进入本期先攻教程；旧数据没有 `turn_order` 时沿用原项目的先手默认值。
2. `requirements.main` / `extra` 由原 `review.requirements()` 按卡牌实例统计，表示构筑中需要包含的资源，包含起手使用实例。检查完整构筑，不额外扣起手；副卡组不可代替主／额外资源。相同卡号的多行数量相加。
3. `requirements.opening` 是最低起手要求，同一张实体卡不能同时满足两份数量需求。明确的「任意手牌」占用满足指定卡之后的剩余手牌；现有结构为并列条件同时满足，没有结构化的 OR／属性表达式。无法自动解释的自由文字限制、缺少条件摘要和原摘要中的来源／份数警告均标为条件待补全。明确保存的空条件数组可读取为无额外限制。`random` 保留为途中随机依赖提示。
4. 当前已保存分支为主线上的独立分支，分支报告包含从起手至分叉前的共同路径。分别核对各分支报告的资源，并保留真实 `source.node_id` / `source.seq` 时点。主线或其他分支的后续资源不累加到这一条替代路线。无效、缺失或不可达分叉不展示；分支共用主线起手条件。原项目尚不支持嵌套分支创建，本次不新增嵌套存储格式。

服务器返回本次可用方案的独立副本和逐项排除原因；教程图与详细一图流预览共用这份副本。教程图的步骤关系复用一图流投影，步骤主体与悬停分别复用原展开日志的简略／详细渲染，棋盘直接读取同一冻结节点快照。渲染函数显式传入报告上下文，不切换展开页的当前报告或编辑器。首个位置为主线 Step 1；允许退到「起手」查看首次操作前的分叉。分支终场不自动接回主线，不自动判定真实操作已经完成。

教程图与棋盘之间提供水平拖拽分隔栏。每次高度变化，步骤先自动加宽，必要时将同一步的多项操作分列，再按区域高度缩放完整格子；布局使用实际测量尺寸重绘分支连线。支持拖动、方向键调整、Home／End 与双击恢复默认高度，当前步骤和报告内容保持不变。

鼠标点选与快捷键跳转共用同一聚焦规则：当前步骤在教程图可滚动范围内水平居中，纵向保证步骤可见，只移动教程图内部。步骤详情统一等待 280 ms 后打开，离开触发区后保留 220 ms 供移入阅读；跨子元素不会反复重启等待，旧关闭计时器不会关闭新预览。移入详情及其卡牌浮层可继续阅读，滚动导致触发节点移动时关闭旧预览。

## 状态与保存

流程只在当前窗口内保留。查看前一步不清空输入；修改上游值立即清空匹配结果、方案选择和教程位置。源卡组 revision 改变时刷新只读预览并清空旧标记和起手，要求重新确认；返回模块时也重新验证当前方案匹配结果。

卡片标记沿用现有展开选择的会话范围，使用区域及实际副本索引。在预览卡牌的浮层中标记，起手页同一候选列表用加强边框表示已标记的主卡组卡号。角标是投入份数减去当前起手份数；为零时灰显。右键槽位移除指定位置，右键候选移除最后一个同名已选副本。

起手槽及其标题居中，主卡组候选位于居中的限宽容器，窄窗口自动换行。候选按卡组编辑器的类型、等级和卡号规则排序，同名份数合并展示；排序只影响候选展示，源 YDK 的牌序、份数及已选起手位置不变。

Tag 列表和预览使用卡组 API 的 `tag_selection` 和同一标签库提供的 `tag_names`。编辑中未保存的 Tag 仍归编辑器缓冲区；保存后刷新卡组列表和其他预览。已开始的原展开、历史记录和已保存方案继续保留其原始卡组快照。

## 快捷键

Electron 主进程通过窄范围 IPC 接受当前教程状态和经过格式／重复校验的按键配置，只接受本应用主窗口及本地服务来源。软件内外共用一套绑定，默认左／右／上／下，结束默认为空。进入教程自动启用，可统一暂停。旧版本默认组合迁移为方向键，已自定义的绑定保留。

教程页的「快捷键设置」与顶部齿轮内的「教程快捷键」打开同一个窗口、读写同一个配置文件，默认值与校验规则由主进程和渲染器共用。快捷键窗口仅显示动作和按键；保存不会更改起手张数。全局设置单独保存默认起手张数，打开任一设置窗口时暂停教程快捷键，关闭所有模态窗口后再按教程状态恢复。旧回放页仅在展开模块内响应方向键。

- 主窗口聚焦时释放全局绑定，由渲染器仅处理配置的同一套按键，并接受 keydown 的重复事件。输入框、选择框、可编辑区域和模态弹窗不推进教程，录制中的按键只用于设置。
- 主窗口失焦后按当前教程状态注册；注册失败会释放本轮所有绑定并明确显示失败动作。
- 退出教程、切换模块、暂停、结束、窗口关闭、导航刷新和渲染器异常均释放绑定。每个教程具有独立 session ID，迟到回调不能控制下一场。
- Windows 后台注册时启动 `tutorial_keys.py`，仅读取配置键和修饰键的当前状态。首次回调后等待 350 ms，以 100 ms 间隔重复导航；松键立即清除，结束动作不重复。聚焦、暂停、会话变化与退出销毁辅助进程；辅助进程也检查父进程存活。无全局输入注入、文字采集或按键日志。
- 设置保存到当前个人数据目录的独立 JSON，通过临时文件替换，保留上一版本备份，不迁移或改写旧业务数据。
- 正常启动不暴露验收回调；`YGO_DESKTOP_TEST=1` 才提供主进程测试句柄。测试不发送系统按键，也不切换用户其他窗口。

## 展示与全局设置

代表卡通过 YDK 的 `#representatives: [code, null, code]` 注释保存三个位置，卡组 ID、牌序和份数不变。读取旧卡组返回三个空位；显式保存校验来源卡号，隐式保留时清空已移出构筑的代表卡。原文件在覆盖前备份，保存失败保留旧文件。

`GET/POST /api/duel/settings` 将默认起手数保存在本地 `_trainer/duel-settings.json`，范围 1–60。已准备的起手继续使用本局数量；还没进入起手页或新对局从全局设置读取。

## 验证

- `npm test`：手牌数量／区域限制，Tag ID 匹配，资源和最低起手条件，通用费用的独立份数，部分分支可用与不可达分叉，缺失条件，原文件不可变；图导航和快捷键注册失败／暂停／释放。
- `node desktop/smoke.cjs --duel-only`：隔离的合成卡组／方案，完整 BO1 流程、默认与自定义起手、预览、鼠标与窗口内按键、实际全局快捷键注册和测试回调、设置冲突／保存、结束及上游变更清理。
- `npm run test:desktop` / `npm run test:packaged`：包含上述决斗验收以及原有卡组、展开、原生场地、回看、Tag、方案和分支检查。

合成教程仅用于验收界面与匹配规则，不表示规则引擎验证过的合法展开。跨软件的真实后台按键、用户个人按键冲突和实际决斗操作由用户验收。
