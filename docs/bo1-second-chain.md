# YGOPro 公开连锁与我方选择快照（1.36.0）

这是执行计划 P2.2b 的有限读取接入。继续沿用自动识别后攻后的“YGOPro 公开资源只读核对”，依次读取预览、人工核对、重新读取并采用。原始起手、已执行历史及先攻流程不改写。

## 可见内容

| 内容 | 本期处理 | 不能据此推断 |
| --- | --- | --- |
| 当前已入列的公开连锁 | 显示链序、公开卡名、我方／对手及发动来源区域；场上来源可显示格位 | 当前目标、发动费用、来源卡仍在原位、完整发动历史 |
| 条目的处理开始标记 | 显示“曾开始处理，结果未确认” | 已结算、处理成功、发动无效或效果无效 |
| 我方客户端选项 | 对普通连锁选择消息，核对我方地址、可见提示区、已知卡片实例、描述标识及当前可选／发动标记 | 独立规则验证、目标或费用可支付认证、必交或最优策略 |
| 未覆盖选择 | 诱发排序、其他消息类型、操作／重置、素材、未知身份及牌库来源保守不展示 | 没有其他合法响应；没有显示不等于不能发动 |
| 本地效果说明 | 描述标识确实属于同一卡号时才显示本地短说明，标注版本待核对 | 描述序号就是卡文效果编号，或客户端脚本必定相同 |

每组默认显示至多三项，其余展开查看；读取范围和前提另行展开。同一卡片的多个选项不是多份可用阻抗，不累计次数或资源价值。主卡组牌序、对手未知手牌与盖卡保持未知；对不支持的选择来源，不读取其身份及效果描述载荷。

“本次读取”“已采用快照”“当时快照”分别标明时点。它们都不是实时发动许可；外部对局仍由玩家在游戏中操作，工具没有向客户端发送输入或把选项转成自动推荐。

## 核对、失效和保存

- 连锁条目或响应选项变化，即使手牌和 LP 不变，也会使旧快照内容校验失败。确认采用前必须重新读取，失败不会覆盖当前记录。
- 客户端发送响应时会清除卡片可选／发动标记。即使旧消息缓存和候选容器仍在，也不能继续发布为支持的我方选项。
- 连锁正在写入或清空时显示“更新中”；空条目不能被解释为没有响应机会。列表清空不生成伪造的结算、费用或无效事件。
- 预览与采用分开保存，采用后在 `current.observed_chain`／`client_response` 和历史快照中保存当时观察。后来的卡片揭示、选项或结果不回填旧记录；旧版本没有这些字段时保持缺失。
- 导入不创建 `current.window` 或规则重建权限，不返还已使用次数，不改变正式方案。人工说明、规则建议和观察仍各自保留。
- 断流、换局和迟到结果继续使用原局次／进程／场景／版本保护。当前采样不能区分两次读取之间内容完全相同的新窗口，因此这些快照不提供可直接采用的交康建议，也不声称精确窗口身份。

## 验证边界和后续

仅支持 SHA-256 为 `55dd3e8ea4e9a0f24bb2b038e4c95f6e266140469be3480924ff1e57dda1e629` 的 YGOPro 镜像。仅原有普通对局范围；MD、MDPRO3、YGOPRO2、其他构建、观战、录像及单人谜题未获得这些能力。MD 卡池／禁限表与验证范围独立处理。

这是当前客户端展示的有限快照。单消息缓存会覆盖中间消息，连锁列表不能证明所有动作均被捕捉。后续先建立可证明连续性的公开事件来源，再补响应窗口身份、对象、费用、无效类型、次数及限制；未完成前不开放外部局面的规则续算或斩杀认证。

实机核对、单元检查与合成界面分别见[1.36.0 验证记录](verification-1.36.0.md)，布局来源见[读取研究](ygopro-live-state-research.md)。
